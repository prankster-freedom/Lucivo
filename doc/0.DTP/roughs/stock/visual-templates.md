# ストック・ボツのラフ: Visualモードの記述パターン別の雛形と動的演出

状態・採否の理由・再利用の条件は [ラフ案台帳](../README.md) を正とする。

## RGH-101 データ表型

```text
┌──────────────────────────────────────────────────┐
│ STAGE 06  比較                                     │
│ ┌──────────┬────────────┬───────────┐            │
│ │ 項目     │ A          │ B         │  ← 見出し行を濃色の帯に │
│ ├══════════┼────────────┼───────────┤            │
│ │ 太字     │ 説明       │    120 ▲ │  ← 数値列を右寄せ・強調 │
│ └──────────┴────────────┴───────────┘            │
└──────────────────────────────────────────────────┘
```

- 表だけの章の専用の雛形ではなく、すべての表に効く規則として採用した（`RGH-014`, `DTP-VTPL-110`）。

## RGH-105 展示ブース向け自動ステップ送り

```text
┌ [▶ Auto-Tour 5s] ───────────────────────────────┐
│   (1) ──→ (2) ──→ (3) ──→ 次の STAGE スラブへ     │

```

- ステージ発表（`RGH-012`）の自動進行として採用した。無人展示ブースで自動的にスポットライト（`RGH-007`・`008`）を順番に進める案。全画面・発表用表示の UI と統合して設けるのが適切なためストックとして保管。

## RGH-107 表紙のメタ情報行

```text
        文書の題名
   山田 太郎  ·  2026-11-06  ·  14 STAGES  ·  6 FIGURES
```

- ストック。`author` は文字列のことも入れ子（`name`・`role`）のこともあり、`date` も形式が文書ごとに違うため、確実に読み取れない。章数は目次と重なる。

## RGH-108 発表の表紙に目次を出す

```text
┌ 舞台 ─────────────────────────┐
│          文書の題名             │
│  01 …   04 …   07 …  10 …      │ ← 押しても送りにならない
└───────────────────────────────┘
```

- ボツ。発表はクリックで次のシーンへ送るため、目次は押せる道案内にならない。題名の主役を弱める。

## RGH-111 比較型（Before / After の左右対置）

```text
┌──────────────────────────────────────────────────┐
│ STAGE 04  従来との比較                             │
│ ┌─ BEFORE ───────────┐  →  ┌─ AFTER ────────────┐ │
│ │ （彩度を落とす）    │     │ （アクセント色）    │ │
│ │ ・手作業で 3 日     │     │ ・自動で 10 分      │ │
│ └─────────────────────┘     └─────────────────────┘ │
└──────────────────────────────────────────────────┘
```

- 狙い: 講演で多い「従来と新しい方法の比較」を、左右の対置と彩度の差で一目で見せる。左は沈め、右を主役にする（`DTP-001` の主役は 1 つ）。
- 判定の候補: 章に `###` の小見出しが 2 つだけあり、その語が対になっている（`Before` / `After`、`従来` / `新方式` など）。
- ストックの理由: 対になる語の一覧を決めないと誤判定が出る。2 つの小見出しの章は要点カード型（`RGH-002`）でも表せる。比較の章が意図どおりに見えないという要望が出たら再検討する。

## RGH-112 タイムライン型（日付つきの箇条書き → 横の年表）

```text
┌──────────────────────────────────────────────────┐
│ STAGE 07  ロードマップ                             │
│                                                  │
│  2026 Q1      2026 Q3      2027 Q1      2027 Q3   │
│ ──●───────────●───────────◉───────────○────────▶ │
│  α 版        β 版        正式版       拡張       │
│                          ↑ 現在（光る点）          │
└──────────────────────────────────────────────────┘
```

- 狙い: ロードマップや沿革を、手順型（`RGH-003`）とは違う「時間の軸」として見せる。現在の位置を光の点にし、過去は塗り、未来は輪郭だけにする。
- 判定の候補: 箇条書きのすべての項目が、日付・年・四半期（`2026`、`2026 Q1`、`2026-04` など）で始まる。日付の書式はセルの文字だけで判定できる（`RGH-101` と同じ考え方）。
- ストックの理由: 「現在」をどう決めるか（閲覧した日か、文書に書いた日か）が未確定。項目が 7 個を超えるときの折り返しも未検討。

## RGH-115 定義リスト型（用語と説明の 2 段組）

```text
┌──────────────────────────────────────────────────┐
│ STAGE 03  用語                                     │
│                                                  │
│  Slab        │ 1 章を載せる面。角丸と影で独立する   │
│  ─────────── │                                    │
│  Scene       │ 発表で 1 度に映す単位                │
│  ─────────── │                                    │
│  ↑ 等幅・太字   ↑ 本文                             │
└──────────────────────────────────────────────────┘
```

- 狙い: 技術発表で多い用語の説明を、辞書のような 2 段組にする。用語を等幅で揃えると、ブランドの「丸みのある等幅」（1.2.5）の論理性が出る。
- 判定の候補: 箇条書きのすべての項目が `**用語**: 説明` または `用語 — 説明` の形。
- ストックの理由: 書き方の揺れ（区切りの記号・太字の有無）が大きい。用語が 1 行に収まらない長さのときの組み方も未検討。

## RGH-907 表のセルを文節でだけ折り返す

```text
│ カード右上コーナーオーナメント │ ← 1 つの文節が列の最小幅になる
→ 7 列の表が版面からはみ出し、横スクロールになる
```

- ボツ。短いラベルの列だけを 1 行に保ち、それ以外は文節の中でも折り返せるようにした（`DTP-VTPL-110`）。

## RGH-901 独自の記法で雛形を指定する

```markdown
<!-- lucivo: layout=cards -->
## 特長
- …
```

- ボツ。Lucivo 以外のビューアーではただのコメントになり、指定の意味が失われる。

## RGH-902 要点カード型を 3 列固定・最小幅の自動段数にする

```text
┌────┐ ┌────┐ ┌────┐
│ 01 │ │ 02 │ │ 03 │
└────┘ └────┘ └────┘
┌────┐                 ← 4 個目が 1 つだけ残る（端数）
│ 04 │
└────┘
```

- ボツ。最小幅の自動段数でも、3 個が 2 列＋1 枚になる端数が出た。項目の数で列を決める方式（`RGH-002`）を採用。

## RGH-903 常時ループする背景パーティクル・光彩アニメーション

```text
┌──────────────────────────────────────────────────┐
│  ✦  ∘   ✦    （常時浮遊・明滅する背景エフェクト）  │
└──────────────────────────────────────────────────┘
```

- ボツ。操作していない間も常時アニメーションが動くと、技術文書や図版の読解の妨げになり、さらに常時 GPU 再描画が発生して閲覧操作のリアルタイム性（`NFR-006` / `NFR-007`）を損なうため。ユーザーのホバーやクリックに応答するインタラクティブ・スポットライト（`RGH-007`・`008`）を採用。
