# ストックのラフ: ステージ発表の前後の場面（stage-scenes）

状態・採否の理由・再利用の条件は [ラフ案台帳](../README.md) を正とする。

ステージ発表（`RGH-012`）は、1 章を 1 シーンとして送る。本書は、その本編の間と前後に入る場面のラフをまとめる。どの案も、Markdown に独自の記法を足さず（`RGH-901` と同じ方針）、文書の構成（見出し・フロントマター）から組み立てられることを前提にする。

## RGH-110 章扉（大きな等幅の章番号の幕間）

```text
┌──────────────────────────────────────────────────┐
│                                                  │
│        02                ← 等幅・極太・画面高の 40% │
│        ─────             ← 4 色バーを短く         │
│        アーキテクチャ    ← 章の見出し              │
│        3 scenes · 2 diagrams   ← 小さな等幅のメタ  │
│                                                  │
└──────────────────────────────────────────────────┘
```

- 狙い: 章が変わったことを聴衆に一瞬で伝え、話の区切りで「間」を作る。ブランドの丸い等幅（1.2.5）を、大きな数字で見せる場面にもなる。
- 素材の候補: 背景に `AST-106`（スポットライトコーン）を薄く敷く。
- ストックの理由: いまの発表は 1 章 1 シーンのため、章扉を挟むとシーンの数が倍になり、送りの操作が増える。見出しの階層（`##` の下に `###` の節が並ぶ文書）で、章と節を分けて送る要望が出たら再検討する。

## RGH-113 エンドカード（ロゴ＋結びの一文＋リンク）

```text
┌──────────────────────────────────────────────────┐
│                                                  │
│               ◉ Lucivo の光（AST-106 の光だまり）    │
│          「構文に生命を。」 ← 結びの一文（大）      │
│           github.com/xxx/yyy   ← 等幅・アクセント色 │
│                                                  │
│                                  made with Lucivo │
└──────────────────────────────────────────────────┘
```

- 狙い: 発表の最後のシーンを、文書の最終章のまま終わらせず、締めの一枚にする。質疑に移るまで投影したままにできる。
- 結びの一文とリンクは、フロントマター（例: `closing:`、`url:`）があれば使い、なければ表紙の題名に戻す。
- ストックの理由: フロントマターのキーの決め方（`RGH-107` と同じ課題）が未確定。右下の `made with Lucivo` は、利用者の発表の主役を奪わないよう、出すかどうかを設定で選べる前提でのみ検討する。

## RGH-114 質疑の待機幕

```text
┌──────────────────────────────────────────────────┐
│ ░░░ ブランドの暗転（AST-107 の光漏れ）░░░░░░░░░░ │
│                                                  │
│                    Q & A                         │
│              ◌ ─ ─ ◉   ← AST-108 が静かに一周     │
│                                                  │
│ 01 ▪ 02 ▪ 03 ▪ 04 ▪ 05   ← 章の番号（押すと戻る）│
└──────────────────────────────────────────────────┘
```

- 狙い: 質疑の間、画面に何を出しておくかを決める。下端の章番号から、質問された章へ 1 操作で戻れる。
- ブランドカラーを使う理由: 文書の中身ではなく Lucivo 自身の画面のため（`DTP-003` の例外と同じ考え方）。
- ストックの理由: 戻る操作は俯瞰（`RGH-015`）で既に満たしている。俯瞰では聴衆に全シーンが見えてしまうことが課題になったら再検討する。

## RGH-116 展示ブースの待機画面（無操作のときだけ題名がゆっくり明滅する）

```text
┌──────────────────────────────────────────────────┐
│                                                  │
│          題名            ← 明るさを 6 秒周期で ±8% │
│          ─────                                   │
│          キーを押すか、画面に触れてください        │
│                                                  │
└──────────────────────────────────────────────────┘
   一定時間（例: 60 秒）操作がない → 待機画面
   何か操作する → 直前のシーンへ戻り、動きを止める
```

- 狙い: 展示会で発表を流したまま離席したとき、止まった画面ではなく「生きている」画面にする（Vivo）。自動進行（`A` キー、`RGH-105`）と組み合わせる。
- `RGH-903`（常時ループする背景のアニメーション）との違い: 読んでいる間は動かさない。待機中にだけ、題名の明るさという 1 つの値を、ゆっくり変える。粒子や背景全体は動かさない。
- ストックの理由: 自動進行のループで展示の放置運用は既に満たせる。ループと待機をどう切り替えるかの要望が出たら再検討する。
