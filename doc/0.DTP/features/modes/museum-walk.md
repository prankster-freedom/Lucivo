# ミュージアム・ウォーク（`museum-walk`）

文書を「1 章 = 1 スライド」で切り替えるのではなく、1 本の連続した建築空間（回廊・広間・小部屋）として構成し、歩いて読み進む展示体験を提供する。

- 対応するラフ: `RGH-142`（採用。連続回廊・門の通り抜け・断面変化）／見送り・ストック: `RGH-136`, `RGH-912`, `RGH-143`, `RGH-144`（[roughs/README.md](../../roughs/README.md)）
- 対象段階: Web 版先行提供（`stage: "web"`。`AGENTS.repo.md` 10 章に基づき、体験の狙い・操作・デザイン上の判断根拠に絞る）
- 本番素材（`AST-xxx`）: 空間・装飾・図形はすべて CSS の 3D 変形・グラデーション・タイポグラフィで構成し、外部画像・SVG 素材は追加しない。

---

## DTP-MWLK-010 世界観とトーン＆マナー（Dark / Light）

- **連続回廊の体験**: 「次へ」のボタンとシーン単位の切替を排し、歩くこと（スクロール・矢印キー・スワイプ）そのものが読み進む行為になる空間を作る。
- **Dark 外観（標準・初期値）**: 背景 `#050608`、インク `#ece8df`。天井のダウンライトから壁・床へ落ちる暖色光と、暗いスレート壁面の対比で展示空間を作る。未選択時の開始外観は本体の設定によらず Dark を標準とする。
- **Light 外観**: 背景 `#eae6dc`、インク `#1a1c22`。石灰岩・漆喰調の明るい美術館ギャラリー空間とし、壁面のアクセント色（引用・数値・左枠線・門番号）は `color-mix(in srgb, rgb(var(--tint)) 42%〜55%, #141720)` で明度を下げて判読性を確保する。
- **ゾーン別アクセント色（`--tint`）**: 表紙〜各章ごとにウォームホワイト（`255, 236, 205`）、アンバー（`255, 207, 122`）、アイスブルー（`122, 208, 255`）、ミントグリーン（`141, 255, 200`）、ローズピンク（`255, 158, 203`）を循環割り当てし、進捗バーと門・照明の光色に連動させる。

## DTP-MWLK-020 空間断面（通路・広間・小部屋）と建築ディテール

同じ断面の廊下を連続させず、内容の役割に応じて 3 種類の空間断面（`SECTIONS`）を切り替える。

| 空間種別       | 半幅（`half`）            | 天井高（`FLOOR - ceil`）            | 用途 |
| :------------- | :------------------------ | :---------------------------------- | :--- |
| 通路（標準）   | `520px`（全幅 `1040px`）  | `1005px`（床 `360` / 天井 `-645`）  | 章の導入、本文、箇条書き、数値の並列展示 |
| 広間（`hall`） | `1100px`（全幅 `2200px`） | `1860px`（床 `360` / 天井 `-1500`） | 通路中央に立体図（`DTP-MWLK-050`）を据える開けた空間 |
| 小部屋（`alcove`） | `400px`（全幅 `800px`） | `820px`（床 `360` / 天井 `-460`） | 引用・注記（`aside`）を壁に近づいて読む親密な空間 |

- **境界の建築処理と空間の起伏（#306）**: 断面が変わる境目には左右の袖壁と上部の垂れ壁を配置し、開口部の奥に次の空間が見える奥行きを作る。さらに空間全体に高低差の起伏（入口を基準 `0` とし、中盤約 62% にかけて徐々に下へ降り、後半にかけて少し上へ戻る谷型プロファイル。最大高低差 360px 以内）を設け、高さが変わる境目には蹴上げ板（`.mw-riser`）とスロープ（`.mw-ramp`、基準奥行き `220px`）を配置して段差の隙間を防ぎながら滑らかにつなぐ。
- **建築ディテール**: 壁面は `1000px` 単位の縦目地・上部ダウンライトコーン・下部シャドウギャップ巾木、床面は左右壁際と中央のスペキュラ反射、スロープは緩やかなノンスリップ溝、天井は 3 列の光源スポットを持つ。
- **採らなかった案**: 文書の内容から建物を自由生成する案（`RGH-144`）。初期実装では空間破綻を防ぐため、通路・広間・小部屋の 3 型に絞る。

## DTP-MWLK-030 壁面パーツの奥行き・出現・文字精度

章を 1 枚の平面に閉じ込めず、パーツ種別ごとに壁面からの浮き出し量（`off`）と出現距離（`range`）をずらす。

| 種類              | 奥行き `off`    | 出現距離 `range` | 組版・装飾の狙い                                       |
| :---------------- | :-------------- | :--------------- | :----------------------------------------------------- |
| `h3` / `h3shadow` | `150px` / `3px` | `3700` → `2600`  | 章の小見出しを空間に浮かせ、壁面に落とした影（`h3shadow`）で立体感を出す。明朝体 `82px`（表示相当） |
| `number`          | `110px`         | `3600` → `2500`  | 右壁に配する大判数値アクセント（`260px` 相当＋ラベル） |
| `quote`           | `60px`          | `3300` → `2300`  | 印象的な一文を明朝体 `62px` 相当で浮かせる             |
| `bullet`          | `46px`          | `2000` → `1300`  | 左端にゾーン色の縦線を持つ箇条書き                     |
| `aside`           | `24px`          | `1500` → `800`   | 小部屋用の引用銘板。左縦線＋等幅小見出し（`CURATORIAL NOTE`）を添える |
| `body`            | `20px`          | `2300` → `1500`  | 壁面に寄り添う本文・壁面画像（`34px` 相当、行間 `1.78`、`line-break: strict`）。壁タイルとの Z-fighting を防ぐため `20px` 浮かす（#415） |

- **図（画像だけの段落）と、横に添える文章**（#423）: 画像だけの段落は、壁パーツの幅 `1000px`（ふつうの本文は `660px`）いっぱいに広げて置く（`img` は幅 100%）。画像の中の文字は、画像と一緒に縮むため、小さい図をそのまま置くと、スマホの画面では読めなくなる。図のすぐ後ろに続く短い段落（160 字以内）は、図の列の隣（奥へ `100px`）に新しい列を開き、小さな文字（`50px` 相当、不透明度 `.86`、幅 `600px`）で、図の上端から `60px` 下げて置く。図に続く段落が何本あっても、添える文章の列に積む。図を主役に、文章はそっと添える狙い。160 字を越える段落と、図の後ろに続かない段落は、ふつうの本文として積む。
  - **背景・根拠**: 図の上に文章を積むと、図が壁の下の方へ追いやられ、画面の中で小さくなる（図 480px、文章の列 660px の壁で、図は壁の 7 割ほどにしか見えない）。図を広げて列の高さを使い切れば、続く文章は、列に収まらず、自然に隣の列になる。
  - **採らなかった案**: 図の上に文章を置く案（図が小さく、文章が主役に見える）。文章を図の中（SVG の文字）に入れる案（スマホでは読めない）。
- **近接 3D 文字の先鋭化**: 小部屋や壁面手前で CSS 3D 変形により拡大される文字のボケを防ぐため、壁面の文字要素は CSS 上で **2 倍のフォントサイズおよび幅** でラスタライズし、3D `transform` の末尾で `scale(0.5)` に縮小して配置する。

## DTP-MWLK-040 章の門（`.gate`）と通り抜け演出

表紙および章の見出し（`h2` 相当）は通路中央に立つ「門」として配置し、近づいて通り抜ける。

- **額縁と紗幕（`.scrim`）**: 通路幅いっぱいにベタ塗りせず、左右 `28px` の隙間と上端・左右の細いアクセント枠を残すことで、門の周囲に回廊の奥行きを見せる。中央部は暗め（Light では明るめ）の半透明グラデーションで文字の可読性を保つ。
- **概要文（`.mw-sub`）の収め方（#386）**: 表紙の概要文は、門の内側の幅の 82% までに収め、3 行を超える分は省略する（`-webkit-line-clamp: 3`）。入口で表紙を斜めに見るとき、門の左右の端は、手前の壁に隠れて切れる。概要文を端いっぱいまで広げると、行の頭と終わりの文字が切れるため。題名は `fitTitle()` が幅に収める。
- **奥の要素との重なり防止（`behindGate`）**: 手前の門が閉じている間は、門より奥にある壁面パーツ（最小不透明度 `0.04`）および次の門（最小不透明度 `0`）の透明度を抑え、文字同士が透けて重なるのを防ぐ。
- **通過演出**: 門に近づくと門全体がフェードして開き、通過の瞬間にゾーン色の淡い光フラッシュ（最大不透明度 `0.34`）を発する。
- **採らなかった案**: 門や展示物を壁側へ避けて回り込む動線（`RGH-912`）、2D の全画面スライドを正面に重ねる案（`RGH-136`）。

## DTP-MWLK-050 広間の立体図（3 層スタンド）

広間の通路中央には、図を構成する 3 つの層を Z 軸（進行方向）へずらして立て、手前の層から順に通り抜ける。

1. **枠とキャプション層（`.fig-frame`, `dz = 0`）**: スモークガラス調パネル（Light は白磁調）の左上隅に展示ラベル（`EXHIBIT nn`）、下端にキャプションと床面へ落ちる光の台座を持つ。図は、札の下に札の高さの余白（枠の上端から `104px`）を空けて置く。線とノードの層は手前（`dz = +70px`・`+210px`）にあり、カメラからは枠より大きく見えるため、余白が小さいと札と図の題名・象限名が重なる（#388）。
2. **接続線層（`.fig-lines`, `dz = +70px`）**: ノード間を貫く 1 本の光学ライン。
3. **ノード層（`.fig-nodes`, `dz = +210px`）**: 各項目を示す角丸カード（先頭カードにゾーン色のアクセント枠と光彩、上部に等幅の連番タグ）。

- 層ごとにカメラ接近でフェードアウト・`display: none` となり、通り抜けた奥の空間がそのまま開ける。
- **《感情の地図》の立体展示（`mw-emotion-cube`）**: 配色ミュージアムの《感情の地図》では平面の額縁を使わず、CSS 3D（`preserve-3d`）で淡く透明感のある 4 象限の立方体を 2 列 × 上下 2 段の互い違い（右柱を奥上へずらし、横から見ても 4 象限が重ならない配置）に組み、その空間内に 14 の配色を光の球体として浮かべ、球体の下に中央寄せのトーン名ラベルを添える。

## DTP-MWLK-060 カメラワークと操作体系

- **視線の自動制御（`G` で切替）**: 歩行中は進行方向寄り（`walkYaw: 14°`）を向き、立ち止まると左壁へ自然に正対する（`stopYaw: 50°`）。
- **場所ごとの誘導（`cues()`）**:
  - **門の手前〜通過直後**: 通路中央（`x = 0`）へ寄り正面（`yaw = 0°`）を向く。
  - **広間**: 中央（`x = 0`）で正面を向き、立体図を見上げる（`hallPitch: 7°`）。
  - **小部屋**: 長い引用の銘板も画面に収まる視距離・角度へ寄せる（`alcoveX: 190`、`alcoveYaw: 68°`）。
  - **突き当たり**: 正面を向く。
- **縦長画面（Portrait、`innerWidth < innerHeight * 0.8`）の自動補正**: スマホ等の狭い縦画面で見出しや本文が左右に切れないよう、停止時の向き（最低 `52°`）、立ち位置（最低 `x = 240`）、視野距離 `P`（最小倍率 `0.45`）を自動調整する。
- **近寄り・離れるカメラワーク（#275, #293, #294, #295）**: 立ち止まった観覧者が展示に一歩寄るように、`Ctrl`＋ホイールまたは `+` / `=` / `-` / `0`（`Ctrl` 併用含む）でカメラを壁側へ寄せ、あわせて視野をわずかに狭めて遠近感を自然に保つ。近寄り・離れ・戻りの移動中にはゆったり大きく一歩踏み出す上下の揺れ（`zoomBob` / `zoomBobSpeed`）を加え、前進・後退の歩行時にも独立した上下の揺れ（`bob` / `bobStep`）を加えて歩いている感覚を出す。壁・柱・門・立体図の脇を通り抜けないよう場所ごとの空間半幅の上限で止め、動きを減らす設定時は上下の揺れ（歩行・ズーム双方）を抑えて即座に切り替える。また、前進・後退のホイール反応量（`wheelSpeed`）とズームのホイール反応量（`zoomWheelStep`）はそれぞれ独立して調整可能とする。
- **カメラの高さ追従と酔い対策（#306）**: カメラの基準高さ `y` を現在位置 `z` の床・スロープ高さ（`elevationAt()`）へ滑らかに追従させ（`elevEase`、歩行揺れ `bob` と合成）、水平目線を保ったまま段差の上下動を体感させる。`prefers-reduced-motion` 有効時は揺れを 0 にし、高さ追従を即座に切り替える。
- **操作**: ホイール・`↑` `↓` `→` `←` `W` `S` `Space`・上下スワイプで歩行（短押しは歩幅 `stride` だけ進む）、`Ctrl`＋ホイール・`+` `-` `0`（`Ctrl` 併用含む）で近寄る・離れる・戻る、ドラッグで見回し、`Esc` で元の表示へ戻る（Lucivo 本体の発表モード終了規約 `ARC-MODE-006` / `007`）。

## DTP-MWLK-070 描画性能の制約（ゼロ・リペイント原則）

CSS 3D 空間で多数の巨大面を滑らかに歩かせるため、実装時は次の描画制約を必ず守る。

1. **歩行中の再ペイント・レイアウト禁止**: `.mw-wall`・`.mw-floor`・`.mw-ceil`・`.mw-ramp`・`.mw-riser` は子要素や `::after` 疑似要素を持たない単一 3D リーフ要素とし、`width`・`height`・`transform`・`background` は初期化時に 1 回だけ設定して歩行中は書き換えない（CSS 変数更新によるグラデーション再描画や `filter: blur()` によるオフスクリーン合成を禁止）。
2. **距離フォグの表現**: 遠景への減衰は各タイルの `style.opacity`（40 段階量子化）の更新のみで行い、GPU コンポジタだけで完結させる。
3. **3D クリッピング崩れの防止**: 視界外やカメラ背面の要素は `visibility: hidden` ではなく `display: none` で描画ツリーから外し、Chromium の `preserve-3d` 空間分割による欠け・黒箱化を防ぐ。
4. **描画の軽さ（4 段階、#426）**: 描画のメモリが足りない端末（スマホなど）で、門の題名や壁の文字が欠ける、または描かれなくなる（#421）のを減らすため、同時に描く面の数を、段階で調整する。段階が大きいほど軽い。

   | 段階 | 名前（案） | 霞みの始まり `fog0` | 真っ暗になる距離 `fog1`（これより先の壁・文字・門は `display: none`） | 床・天井の届く距離 `flat` | タイル 1 枚の長さ `tile` |
   | :--- | :--------- | ------------------: | --------------------------------------------------------------------: | ------------------------: | -----------------------: |
   | 1    | くっきり   | 900                 | 7000                                                                  | 7000                      | 1000                     |
   | 2    | ふつう     | 750                 | 5000                                                                  | 5000                      | 1000                     |
   | 3    | 軽い       | 450                 | 2500                                                                  | 1500                      | 1000                     |
   | 4    | とても軽い | 300                 | 1800                                                                  | 900                       | 500                      |

   - **床・天井だけ短くする理由**: 床・天井のタイルを隠すと、門の縦の切れが消えた。遠くの床・天井は、霞みでほとんど暗く、短く切っても、見た目の損が小さい。床・天井は、`fog1 / flat` 倍に縮めた霞みで、`flat` の距離で真っ暗にし、切れ目を見せない。
   - **決め方**: URL の指定（`museum-light=1`〜`4`。`museum-mem` は段階 3 の別名）→ 保存した段階（`localStorage`）→ 端末の既定（PC は 1、タッチ主体で短辺 768px 以下の画面は 3）。範囲外・不正な値は、次の決め方へ進む。
   - **背景・根拠**: 実機（Pixel 7 Pro、Chrome）で、見える距離を 3500px に縮めると、だいぶ改善し、さらに、見える距離 2500px・床と天井 1500px にすると、いちばん良かった。そこで、段階 3 を、この値にした（スマホの既定）。段階 4 は、それより軽い、安全側の段階にする。壁の文字と壁、門と床・壁の間隔を広げる案は、実機で効かなかった（奥行きの取り違えは、原因として外れた）。
   - **タイルを短くする理由（段階 4）**: タイルは 1 枚 1000px で、手前の 1〜2 枚は必ず描かれるため、見える距離を 1000px 前後まで縮めても、タイルが 1000px のままでは、描く面積があまり減らない。段階 4 は、タイルを 500px にして、切り取る範囲を細かくする（枚数は増えるが、描く面積は減る）。代表の止まり位置での、壁・床・天井の描く長さ（平均）は、段階 1 を 100% として、段階 2 が 76%、段階 3 が 35%、段階 4 が 26%。タイルを短くすると、天井の照明（タイルごとに 1 つ）が、細かく並んで見える。
   - **採らなかった案**: 見える距離の数値を、利用者が直接入力する案（値の意味が分かりにくく、極端な値で表示が壊れる）。端末の自動判定だけで決める案（誤りを、利用者が直せない）。
   - **設定の画面**（#426）: 「その他（アプリ設定）」のモーダルの末尾に、「ミュージアム・ウォークの描画の軽さ」の節を置く。プルダウンの 5 択（おまかせ（端末に合わせる）・1 くっきり・2 ふつう・3 軽い・4 とても軽い）と、「門や壁の文字が欠けたり、描かれなかったりするときは、軽い段階を選びます。変更は、次にミュージアム・ウォークを始めるときから効きます。」という説明を添える。スマホ幅では、設定の他の節と同じく縦に並べる。
     - **「おまかせ」を置く理由**: 5 択目がないと、一度選んだ段階を、端末の既定（PC は 1、スマホは 3）に戻せない。「おまかせ」を選ぶと、保存した段階を消す。
     - **プルダウンにする理由**: 4 段階を、ラジオボタンで並べると、スマホ幅で縦に長くなり、設定の画面の他の節（チェックボックス 1 つ）と比べて、重くなる。
     - **採らなかった案**: 段階を、スライダーで選ぶ案（段階の名前が見えず、4 段階が連続の値に見える）。ミュージアム・ウォークの中（`C` キーの調整パネルなど）に置く案（欠けるなどの症状で、歩けない人が、選べなくなる）。
   - **決めていないこと**: 段階 4 の見た目（天井の照明の並び、遠景の短さ）が、安全側の段階として許せるか。段階 2 と 3 の間隔（5000/5000 と 2500/1500 の間が空いている）に、もう 1 段階が要るか。
