# デザイン仕様: Visualモードの記述パターン別の雛形と動的ステージ演出（visual-templates）

Visualモードでは、文書を章（`h2`）ごとのスラブに分ける。本仕様は、スラブの中身の記述パターンを判定し、パターンに合った誌面の雛形・ベクター装飾素材で割り付けるとともに、講演・展示でのリアルタイムな視線誘導を支える動的ステージ演出を定める。全体の版面・配色・書体は [DTP 全体設計書](../README.md)（`DTP-001`〜`004`）に従う。

- 対応する要求: `FR-016`, `FR-017`, `FR-020`, `FR-021`, `FR-027`, `FR-029`〜`FR-032`, `FR-035`, `FR-036`（[visual-templates.md](../../1.SRS/features/visual-templates.md)）、`FR-015`（解説＋図版型）、`FR-034`（コールアウト。[markdown-typography.md](../../1.SRS/features/markdown-typography.md)）
- 採用したラフ: `RGH-001`〜`RGH-008`, `RGH-013`, `RGH-101`, `RGH-102`, `RGH-104`, `RGH-107`, `RGH-111`, `RGH-112`, `RGH-115`, `RGH-118`, `RGH-119`（[roughs/README.md](../roughs/README.md)）
- 使用する素材: フォント `AST-001`〜`AST-004`、ベクター装飾素材 `AST-005`〜`AST-008`, `AST-109`, `AST-110`、コールアウトのアイコン `AST-113`（[assets/README.md](../assets/README.md)）

## DTP-VTPL-001 雛形の判定

スラブの「本文要素」（見出し `h2` とフロントマターを除く、スラブ直下の要素）を調べ、上から順に最初に当てはまる雛形を適用する。

| 順位 | 雛形                        | 記述パターン（条件をすべて満たす）                                  |
| :--- | :-------------------------- | :------------------------------------------------------------------ |
| 1    | 解説＋図版型（`split`）     | 図がちょうど 1 つあり、本文要素が 1 つ以上ある（`FR-015`）          |
| 2    | 標準型（`standard`）        | 図が 1 つ以上ある（1 位に当てはまらないもの）、または本文要素がない |
| 3    | リード型（`lead`）          | 本文要素が段落（`p`）だけで 1〜2 個、文字数の合計が 1〜160 字       |
| 4    | 定義リスト型（`glossary`）  | 本文要素が「箇条書き（`ul`）1 つ」または「段落 1 つ＋箇条書き 1 つ」。項目が 2〜12 個で、どの項目も `**用語** — 説明`（太字の用語の直後がダッシュ `—` `–` `―`）の形。用語は 40 字以内、項目は 200 字以内で、入れ子のリスト・コード・表・引用・チェックボックスを含まない（`DTP-VTPL-045`） |
| 5    | 要点カード型（`points`）    | 本文要素が「箇条書き（`ul`）1 つ」または「段落 1 つ＋箇条書き 1 つ」。項目が 2〜6 個で、どの項目も入れ子のリスト・コード・表・引用・チェックボックスを含まず 100 字以内 |
| 6    | 手順型（`steps`）           | 本文要素が「番号付きリスト（`ol`）1 つ」または「段落 1 つ＋番号付きリスト 1 つ」。項目が 2〜8 個で、項目の条件は 5 位と同じ |
| 7    | ステートメント型（`quote`） | 本文要素が引用（`blockquote`）1 つだけで、その中身が段落 1〜3 個、合計 240 字以内 |
| 8    | 標準型（`standard`）        | 上記のいずれにも当てはまらない                                      |

- 文字数は、要素の文字（`textContent`）の前後の空白を除いた長さで数える。
- 背景: 雛形は「一目で主役が分かる」量の内容にだけ使う。上限を超える長い段落・項目の多いリストを大きな文字やカードにすると、展示パネルとして読み切れない量になり、かえって品質が下がるため、標準型に戻す。
- 背景（小見出しを含む章）: `h3` などの小見出し、表、コード、ブロック数式を含む章は、構成が複合しているため標準型とする。

## DTP-VTPL-010 標準型（standard）

- これまでのスラブの組版（`FR-003` / `FR-009`）のまま。見出しの下に本文要素を上から順に流す。
- 雛形を適用しない章の受け皿であり、すべての Markdown 記法を見分けられる組版を保つ（`FR-009`）。

## DTP-VTPL-020 リード型（lead）

用途: 章の主張・概要を述べる短い文章（文書の冒頭の導入文など）。

```text
┌ STAGE 01  概要 ───────────────────────────────┐
│ ┃ Lucivo は、Markdown を展示品質の誌面に         │
│ ┃ 変換するビューアーです。                       │ ← 大きめ・太めの本文
└────────────────────────────────────────────────┘
  ┃ = 4 色のグラデーションの縦線（--vs-c1 → --vs-c4）
```

- 段落を 1 つのリードの枠（`.vs-lead`）にまとめ、左に幅 4px・角丸 2px の縦線（4 色のグラデーション）を引く。縦線と文字の間は `1.25rem`。
- 文字は `DTP-004` のリード（`clamp(1.1rem, 1.8vw, 1.35rem)`・600・行送り 1.85）、色は主文字色（`--text-primary`）。
- 2 つ目の段落との間は `0.75rem`。

## DTP-VTPL-030 要点カード型（points）

用途: 特長・要点・選択肢などの並列の項目。

```text
┌ STAGE 02  特長 ─────────────────────────────────────────┐
│ （導入の段落があれば、ここに通常の本文で置く）            │
│ ┌▀▀▀▀▀▀▀▀▀▀▀┐ ┌▀▀▀▀▀▀▀▀▀▀▀┐ ┌▀▀▀▀▀▀▀▀▀▀▀┐            │
│ │ 01      ◢ │ │ 02      ◢ │ │ 03      ◢ │  ▀ = 上端 4px の帯 │
│ │ 軽快       │ │ 展示品質   │ │ 記法そのまま│  ◢ = AST-007 コーナー透かし │
│ │ 説明文…    │ │ 説明文…    │ │ 説明文…    │            │
│ └────────────┘ └────────────┘ └────────────┘            │
└──────────────────────────────────────────────────────────┘
```

- 箇条書きをカードのグリッドにする。間隔は `1rem`。列の数は項目の数から決め、最後の行に 1 枚だけ残る端数を作らない。

  | 項目の数 | 列の数                                    |
  | :------- | :---------------------------------------- |
  | 2・3     | 項目の数と同じ（1 行）                    |
  | 4        | 2（2 × 2）。版面 56rem 以上では 4（1 行） |
  | 5・6     | 3                                         |

  版面 30rem 以下では 1 列にする。
- カード: 角丸 16px、内側の余白 `1.25rem`、背景は本文より一段明るい（Light `#F8FAFC` / Dark `rgba(15, 23, 42, 0.45)`）、枠線 1px、影 `0 6px 18px -8px rgba(15, 23, 42, 0.12)`。
- 上端に幅 4px の帯を付ける。帯の色は項目の順に `--vs-c1`→`--vs-c2`→`--vs-c3`→`--vs-c4` を繰り返す。
- **コーナーファセット装飾（`AST-007`）**: カードの右上に `.vs-card-ornament`（`56px × 56px`）を置き、`assets/motifs/card-corner-ornament.svg` を CSS `mask-image` で適用して項目のアクセント色（`--vs-c`）で塗る（通常時の不透明度 `0.55`、ホバー・スポットライト時は `0.95` に高まり微細に拡大する）。
- カードの先頭に 2 桁の番号（`01`, `02`…）を置く。`DTP-004` のカードの番号（1.75rem・800）、色は帯の色を濃く（Dark では明るく）した色（`DTP-003`）。
- 項目が「**題**: 説明」（太字の直後に `:` または `：`）で始まる場合は、太字を項目の題（1rem・700・主文字色）として番号の下に独立した行で置き、区切りの `:` は表示しない。
- 導入の段落がある場合は、カードの上に標準型の本文として置く。

### DTP-VTPL-035 KPI メトリクス・ショーケース（要点カード型の派生）

用途: 要点カード型のうち、項目の題（`.vs-point-title`）が数値・指標を表すカード（`RGH-104`、`FR-027`）。

- **判定規則**: 項目の題（太字部分）が `120ms`, `99.9%`, `3.2x`, `+48%`, `< 15ms`, `$1.2M`, `2,400件`, `0依存` などの純粋な数値・指標パターン（数字＋単位・接頭/接尾記号のみで、20 字以内かつ 2 文字以上の連続する日本語や 4 文字以上の連続する英単語を含まないもの）に一致するとき、そのカード（`li`）に `.vs-metric-item`、題の `strong` に `.vs-metric-value` を付与する。
- **混在許容**: リスト内の全項目が数値で揃っていなくても、条件を満たすカード単位で個別に昇格させる。
- **タイポグラフィ**: `.vs-metric-value` は Plus Jakarta Sans / JetBrains Mono・`clamp(1.75rem, 2.8vw, 2.35rem)`・800・`font-variant-numeric: tabular-nums`・字間 `-0.03em`・行送り `1.1` で、カードのアクセント文字色（`--vs-c-text`）で大きく際立たせる。カード先頭の連番（`01`, `02`…）は数値の主役を邪魔しないよう `0.8rem`・不透明度 `0.55` に控える。

### DTP-VTPL-036 タイムライン・ロードマップ修飾（要点カード型の派生）

用途: 要点カード型のすべての項目（2 個以上）の題が日付・四半期・フェーズ・マイルストーン・バージョンを表す章（`RGH-112`、`FR-029`）。

- **判定規則**: 要点カード型（`ul.vs-points`）のすべての項目が題（`.vs-point-title`）を持ち、かつ全項目の題が `2026 Q1`, `2026-04`, `2026年5月`, `Phase 1`, `Step 2`, `Milestone 3`, `v1.2`, `Day 1`, `第1期` などの時系列・フェーズ表記に一致するとき、`ul.vs-points` に `.vs-points-timeline`、各 `li` に `.vs-timeline-item`、題の `strong` に `.vs-timeline-badge` を付与する。
- **デザイン**: カードのグリッド配置は維持したまま、`.vs-timeline-badge` を等幅フォント（JetBrains Mono・`0.82rem`・700）の角丸ピルバッジ（背景 `color-mix(in srgb, var(--vs-c) 18%, transparent)`、枠線 `1px solid color-mix(in srgb, var(--vs-c) 48%, transparent)`）として上部に配置し、カード間に破線の接続ガイドを通して時系列の連続性を示す。

### DTP-VTPL-037 Before / After 比較ペアカード修飾（要点カード型の派生）

用途: 従来と導入後、課題と解決策などを左右 2 枚のカードで対置する章（`RGH-111`、`FR-030`）。

- **判定規則**: 要点カード型（`ul.vs-points`）の項目がちょうど 2 個で、1 項目目の題が課題側（`Before`, `従来`, `旧`, `課題`, `現状`, `As-Is` で始まる）、2 項目目の題が解決側（`After`, `導入後`, `新`, `解決`, `改善`, `To-Be` で始まる）に一致するとき、`ul.vs-points` に `.vs-points-compare`、1 項目目に `.vs-compare-before`、2 項目目に `.vs-compare-after` を付与する。
- **デザイン**:
  - `.vs-compare-before`（課題側）: 上端帯とアクセントを控えめなスレートグレー（`#94A3B8`）に抑え、背景の彩度を落として「過去の課題」として一歩引かせる。
  - `.vs-compare-after`（解決側）: アクセント色（`--vs-c2`）の太枠（`2px`）と光彩付きの影で浮き上がらせ、導入後の価値・解決策に視線を集める。

### DTP-VTPL-038 コード・ショーケース（全幅暗色パネル・言語ラベル・ワンクリックコピー）

用途: Visualモード内のすべてのコードブロック（`<pre><code>`）を、技術プレゼン・仕様展示にふさわしい暗色コンソールパネルとして仕立てる（`RGH-102`、`FR-031`）。

- **対象**: 図版（`.diagram-container`）内部を除く、スラブ内のすべての `<pre><code>` 要素。コードだけの章の専用雛形にはせず、どの雛形（標準型・解説＋図版型など）の章に置かれたコードブロックにも一貫して適用する。
- **ヘッダー装飾と丸端キャレット素材（`AST-109`）**:
  - `<pre>` に `.vs-code-block` と `data-code-lang="<LANG>"`（`code` の `language-xxx` クラスから抽出、指定がない場合は `CODE`）を付与する。
  - 左上に丸端キャレット・グリフ（`AST-109`: `assets/motifs/rounded-caret-glyph.svg`、`.vs-code-caret`、`28px × 14px`、`mask-image`、塗り `--vs-c1`）と、その右に等幅大文字の言語ラベル（`::before { content: attr(data-code-lang) }`）を配置する。
- **ワンクリックコピーボタン（`.vs-code-copy-btn`）**:
  - 右上にコピーボタンを置き、ラベルは DOM のテキストノードを増やさないよう `data-copy-label="COPY"` の CSS 擬似要素（`::after`）で表示する。
  - クリックするとコード文字列をクリップボードへコピーし、`1.6 秒` の間 `.is-copied`（`data-copy-label="COPIED"`、エメラルド色 `#34D399`）に切り替える。
- **配色**: Light / Dark を問わず、コードブロックの背景は深いスレートネイビー（`#0F172A`）、文字は明るいアイスグレー（`#E2E8F0`）とし、ステージ上でのコントラストと可読性を保つ。

### DTP-VTPL-039 コールアウト（GitHub アラート記法）

用途: 注記・ヒント・重要事項・警告・注意を、本文から一段浮かせたパネルで示す（`RGH-118`、`FR-034`）。雛形ではなく、どの雛形の章に置いても同じ見た目にする（コード・ショーケースと同じ扱い）。高速モードの見た目は [markdown-typography の設計](../../3.sw_design_notes/features/markdown-typography.md)（`DD-MD-021`）に定め、構成（アイコン・ラベル・左線・淡い背景）は両モードで共通にする。

```text
▍ ⓘ NOTE                     ← アイコン 16px（AST-113）＋ラベル（等幅・大文字・0.14em）
▍ 本文（通常の大きさ・--text-secondary）
▍ ← 左線 3px（意味の色）  背景: 意味の色 7%  角丸: 0 12px 12px 0
```

- **種類と意味の色**: スタイル（4 色）に依らず、種類ごとの意味の色を使う（`RGH-910`）。Light / Dark で明るさを変え、どちらの背景でもラベルを判読できるようにする。

  | 種類        | ラベル      | アイコン（`AST-113`）  | Light     | Dark      |
  | :---------- | :---------- | :--------------------- | :-------- | :-------- |
  | `NOTE`      | `Note`      | 円の中の i             | `#2563EB` | `#60A5FA` |
  | `TIP`       | `Tip`       | 電球（「Luc-（光）」） | `#059669` | `#34D399` |
  | `IMPORTANT` | `Important` | 吹き出しの中の !       | `#7C3AED` | `#A78BFA` |
  | `WARNING`   | `Warning`   | 角の丸い三角形の中の ! | `#D97706` | `#FBBF24` |
  | `CAUTION`   | `Caution`   | 角の丸い八角形の中の ! | `#DC2626` | `#F87171` |

- **パネル**: 左線 3px（意味の色）、背景は意味の色を 7%（Dark は 10%）だけ混ぜる。角丸は右側だけ 12px、内側の余白 `0.95rem 1.2rem`、上下の外側の余白 `1.1rem`。影は付けない（カード・図の影と主役を競わないため）。
- **題の行**: アイコン（16px、`mask-image`、塗りは意味の色）とラベル（JetBrains Mono・`0.72rem`・700・字間 `0.14em`・大文字）。ラベルの色は意味の色とし、DOM の文字は `Note` のように頭文字だけ大文字で持つ（大文字にするのは CSS の `text-transform`。コピーした文字が叫び調にならないように）。
- **種類を色だけで示さない**: アイコンの形・ラベルの文字・色の 3 つで種類を示し、色覚の多様性と白黒の印刷に耐えるようにする。
- **発表**: ステージ発表では、本文の拡大に合わせてアイコン・ラベル・余白を相対単位（`em`）で大きくする。

## DTP-VTPL-040 手順型（steps）

用途: 手順・工程・時系列など、順序に意味のある項目。

```text
項目が 4 個以下で、版面の幅が 40rem 以上の場合（横並び）
   (1)━━ » ━━(2)━━ » ━━(3)━━ » ━━(4)   » = AST-008 方向シェブロン
  受け付ける   確認する    発注する    出荷する

項目が 5 個以上、または版面の幅が 40rem 未満の場合（縦並び）
   (1) 受け付ける
    ┃
   (2) 確認する
    ┃
   (3) …
```

- 番号付きリストを、番号の丸と接続線・方向シェブロン（`AST-008`）でつないだ手順図にする。
- 番号の丸: 直径 `2.5rem`、塗りは項目の順に `--vs-c1`〜`--vs-c4`、文字は濃紺（`#1E293B`、1.05rem・800）。丸の周りにスラブの背景色の輪（5px）を付け、接続線から浮かせる。
- 接続線: 太さ 2px、色は強い線の色（Light は `--border-strong`、Dark は `#64748B`）。丸の中心を結ぶ。
- **方向シェブロン素材（`AST-008`）**: 2 番目以降の各ステップ（`li:not(:first-child)`）に `.vs-step-chevron`（`14px × 14px`、`assets/motifs/step-arrow.svg` の `mask-image`）を置き、前のステップからの進行方向を示す（横並びでは左側の接続線上、縦並びでは 90 度回転して上側の接続線上）。
- 横並び: 項目を等幅の列に置き、丸の下に中央揃えで文字を置く。版面の幅（スラブの幅）で判定するため、`Split` 表示の狭いプレビューでも詰まらない。
- 縦並び: 丸を左に、文字を丸の右（左端から `3.5rem`）に左揃えで置き、項目の間隔は `0.9rem`。
- 導入の段落は、要点カード型と同じく手順の上に置く。

## DTP-VTPL-045 定義リスト型（glossary）

用途: 用語集・略語表・役割の一覧など、「用語」と「その説明」の対を並べる章（`RGH-115`、`FR-035`）。

```text
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ← 2px・--vs-c1（誌面の表の見出しの線と同じ）
 ● Slab           1 章を載せる面。角丸と影で独立する     ← 用語: 等幅・700 ／ 説明: 本文
─────────────────────────────────────────────────  ← 1px・--vs-card-border
 ● Scene          ステージ発表で 1 度に映す単位
─────────────────────────────────────────────────
   ↑ 用語の列 7.5rem〜13rem（行の幅の 34% まで）↑ 説明の列（残り）
```

- **判定規則**: `DTP-VTPL-001` の 4 位。区切りをダッシュ（`—` `–` `―`）にした `**用語** — 説明` だけを対象とし、コロン区切り（`**題**: 説明`）は要点カード型のまま変えない（`RGH-909`）。
- **組み方**: 箇条書きを定義リスト（`dl.vs-glossary`）に組み替え、項目ごとに `div.vs-gloss-row` の中へ用語（`dt`）と説明（`dd`）を置く。区切りのダッシュは消す。

- **説明**: 本文と同じ書体・`0.95rem`・行間 1.7・`--text-secondary`。
- **罫線と余白**: 最初の行の上に 2px のアクセントの線（`--vs-c1`）、各行の下に 1px の罫線（`--vs-card-border`）。行の上下の余白は `0.85rem`、列の間は `1.5rem`。用語の列の幅は `7.5rem` 以上、`13rem` と行の幅の 34% の小さい方以下とする（2 段に並べたとき、用語の列が段の幅の 4 割を超えて説明が細く折り返されたため。校正の赤字）。縦の罫線は引かない（誌面の表 `DTP-VTPL-110` と同じ調子）。

- 背景: 用語は書き手が文書の中で定義した「名前」であり、コードの識別子と同じく等幅で揃えると、拾い読みのときに目が用語の列だけを縦に追える。ブランドの「丸みのある等幅」（[ブランドコンセプト 1.2.5](../../1.SRS.md#125-ビジュアルデザインディレクション方針visual-tone--style)）の論理性をそのまま誌面に出せる。

## DTP-VTPL-110 誌面の表

用途: 表を、エディトリアルデザインの「罫線で組む表」にする。セルを格子で囲む表計算ソフトの見た目をやめ、行と列を余白と横の罫線で読ませる（`RGH-101`）。

```text
 雛形           最小項目数   最大項目数   合計の上限      ← 見出し: 0.78rem・700
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ← 2px・--vs-c1
 リード型                1            2       160 字      ← 先頭の列は行の見出し（600・主文字色）
───────────────────────────────────────────────────  ← 1px・--vs-card-border
 要点カード型            2            6            —      ← 数値の列は右揃え・等幅の数字
───────────────────────────────────────────────────  ← 最後の行の下は強い線
```

- 縦の罫線は引かない。行の下に 1px の罫線（`--vs-card-border`）、最後の行の下は強い線（Light は `--border-strong`、Dark は `#64748B`）、見出しの行の下は 2px のアクセントの線（`--vs-c1`）とする。見出しの行の背景は塗らない。
- 見出し: Inter / Noto Sans JP・`0.78rem`・700・字間 `0.02em`・下揃え。大文字にしない（高速モードの JetBrains Mono・大文字の見出しは仕様書の調子のため）。
- セルの余白は `0.8rem 0.9rem`、上揃え。行にポインタを重ねると、行の背景を `--vs-c1` で 7% だけ染める。
- **先頭の列**: 行の見出しとして 600・主文字色にする。
- **数値の列**: 本文のセルがすべて数値（数字に単位・記号が付いたもの。`—` などの欠損の印は除く）の列は、見出しとセルを右揃え・等幅の数字（`tabular-nums`）・折り返しなしにし、セルの数字を Plus Jakarta Sans・700 にする。先頭の列と、Markdown で揃え（`:--` など）を指定した列は対象外とし、書き手の指定を優先する。
- **短いラベルの列**: 本文のセルがすべて 10 字以内で空白を含まない列は、セルを折り返さない（「リー／ド型」のような語の途中の改行を避ける）。
- **それ以外の列**: 文節の区切りで折り返す（`word-break: auto-phrase`）。ただし文節の幅で列の最小幅を広げない（`overflow-wrap: anywhere`）。多列の表も版面に収めるため（`TC-VTPL-014`）。列の幅は `6em` を下限とし、狭い版面（`Split` 表示など）で下限の合計が版面を超える場合は、表の枠の中で横スクロールにする。
- 背景（文節での折り返しと最小幅）: 文節での折り返しだけを指定すると、「カード右上コーナーオーナメント」のような長い複合語が 1 つの文節として列の最小幅になり、7 列の表が版面からはみ出した。短いラベルの列だけを 1 行に保ち、それ以外は文節を優先しつつ必要なら文節の中でも折り返す。また、下限がないと `Split` 表示の狭い版面で、1 行に保つ列が幅を取った分だけ他の列が 1 文字幅まで縮み、縦書きのように潰れた（校正の赤字）。読めない幅に潰すより、表の枠の中で横スクロールするほうが判読性（`NFR-005` と同じ考え方）を保てる。

## DTP-VTPL-120 印刷・PDF の配布資料

用途: ブラウザの印刷（`Ctrl+P` / `⌘P`、またはファイルメニューの「印刷 / PDF として保存…」）で、Visualモードの誌面をそのまま配布資料にする（`RGH-119`、`FR-036`）。

```text
 1 ページ目        2 ページ目        3 ページ目
┌───────────┐  ┌───────────┐  ┌───────────┐   ← A4 横・余白 10mm
│  表紙      │  │ STAGE 01  │  │ STAGE 02  │   ← 1 章 1 ページ（改ページは章の前）
│  題名・目次 │  │ カード     │  │ 図        │
└───────────┘  └───────────┘  └───────────┘
```

- **版面**: Visualモードは A4 横・余白 10mm（名前付きページ `lucivo-visual`）。表紙と各章（スラブ）の前で改ページし、1 章を 1 ページに置く。1 ページに収まらない章は、カード・手順の項目・図・表の行の途中では切らずに次のページへ送る。
- **高速モード**: A4 縦・余白 14mm で、仕様書として上から流す。見出しの直後では改ページせず、図・表・コードの途中ではできるだけ切らない。
- **刷らないもの**: ヘッダー、エディタ、状態の表示、トースト、スラブの操作ボタン（コピー・PNG）、コードのコピーボタン、ステージ発表の操作部、光の演出の層（Canvas）、スポットライトの減光。紙は動かないため、動き（アニメーション・遷移）もすべて止めた最終の状態で刷る。
- **配色**: 画面と同じ配色で刷る（背景色・グラデーションも省かない。`print-color-adjust: exact`）。Dark の外観なら Dark のまま刷る（`RGH-911` はストック）。スラブの大きな影は紙では灰色のにじみに見えるため消し、代わりに 1px の枠（`--vs-card-border`）でスラブの輪郭を保つ。
- **幅**: 印刷の版面に合わせて、スラブ・図・表を版面の幅に収める（図は `Fit` と同じく版面の幅まで縮める）。
- 背景: 展示会・講演では、投影した誌面と同じものを配布資料として求められることが多い。スラブの画像化（`FR-026`）は 1 章ずつの操作のため、文書全体を 1 回で書き出せる手段として、追加のライブラリを使わずにブラウザの印刷（PDF として保存を含む）を使う（`NFR-008`）。
