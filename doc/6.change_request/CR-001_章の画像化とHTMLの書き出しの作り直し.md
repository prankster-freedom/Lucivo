# CR-001 章の画像化と HTML の書き出しの作り直し

| 項目     | 内容                                                                      |
| :------- | :------------------------------------------------------------------------ |
| 分類     | 不具合                                                                    |
| 状態     | 登録                                                                      |
| 優先度   | 中                                                                        |
| 起票の元 | 0.2.0 のリリース前の点検（Claude のコードの点検と、利用者の確認）         |
| 戻る工程 | swe1（書き出すものと、書き出した後にどこまで動けばよいかを決める）        |
| 対応     | 0.2.0 では操作部を外した（`DD-VTPL-124`、`DD-OFF-005`）。作り直しは未着手 |

## 1. 要求の内容

- **章の画像化（`FR-026`）**: 「コピー」「PNG保存」で出力される PNG が、題名とリード 1 行だけの白いカードになり、画面の誌面とまったく違う。誌面と同じ見た目の画像にしたい。
- **HTML の書き出し（`FR-005`）**: ヘッダーの `HTML` で書き出したファイルをダウンロードフォルダで開くと、スタイルのない画面になる。ロゴは代わりの文字、アイコンは原寸の大きな絵になり、ヘッダー・エディタ・テスト用のボタンまで並ぶ。持ち出した先でも誌面として読めるファイルにしたい。

## 2. 分析

### 2.1 現在の仕様との関係

どちらも要求（`FR-026`・`FR-005` の「スタンドアロンで閲覧可能な自己完結型 HTML ファイル」）を満たしていない不具合。0.2.0 では、動かない機能を出さないよう、操作部だけを外した。

### 2.2 原因

- **章の画像化**: `renderSlabToBlob()` は、章の HTML の複製を SVG の `foreignObject` に入れて画像にするが、`style.css` などのスタイルシートを含めていない。さらに、描画に失敗するか 250ms を超えると、題名とリードを `fillText` で描くだけの簡易な絵に黙って切り替わる。
- **HTML の書き出し**: 表示中のアプリの画面（`document.documentElement.outerHTML`）をそのまま保存し、同梱ライブラリの参照だけを CDN の URL に置き換えている（`EXPORT_URLS`）。アプリ自身の CSS・JS・ロゴは相対パスのまま残り、持ち出した先で読めない。CSS と JS が読める場所に置いても、`app.js` が起動し直して書き出した誌面を消す（エディタの中身は `outerHTML` に含まれない）。
- **共通の制約**: `file://` で開いたアプリは、自分の CSS の中身を読み出せない（`cssRules` は SecurityError、`fetch` は失敗。Playwright の Chromium で確認）。実行中に CSS を取り込んで埋め込むことができない。
- **テストで見逃した理由**: TC-VTPL-017 は PNG ができたかだけを、TC-OFF-003・TC-MATH-009 は書き出した HTML の文字列だけを確かめ、出力の中身や、書き出したファイルを開いた表示を確かめていなかった（`CR-003`）。

## 3. 影響範囲

| 種別   | ID                 | 影響                                                                                 |
| :----- | :----------------- | :----------------------------------------------------------------------------------- |
| 要求   | `FR-005`, `FR-026` | 書き出すもの（文書の誌面だけか）、書き出した後にどこまで動けばよいか（Fit / 1:1、光の演出、発表）を決め直す |
| 設計   | `DD-OFF-003`, `DD-OFF-005`, `DD-VTPL-120`〜`124` | CSS をデータとして持つファイルを生成して埋め込む設計に変える。0.2.0 の停止（`DD-OFF-005`、`DD-VTPL-124`）を解く |
| テスト | `TC-OFF-003`, `TC-MATH-009`, `TC-VTPL-017`, `TC-OFF-004`, `TC-VTPL-024` | 保留中の TC を、出力の中身・書き出したファイルを開いた表示を確かめる TC に置き換える |

## 4. 対応方針

- 採る案（案）: CSS の中身をデータとして持つファイルを `tools/` で生成しておき（`samples-data.js` と同じやり方）、画像にする・書き出すときだけ読み込む。章の画像化と HTML の書き出しの両方の土台にする。HTML の書き出しは、アプリの画面ではなく文書の誌面だけを書き出し、スクリプトを含めない。
- 決めること: 書き出した後にどこまで動けばよいか（Fit / 1:1、光の演出、発表）。書き出した HTML のフォントを CDN から読むか、埋め込むか（埋め込むとファイルが大きくなる）。
- 採らなかった案とその理由: アプリの CSS・JS も CDN の URL に置き換える案。`app.js` が書き出した誌面を消す問題が残る。
- 副作用: 生成した CSS のデータの分だけ、配布物が大きくなる。読み込むのは画像にする・書き出すときだけにし、起動と閲覧の速さ（`NFR-006`）には影響させない。
- 規模の見積もり: 半日〜1 日（要求の決め直し、テスト、デザインの校正を含む）。
