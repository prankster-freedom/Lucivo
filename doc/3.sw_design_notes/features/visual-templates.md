- **背景（DD-VTPL-001）**: 判定はタグ名と `textContent` の長さだけで行う。`getComputedStyle` や要素の大きさの計測を使わないため、Visualモードの描画のたびに判定しても軽く、キャッシュからの再描画で `getComputedStyle` を呼ばない条件（`TC-PERF-002`）を保つ。
- **背景（DD-VTPL-002）**: 組み替えは、`buildVisualStageHtml()` がスラブごとに作る DOM（`wrapper`）の上で行う。この DOM は DOMPurify でサニタイズした後の HTML から作っているため、組み替えで付ける `class`・`style`（CSS 変数）がサニタイズで消えることはない。
- **背景（DD-VTPL-011）**: 列の数を CSS の自動段数（`auto-fit`）で決めると、版面の幅によって 3 個が 2 列＋1 枚になるなど、最後の行に端数が出た（`RGH-902`）。項目の数から列の数を決めることで、端数の行を作らない。
- **背景（DD-VTPL-019）**: 子を移す（`append(...childNodes)`）ため、用語の中のインラインコード・強調も保たれ、文字の並びは高速モードと同じになる（`TC-VTPL-003` の文字一致を保つ）。行ごとの `div` は、2 段組みのグリッドで用語と説明の対を崩さないために置く（HTML では `dl` の子に `div` で `dt`・`dd` の組を包める）。要点カード型の判定より先に調べるのは、2〜6 個のダッシュ区切りの箇条書きを要点カード型にしないため。
- **背景（DD-VTPL-014, 015）**: 装飾要素（`aria-hidden="true"` の空 `span`）はテキストノードを持たず、`strong`・`em`・`code`・`a`・`del` でもないため、高速モードとの内容一致検証（`TC-VTPL-003`）に影響しない。スポットライトの切り替えは `#visual-stage-container` へのイベント委譲で行うため、再描画のたびに個別要素へリスナーを貼り直す必要がなく、`renderApp()` も呼ばないためミリ秒単位で応答する。

- **背景（DD-VTPL-024）**: Chromium で `file://` から開くと（`NFR-001`）`mask-image` の外部ローカルファイル参照が CORS エラーになるため、`assets/motifs/*.svg` と同一のベクター定義を `data:image/svg+xml` として `--motif-*` に保持する。これにより `file://` 起動と単一 HTML エクスポート（`FR-007`）の両方で欠落なく描画できる。また、ステートメント型の引用符（`.vs-quote::before`）は `content: "“"` を保ったまま `color: transparent` とし、`mask-image` と `background: var(--vs-c1)` で彫刻引用モニュメント素材を描画することで、既存の `::before` 存在確認（`TC-VTPL-006`）との互換性を保ちながらベクター素材の造形を実現する。
- **背景（DD-VTPL-031）**: Dark のスラブの背景（`#1E293B`）に対し、`--border-strong`（`#334155`）と `--text-muted`（`#64748B`）は明るさの差が小さく、接続線と出典が沈んだため、雛形の中だけ明るい色を使う。
