# Visualモードの記述パターン別の雛形と動的ステージ演出（visual-templates）

対応する要求: `FR-016`, `FR-017`（[1.SRS/features/visual-templates.md](../../1.SRS/features/visual-templates.md)）／アーキテクチャ: [2.ARCHITECTURE.md](../../2.ARCHITECTURE.md) 4.10／デザイン仕様: [0.DTP/features/visual-templates.md](../../0.DTP/features/visual-templates.md)（`DTP-VTPL-001`〜`090`）

## 1. 判定・組み替え・インタラクション（js/app.js）

| :---------- | :------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------- |
| DD-VTPL-001 | 雛形の判定                 | `detectSlabTemplate(els, slotCount)` は、スラブの本文要素（`buildVisualStageHtml()` の `proseEls`）と図のスロットの数から、`'lead'` / `'points'` / `'steps'` / `'quote'` / `'standard'` のいずれかを返す。判定の順序と条件は `DTP-VTPL-001` の表のとおりで、上限の数値は `TEMPLATE_LIMITS` に置く                                                            | `FR-016`, `DTP-VTPL-001` |

| DD-VTPL-014 | ベクター装飾素材の要素付与 | ヒーロー（`.exhibition-hero`）の先頭行に `<span class="exhibition-hero-emblem" aria-hidden="true"></span>`（`AST-005`）を置く。`applySlabTemplate()` で、要点カードの各 `li` に `<span class="vs-card-ornament" aria-hidden="true"></span>`（`AST-007`）、手順の 2 番目以降の各 `li` に `<span class="vs-step-chevron" aria-hidden="true"></span>`（`AST-008`）を追加する（いずれも文字を持たない装飾要素のため、`textContent` を変えず `TC-VTPL-003` の文字一致を保つ） | `FR-017`, `AST-005`, `AST-007`, `AST-008`, `DTP-VTPL-030`, `040`, `070` |
| DD-VTPL-015 | 動的スポットライトの制御   | `#visual-stage-container` のクリックイベント委譲と `document` の `Escape` キーで、次の 3 種のスポットライトを制御する（リンク `a` のクリックは除外）:<br>1) `.vs-points > li`: クリックした `li` の `.is-spotlight` をトグルし、親 `ul.vs-points` の `.has-spotlight` を同期する。<br>2) `.vs-steps > li`: クリックした `li`（$k$ 番目）が既に `.is-spotlight` なら全解除し、そうでなければ親 `ol.vs-steps` に `.has-spotlight`、$k$ 番目に `.is-spotlight`、1〜$k$ 番目に `.is-reached` を付ける。<br>3) `.exhibition-num-badge`: 親の `.exhibition-slab` の `.is-stage-focused` をトグルし、`.exhibition-wrap` の `.has-stage-focus` を同期する。<br>`Escape` キー押下時は、`#visual-stage-container` 内のすべてのスポットライト・ステージフォーカスのクラスを解除する | `FR-017`, `DTP-VTPL-090` |
| DD-VTPL-016 | ダイアグラム結線のルミナス・ビーム付与 | `decorateVisualSvg()` で Visualモードのフローチャート・状態遷移図（`NODE_DECORATED_TYPES`）およびシーケンス図を装飾した後、`addVisualFlowBeams(svg, diagramType, styleMode)` を呼び出す。フローチャート・状態遷移図の各結線（`.edgePath path.path, path.flowchart-link, path.transition`）の直後に `<path class="lucivo-flow-beam" d="…" aria-hidden="true">` を挿入し、シーケンス図の各メッセージ線（`line.messageLine0, line.messageLine1`）の直後に `<line class="lucivo-flow-beam" x1="…" y1="…" x2="…" y2="…" aria-hidden="true">` を挿入する。元の結線のクラス（`flowchart-link` 等）や属性はコピーせず、`style.--beam-delay` に `(idx % 6) * 0.35s` を設定する | `FR-017`, `DTP-VTPL-095` |

- **背景（DD-VTPL-001）**: 判定はタグ名と `textContent` の長さだけで行う。`getComputedStyle` や要素の大きさの計測を使わないため、Visualモードの描画のたびに判定しても軽く、キャッシュからの再描画で `getComputedStyle` を呼ばない条件（`TC-PERF-002`）を保つ。
- **背景（DD-VTPL-002）**: 組み替えは、`buildVisualStageHtml()` がスラブごとに作る DOM（`wrapper`）の上で行う。この DOM は DOMPurify でサニタイズした後の HTML から作っているため、組み替えで付ける `class`・`style`（CSS 変数）がサニタイズで消えることはない。
- **背景（DD-VTPL-011）**: 列の数を CSS の自動段数（`auto-fit`）で決めると、版面の幅によって 3 個が 2 列＋1 枚になるなど、最後の行に端数が出た（`RGH-902`）。項目の数から列の数を決めることで、端数の行を作らない。
- **背景（DD-VTPL-014, 015, 016）**: 装飾要素（`aria-hidden="true"` の空 `span`）はテキストノードを持たず、`strong`・`em`・`code`・`a`・`del` でもないため、高速モードとの内容一致検証（`TC-VTPL-003`）に影響しない。またダイアグラム結線のルミナス・ビーム（`path.lucivo-flow-beam`）に `flowchart-link` クラスを付けないことで、元の結線を調べる検証（`TC-DIAG-019`, `TC-EDGE-001`〜`004`）と干渉しない。スポットライトの切り替えは `#visual-stage-container` へのイベント委譲で行うため、再描画のたびに個別要素へリスナーを貼り直す必要がなく、`renderApp()` も呼ばないためミリ秒単位で応答する。

- **背景（DD-VTPL-022）**: 画面の幅（`@media`）で切り替えると、`Split` 表示ではプレビューが画面の半分ほどになるのに横並びのままになり、手順の文字が詰まる。版面の幅で判定することで、表示モード（`Split` / `Canvas`）によらず同じ基準で切り替わる。
- **背景（DD-VTPL-024）**: Chromium で `file://` から開くと（`NFR-001`）`mask-image` の外部ローカルファイル参照が CORS エラーになるため、`assets/motifs/*.svg` と同一のベクター定義を `data:image/svg+xml` として `--motif-*` に保持する。これにより `file://` 起動と単一 HTML エクスポート（`FR-007`）の両方で欠落なく描画できる。また、ステートメント型の引用符（`.vs-quote::before`）は `content: "“"` を保ったまま `color: transparent` とし、`mask-image` と `background: var(--vs-c1)` で彫刻引用モニュメント素材を描画することで、既存の `::before` 存在確認（`TC-VTPL-006`）との互換性を保ちながらベクター素材の造形を実現する。
- **背景（DD-VTPL-031）**: Dark のスラブの背景（`#1E293B`）に対し、`--border-strong`（`#334155`）と `--text-muted`（`#64748B`）は明るさの差が小さく、接続線と出典が沈んだため、雛形の中だけ明るい色を使う。
