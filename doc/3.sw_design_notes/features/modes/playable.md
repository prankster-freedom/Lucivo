# 詳細設計: プレイアブル・ダイアグラム（`playable`）

要求: [playable.md](../../../1.SRS/features/modes/playable.md)（`FR-055`、#62）／ソース: `src/ts/modes/playable/`（`index.ts`・`playable-graph.ts`・`style.css`）／目次: [README.md](README.md)

発表モードの登録・host の設計は `doc/2.ARCHITECTURE.md` 4.16（`ARC-MODE-001`〜`010`）による。この設計は、モード固有の部分だけを書く。

| ID          | 項目           | 設計                                                                                                                                                                                                                                                                                                                                                                                                                                               |     |     |
| :---------- | :------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | --- |
| DD-SHOW-120 | 部品と入口     | 登録表（`src/ts/modes/modes.json`）の行（`stage: "web"`）から、`src/ts/modes/playable/index.ts` を `js/modes/playable.js`、`style.css` を `css/modes/playable.css` にビルドする。発表のドロップダウンの項目（`#menu-present-playable`）は、本体が登録表から作り、選んだときに JS と CSS を読み込んで `LucivoModes.get('playable').enter(host)` を呼ぶ（`ARC-MODE-002`・`005`・`006`）。モードは本体のモジュールを `import` せず、`host` だけを使う |     |     |
| DD-SHOW-121 | 図の読み取り   | `playable-graph.ts` の `parsePlayable()` が、Mermaid の原文から、ノード（名前・判定かどうか・注釈）と矢印（元・先・ラベル）を読む。原文は `host.getMermaidSource(図の番号)` で受け取る（本体が描画のときに、図の番号（`data-stage-index`）ごとに覚える）。状態遷移図: `A --> B : ラベル`、`[*] --> A`（始まり）、`A --> [*]`（終わり）、`state "表示名" as A`、`state A <<choice>>`（判定）、`A : 注釈`。フローチャート: ノードの形（`{}`・`{{}}` は判定）、`--> | ラベル | `・`-- ラベル -->` の矢印、`A --> B --> C` の連なり。サブグラフ・スタイル・クリックなどの行は飛ばす |
| DD-SHOW-122 | 始まりと進み方 | 状態遷移図は `[*] -->` の先、フローチャートは入ってくる矢印のない最初のノードから始める。今の場所から出る矢印を、選択肢として順に並べる（ラベルがなければ「先の名前 へ」、終わりへの矢印は「終了」）。終わりへ進むか、出る矢印のないノードに着いたら、最初からやり直せる                                                                                                                                                                           |     |     |
| DD-SHOW-123 | 図の上の表示   | 描画済みの図の枠（`[data-stage-index]`）を、コメントの目印を置いてから一時的に右の枠へ移す。ノードは SVG の id（`…-flowchart-<id>-<番号>`、`…-state-<id>-<番号>`）で探し、入れ子の状態は枠（`g.cluster`）で探す。今の場所に `.is-play-current`、通った場所に `.is-play-visited`、フローチャートの最後に通った矢印（`data-id` が `L_<元>_<先>_`）に `.is-play-edge` を付ける                                                                        |     |     |
| DD-SHOW-124 | 始める・終える | `host.previewRoot()` が返す、今の描画モード（高速モード・Visualモード）のプレビューの図をそのまま使う（表示は切り替えないため、`host.restoreView()` は呼ばない）。終えるときは、図の枠を目印の場所へ戻し、付けた印と `svg.is-playing` を外し、画面を消す。図を切り替えるときも、前の図を元の場所へ戻してから次の図を移す                                                                                                                           |     |     |

- **背景（DD-SHOW-121）**: SVG から図の構造を逆算すると、Mermaid の版で SVG の構造（id の付け方、ラベルの置き方）が変わったときに壊れやすい。原文の基本の書き方を読む方が確実で、読めない行は飛ばしても、動かせる範囲が狭まるだけで壊れない。SVG は、今の場所を光らせるためにだけ使う。
- **背景（DD-SHOW-123）**: 図を複製すると、SVG の中の id が重複し、矢じりやグラデーションの参照が崩れる。ズーミング・マップ（`DD-SHOW-111`）と同じく、描画済みの図をそのまま使い、終えたら戻す。
- 採らなかった案: 状態遷移図の矢印に光を走らせる。Mermaid 12 の状態遷移図の矢印には、元と先のノードが分かる印（`data-id` など）がなく、確実に見つけられない。今の状態を光らせ、通った状態を残すことで、どこから来たかを示す。
