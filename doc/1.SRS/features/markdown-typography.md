# Feature Requirement Specification: markdown-typography

本ドキュメントは、Lucivo における高速モードおよび Visualモードのドキュメントシート外観と、Markdown 各種記法のタイポグラフィ・描画に関する機能要求仕様を定義する。

対応する全体 SRS: [doc/1.SRS.md](../../1.SRS.md)

## 対象機能要求一覧

| ID     | 機能名                             | 概要                                                                   |
| :----- | :--------------------------------- | :--------------------------------------------------------------------- |
| FR-002 | 高速モード（ドキュメントシート）   | 純白またはディープスレートのフラットなドキュメントシートとして描画する |
| FR-003 | Visualモード（ドキュメントシート） | Editorial Cream のウォームクリームシートなど、各スタイルに応じた背景・余白・見出し構造で描画する |
| FR-009 | 同梱サンプルの Markdown 記法の描画 | `notation_sample.md` に記載された各種 Markdown 記法を、高速モード・Visualモードの両方で見分けられるように描画する |
| FR-034 | コールアウト（GitHub アラート記法） | GitHub と同じ `> [!NOTE]` などの引用を、種類ごとのアイコン・ラベル・意味の色を持つ注意書きのパネルとして、高速モードと Visualモードの両方で表示する |
| FR-042 | ローカルの画像の表示               | `file://` の URL、絶対パス、Windows のパスで書いた画像を表示する。読み込めない画像は、読み込めないことと場所を示す |

---

## 機能要求の詳細

### FR-002 / FR-003: ドキュメントシート外観

- **高速モード**:
  - 純白（Light: `#FFFFFF`）またはディープスレート（Dark: `#0F172A`）のフラットなシート。
  - 自然で高密度な仕様書スタイルを維持し、長文の技術文書でも視認性を保つ。
- **Visualモード**:
  - `Editorial Cream` スタイルではウォームクリーム（`#F7F4EB`）の誌面調背景を適用。
  - 各スタイルに応じたセクションカード化、適切な余白（マージン・パディング）、洗練されたフォントファミリ・カーニングを適用する。

### FR-009: 同梱サンプルの Markdown 記法の描画

- Light / Dark のどちらの外観でも、以下の Markdown 記法がそれぞれ明確に見分けられること：
  1. **見出し（h1〜h6）**: 階層ごとにフォントサイズおよび太さが異なり、本文と一目で見分けられる。
  2. **箇条書き・番号付きリスト**: 箇条書きにはビュレット記号、番号付きリストには連番が付与され、ネスト（入れ子）は適切にインデントされる。
  3. **リンク**: 本文と異なるアクセント色で表示され、リンクであることが即座に認識できる。
  4. **インラインコード・コードブロック**: 本文と異なる背景色および等幅フォント（Monospace）でレンダリングされる。
  5. **引用（Blockquote）**: 左ボーダー線とインデントにより、本文と区別して表示される。
  6. **テーブル（表）**: Markdown で指定した列アライメント（左・中央・右寄せ）に従ってセル内容が整列される。Dark 外観でも境界線が視認可能であること。
  7. **水平線（hr）**: 背景と見分けられるソリッドラインで描画される。
  8. **HTML 標準要素**: `<details>` / `<summary>`, `<kbd>`, `<mark>`, `<sub>` / `<sup>` などの標準 HTML タグが、その要素固有の意図された外観で表示される。
- **背景・根拠**: 本アプリではリセット CSS や Tailwind CSS を読み込んでいるため、未定義の標準タグがプレーンテキスト化する問題を防ぐ。`notation_sample.md` には独自の装飾クラスを用いず標準 HTML 要素のみを使用し、純粋な Markdown/HTML 互換性を保証する。

### FR-034: コールアウト（GitHub アラート記法）

- 引用（`>`）の最初の行が `[!NOTE]`・`[!TIP]`・`[!IMPORTANT]`・`[!WARNING]`・`[!CAUTION]` のいずれか（大文字・小文字は問わない）だけの場合、その引用をコールアウト（注意書きのパネル）として表示すること。GitHub のアラート記法と同じ書き方・同じ 5 種類とする。
- コールアウトは、種類を示すアイコン（`AST-113`）・ラベル（`Note`・`Tip`・`Important`・`Warning`・`Caution`）・種類ごとの意味の色の左線と淡い背景を持ち、`[!NOTE]` の文字そのものは表示しないこと（`DTP-VTPL-039`、`DD-MD-021`）。
- 高速モードと Visualモードの両方で表示し、Light / Dark のどちらでもラベルと本文を判読できること。種類は色だけでなく、アイコンの形とラベルの文字でも見分けられること。
- 最初の行が上記の 5 種類以外（`[!FOO]` など）、またはマーカーの後ろに同じ行で文字が続く引用は、通常の引用のまま表示すること（GitHub と同じ）。
- Visualモードでは、コールアウトだけの章をステートメント型（`DTP-VTPL-050`）にしないこと（注意書きは主張の引用ではないため）。
- コールアウトの判定は、描画のたびに引用（`blockquote`）の最初の段落の先頭の文字だけを調べ、要素の大きさを計測しないこと（`NFR-006`）。
- **背景・根拠**: 仕様書・手順書・発表資料には、注意・警告・ヒントが欠かせない。GitHub が 2023 年に導入したアラート記法は、GitHub・GitLab などで同じ意味で表示されるため、書き手は Lucivo 専用の記法を覚える必要がなく、同じ Markdown がリポジトリ上でも注意書きとして読める（独自の記法を足さない方針。`RGH-901`）。高速モードでも軽く判定でき、Visualモードでは展示の誌面にふさわしいパネルになる。
- **採らなかった案**:
  - 色を Visualモードの 4 色（`--vs-c1`〜`c4`）に置き換える案（`RGH-910`）。スタイルによって警告と注記の色の区別が崩れる。
  - Marked の拡張（トークナイザー）で引用の構文解析そのものを変える案。標準の引用として解析した後の DOM を書き換える方が、Marked の版の更新に影響されにくく、判定が引用の先頭の文字だけで済む。

### FR-042: ローカルの画像の表示

- `![代わりの文字](パス)` と `<img src="パス">` の画像を、次のパスで表示すること。高速モードと Visualモードで同じとする。
  - `file://` の URL（例: `file:///C:/work/images/a.png`）
  - `/` で始まる絶対パス（例: `/C:/work/images/a.png`、`/home/user/images/a.png`）
  - Windows のドライブ名で始まるパス（例: `C:\work\images\a.png`、`C:/work/images/a.png`）。`file:///C:/…` の URL に直して読み込む
  - Windows のネットワーク上のパス（例: `\\server\share\a.png`）。`file://server/share/…` の URL に直して読み込む
  - `https://` の URL と `data:` URI（従来どおり）
- `<img>` の `width`・`height`・`style` による大きさの指定を保つこと。
- 読み込めない画像は、代わりの文字（alt）だけを細く出すのではなく、「画像を読み込めません」と画像の場所（直した後の URL）を、画像の位置に枠で示すこと。相対パスのときは、相対パスを使えない理由と、絶対パスで書く案内を添える。
- 安全性（`NFR-003`）: `file:` を許すのは画像の `src` だけとする。リンク（`<a href>`）の `file:` と、画像の `src` の `javascript:` などは、従来どおり無害化で消す。
- **背景・根拠**: 無害化（DOMPurify）の既定の設定は `file:` の URL を許さず、`src` ごと消していた。Windows のパス（`C:\…`）も、`c:` という未知の形式の URL とみなされて消えていた。画像は読み込むだけでスクリプトを動かさず、Lucivo は手元のファイルを見るビューアーのため、ローカルの画像の表示を許す。
- **相対パス**: ファイル選択・ドロップで開いた文書では、ブラウザが Markdown ファイルの場所（フォルダ）をページに渡さないため、相対パス（`images/a.png`）の基準にできず、表示されない。案内には、「フォルダを開く…」で開くか、絶対パスで書くことを示す。「フォルダを開く…」の一覧から開いた文書の相対パスは、`FR-045` で表示する。
- **制約**: Markdown の `![](…)` に書いた `\` の直後が記号（`\_` など）のときは、Markdown のエスケープとして `\` が消える。`/` で区切るか、`<img>` で書く。パスに空白を含むときは、`![](<C:\my docs\a.png>)` のように `< >` で囲むか、`<img>` で書く（Markdown の記法）。
