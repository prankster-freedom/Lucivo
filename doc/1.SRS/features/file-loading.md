# Feature Requirement Specification: file-loading

本ドキュメントは、Lucivo におけるファイル操作およびエディタの保護・初期状態に関する機能要求仕様を定義する。

対応する全体 SRS: [doc/1.SRS.md](../../1.SRS.md)

## 対象機能要求一覧

| ID     | 機能名                         | 概要                                                                                     |
| :----- | :----------------------------- | :--------------------------------------------------------------------------------------- |
| FR-006 | Markdown ファイルの読み込み    | ヘッダーの「開く」メニューの「ファイルを開く…」からローカルファイルをエディタに読み込み、プレビューを更新する |
| FR-007 | 起動時の初期表示               | 起動直後のエディタは空とし、プレビューに案内を表示する                                   |
| FR-013 | Markdown の保存                | 「保存」メニューの「Markdown を保存」でエディタの内容を Markdown ファイルとしてダウンロードする |
| FR-014 | 読み込み直後の読み取り専用     | ファイル読み込み直後はエディタを読み取り専用とし、「閲覧」「編集」の切り替えで切り替える |
| FR-040 | ウィンドウのタイトル           | ファイルを読み込んだら、ウィンドウのタイトルを「ファイル名 - Lucivo」にする              |
| FR-041 | ドラッグ&ドロップでの読み込み  | ウィンドウのどこにファイルやフォルダを落としても開く                                     |
| FR-043 | 開く・保存のメニュー           | ヘッダーの操作を「開く」（ファイル・フォルダ・同梱サンプル）と「保存」（Markdown・印刷 / PDF）の 2 つのメニューに分ける |
| FR-044 | フォルダを開く                 | フォルダを選び、中の Markdown ファイルを左の一覧から開く。一覧は隠せる                   |
| FR-045 | フォルダの文書の相対パスの画像 | フォルダから開いた文書の相対パスの画像を、その文書の場所を基準に表示する                 |
| FR-046 | 文書の中のリンク               | 相対パスの Markdown へのリンクと見出しへのリンク（`#…`）を、Lucivo の中で開く            |
| FR-048 | 文字コードと改行コード         | 文字コード（UTF-8・Shift_JIS・EUC-JP など）を判定して読み、改行コードを LF にそろえる    |
| FR-049 | 更新の確認とヘルプ             | ヘッダーと起動時の案内に「更新を確認」ボタン、ヘッダーに README への「ヘルプ」リンクを置き、押したときだけ最新の版を問い合わせて知らせる |
| FR-050 | 公開 URL パラメータでの読み込み | 起動時の URL パラメータ（`?url=...` / `#url=...`）や公開 URL のドロップから、GitHub `blob` URL 読み替えを含めて Markdown を読み込み、アドレスバーの `?url=` に反映する |
| FR-061 | URL パラメータによる表示状態の指定と反映 | 起動時の URL パラメータで表示状態（モード・外観・スタイル・トーン・ビュー）を復元し、状態切替時にアドレスバーのクエリを更新する |
| FR-062 | ローカルファイルの外部更新の自動反映 | ハンドルで開いたローカルファイルが外部で更新されたとき、未編集なら自動で再読み込みし、編集中は上書きせず再読み込みの案内を出す |
| FR-063 | Web 版の利用状況計測           | Web 版でデザインスタイル・トーン・発表モードを選んだときに配布種別とともに GA4 へ送信する |
| FR-064 | フォルダ内文書の横断全文検索と該当箇所への移動 | 開いているフォルダ内の Markdown 文書を横断して全文検索し、選んだ箇所へ移動・強調表示する |
| FR-068 | Web 版のサンプルの GitHub 参照 | Web 版は同梱サンプルを配信物に含めず、GitHub 上のサンプルを公開 URL として読み込む（スタンドアロン版は同梱を維持） |
| FR-069 | 発表モードの URL 起動          | URL パラメータ `present` で、文書を開いた直後に発表モードを開始する                      |

## 機能要求の詳細

### FR-006: Markdown ファイルの読み込み

- ヘッダーの「開く」メニューの「ファイルを開く…」から、ローカルの `.md` / `.markdown` / `.txt` ファイルをエディタに読み込み、プレビューを即座に更新する。
- 同メニューの下段に同梱サンプル項目として上段に「`Visualモードサンプル (visual-sample.md)`」、中段に「`記法サンプル (notation_sample.md)`」、下段に「`記法サンプル追補版 (notation_sample_extra1.md)`」を配置し、続けて「`ミュージアム・ウォーク サンプル (museum-walk-sample.md)`」「`配色ミュージアム (color-museum-sample.md)`」「`印刷・PDF の確認サンプル (print-sample.md)`」を置いて、ファイル選択ダイアログを経由せずワンクリックで読み込めるようにする。
  - **背景・根拠（印刷・PDF の確認サンプル）**: 印刷の改ページは、本文の行数や表の段数で結果が変わる。行数と段数を変えた章を並べ、各章に「正しく刷れたときの見え方」を書いたサンプルを同梱し、利用者の受け入れテストと E2E テスト（`TC-VTPL-029`）で同じ文書を使う（`FR-036`）。
- エディタの内容を、最後に読み込んだ時点から編集していた場合（起動直後の空の状態から入力した場合を含む）は、置き換える前に確認ダイアログを表示し、ユーザーが誤って未保存の変更を破棄しないよう取り消せるようにする。
- ブラウザ標準のファイル選択（`<input type="file">`）および同梱サンプルの遅延スクリプトフォールバック（`samples/samples-data.js`）により、`index.html` をローカル環境で `file://` で直接開いた場合でも動作を保証する。ただし、同梱サンプルを持つのはスタンドアロン版だけで、Web 版はサンプルを GitHub から読み込む（`FR-068`）。

### FR-007: 起動時の初期表示

- 起動直後のエディタは空の状態とする。
- プレビュー領域には、上部に公式ブランド・フルバナーロゴ（`AST-012`、`DTP-005`。外観の Light / Dark に連動）を掲出し、本プロダクトの差別化ポイント（思考を妨げない「高速モード」、講演・展示素材品質の「Visualモード」、全画面の臨場感ある「ステージ発表」）と、画面上部のセグメントボタンや発表ボタンでいつでも切り替えられること、`?` キーでキーボードショートカット一覧を表示できることの簡潔な説明、およびファイルやフォルダをドラッグ&ドロップして開く案内、ヘッダーの「開く」メニューから開く案内を表示する。
  - 説明の直後（モード紹介カードの上）に、代表的なサンプルを**サムネイル付きのカード**で並べ、ワンクリックで開けるようにする（`DTP-005`）。カードは次の順とする。リンクは表示言語に合わせて日本語版・英語版のサンプルを開く（`FR-067`）。
    1. `Visualモードサンプル`: Visualモード・Light の表示のサムネイル
    2. `記法サンプル` と `記法サンプル追補版`: Split 表示・Light・数式の周辺のサムネイル 1 枚に、リンク 2 件
    3. `配色ミュージアム`: ミュージアム・ウォーク・Dark の表示のサムネイル。リンクを押すと、サンプルを開くと同時にミュージアム・ウォークを開始する（`FR-069`）。**Web 版だけ**に表示する（スタンドアロン版には発表モード `museum-walk` がないため）
  - サムネイルは、日本語版・英語版を別の画像として `public/assets/` に同梱し、表示言語に合わせて切り替える。画像は軽量な圧縮形式（WebP）とし、起動時に外部通信しない（`NFR-008`）。カードは、キーボードで操作でき、狭い幅では 1 列に並ぶこと。
  - **背景・根拠（サムネイルカード）**: 文字だけのボタンでは、Visualモード・Split 表示・ミュージアム・ウォークがどんな見た目かが、開く前に伝わらない。画像を同梱するのは、起動時に外部の画像を読まない（`NFR-008`）ため。
  - Markdown ファイルは、ウィンドウにドラッグ&ドロップするだけで簡単に開けること。
  - 別の文書へのリンクや画像を含む文書は、フォルダごとドラッグ&ドロップすれば、左の一覧から開けて、リンクと画像も表示できること（ファイルだけを開くと、相対パスの画像やリンクは使えないため）。
- サンプル文書は `app.js` 内にハードコードして埋め込まず、同梱の `notation_sample.md` として配布し、ユーザーが必要に応じて FR-006 で開く形態とする。
- **背景・根拠**: ソースコード内にサンプル文書を埋め込むとコードの保守性が低下する。また起動時に `notation_sample.md` を fetch 等で自動読み込みする方式は、`file://` プロトコルで開いた場合にブラウザの CORS/ローカルファイルアクセス制約でエラーとなり、開き方によって挙動が変わるため採用しない。また、初期画面で Visualモードの存在を明示することで、ユーザーが展示品質の魅力に触れずに離脱することを防ぐ。

### FR-024: 公開リポジトリと README への導線

- メインヘッダー左端のロゴと、起動時の案内（FR-007）のロゴを、Lucivo の公開 URL で README を開くリンク（`https://prankster-freedom.github.io/Lucivo/preview/ja/?url=https%3A%2F%2Fgithub.com%2Fprankster-freedom%2FLucivo%2Fblob%2Fmain%2FREADME.md&view=canvas&mode=visual`。英語表示では、`/preview/en/` で `README.en.md` を開く。`FR-065`）にする（#298）。
- 起動時の案内の最後に「最新版はこちら」の一文と、公開リポジトリ（https://github.com/prankster-freedom/Lucivo）へのリンクを表示する。
- リンクは新しいタブで開き、開いたページから Lucivo の画面を操作できないようにする（`rel="noopener noreferrer"`）。
- **背景・根拠**: Lucivo はダウンロードしてローカルで開く配布形態のため、利用者が手元の版が最新かを確かめる手段がない。配布元への導線を起動時の案内に置きつつ、ロゴやヘルプからは README 自体を Lucivo の Visualモードで直接読めるようにする（#298）。インターネットに接続していない環境では、リンク先を開けないだけで、Lucivo の動作には影響しない（NFR-008）。

### FR-049: 更新の確認とヘルプ

- 起動時の案内（FR-007）の「最新版はこちら」の次の行と、ヘッダー右側に更新確認のUIを表示する。ヘッダーでは「最新版確認」ボタン（メニュー・更新アイコン付き）を配置し、クリックで「通信が発生します」メニューボタンを開き、そのクリックで初めて最新の GitHub Release の版を問い合わせる。結果に応じてヘッダーボタンの表示文字を、新しい版があるときは「更新あり」、最新版で更新がないときは「更新なし」に切り替える。またヘッダー右端に Lucivo の公開 URL で README を開く「ヘルプ」リンク（`https://prankster-freedom.github.io/Lucivo/preview/ja/?url=https%3A%2F%2Fgithub.com%2Fprankster-freedom%2FLucivo%2Fblob%2Fmain%2FREADME.md&view=canvas&mode=visual`。英語表示では、`/preview/en/` で `README.en.md` を開く。`FR-065`、#298）を新しいタブ（`rel="noopener noreferrer"`）で置く。ヘッダー右端からの並び順は、ヘルプ、最新版確認、Light / Dark 切替、YAML 切替、アニメーション切替とする。
- 案内の「更新を確認」ボタンには外部通信を伴う注記（`title`）を表示する。
- ボタンを押したときだけ、公開リポジトリの最新の GitHub Release の版を問い合わせ、結果を案内のボタン横とトーストで知らせる。
  - 新しい版があれば、その版番号と、リリースのページへのリンク（新しいタブ）
  - 新しい版がなければ「最新版です（版）」
  - 問い合わせに失敗したとき（インターネットに接続していない、応答がない、応答を読めない）は、確認できなかったことと、リリースの一覧へのリンク
- ボタンを押さない限り、インターネットへは接続しない。
- 確認の結果は、画面を描き直しても（Visualモードへの切り替えなど）、ページを開き直すまで表示を保つ。
- **背景・根拠**: FR-024 のリンクだけでは、利用者は配布元を開いて版を見比べないと、手元の版が古いか分からない。起動時に自動で問い合わせると、オフラインで使えること（NFR-008）と、利用者の知らないうちに外部へ接続しないことを損なうため、利用者が押したときだけ接続する。文書を読み込んだ後でもヘッダーから版確認・README 参照ができるよう常設導線を設ける。
- **背景・根拠（問い合わせ先）**: GitHub の REST API（`https://api.github.com/repos/prankster-freedom/Lucivo/releases/latest`）を使う。認証が要らず、`file://` で開いたページからも読める（CORS を許している）。認証なしの API は IP アドレスごとに 1 時間に 60 回までの制限があるが、押したときだけの問い合わせでは足りる。
- **背景・根拠（版の出どころ）**: 表示する版は、`package.json` の `version` をビルドのときに埋め込む。版を書く場所を増やさず、リリースのときに `package.json` と README の 2 か所をそろえれば足りるようにするため（AGENTS.repo.md 4 章）。

### FR-013: Markdown の保存

- ヘッダーの「保存」メニューの「Markdown を保存（ファイル名）」を押すと、エディタの内容（YAML フロントマターを含む）を UTF-8 の Markdown ファイルとしてダウンロードする（改行は LF。元の文字コードと改行コードは保たない。`FR-048`）。
- ファイル名は、読み込んだファイルの名前を維持する（読み込んでいない場合は `untitled.md` とする）。
- ダウンロード完了後は、その保存時点の内容を「最後に読み込んだ内容」とみなし、別のファイルを読み込む際の破棄確認ダイアログ（FR-006）を表示しない。
- **背景・根拠**: 元ファイルへのローカル上書き API（File System Access API）は対応ブラウザが限定され、`file://` 環境での互換性に課題があるため、普遍的に動作するブラウザダウンロード方式を採用する。

### FR-014: 読み込み直後の読み取り専用

- ファイルを読み込んだ直後は、エディタを読み取り専用状態にする。エディタのヘッダーに「`閲覧` | `編集`」の 2 つ並びの切り替えを表示し、今の状態のほう（読み込み直後は `閲覧`）を選択中として示す（`DTP-006`）。
- `編集` を押すと編集可能状態に、`閲覧` を押すと再び読み取り専用状態に切り替わる。切り替えは、ファイルを読み込んだ後は表示したままにする。別のファイルを再度読み込んだ場合は、再び読み取り専用に戻る。
- 起動直後（ファイルを読み込んでいない状態）は、直ちに記述できるよう初期状態で編集可能とし、切り替えは表示しない。
- 読み取り専用の間も、保存（FR-013）、表示モード・スタイルの切替、図の操作・エクスポートは妨げない。
- **背景・根拠**: 本製品の位置づけは Markdown ビューアーであり、閲覧中のタイピングミスによる意図しない文書書き換えを防止するため。
- **背景・根拠（切り替えの形）**: 以前は「読み取り専用」のバッジとアクセント色の「編集」ボタンを並べていたが、ボタンの色が選択中の印に見え、読み取り専用なのに編集中に見えた。高速モード / Visualモードと同じ形の切り替えにして、今の状態を示す。読み取り専用に戻せないと、一度編集を始めた後の閲覧で誤入力を防げないため、`閲覧` で戻せるようにした。

### FR-040: ウィンドウのタイトル

- ファイルを読み込んだら（ファイル選択、同梱サンプル、ドラッグ&ドロップ（`FR-041`））、ウィンドウのタイトルを「`ファイル名 - Lucivo`」（例: `README.md - Lucivo`）にすること。
- ファイルを読み込んでいない起動直後は、製品名のタイトル（`Lucivo Markdown Presenter — Exhibition-Grade Markdown Viewer —`）のままとする。
- **背景・根拠**: ブラウザの印刷で「PDF として保存」を選ぶと、ウィンドウのタイトルが既定のファイル名になる。タイトルが製品名のままだと、印刷・PDF の配布資料（`FR-036`）を作るたびに、ファイル名を打ち直す必要があった。あわせて、複数のタブやウィンドウで開いたとき、どのファイルかを見分けられる。
- **背景・根拠（形）**: ファイル名を先に置くのは、タブの幅が狭いときに、見分けるのに要るファイル名が先に見えるため。拡張子を残すのは、保存（`FR-013`）のファイル名と同じ名前で見せるため（PDF の既定のファイル名からは、ブラウザが拡張子の扱いを決める）。

### FR-041: ドラッグ&ドロップでの読み込み

- Markdown ファイル（`.md` / `.markdown` / `.txt`。ファイル選択と同じ）およびフォルダを、ウィンドウのどこに落としても開くこと。
  - ファイルを落とした場合の動作（未保存の編集の確認、読み取り専用、タイトル（`FR-040`））は、ファイル選択（`FR-006`）と同じとする。
  - フォルダを落とした場合の動作は、フォルダを開く機能（`FR-044`）と同じく、中の Markdown ファイルを左の一覧に並べ、前回のフォルダとして記憶する。
  - ファイルとフォルダを一緒に落としたときは、フォルダを優先して開く（関連ファイルを含む可能性が高いため）。
- ファイル、フォルダ、または公開 URL をウィンドウの上へドラッグしている間だけ、画面全体に受け付けの表示（「URL・ファイル・フォルダをドロップして開く」と開ける拡張子・フォルダ・公開 URL）を重ねること。ウィンドウの外へ出たら、または落としたら消す（`DTP-007`）。
- 開けないファイル（フォルダでないもの）を落としたときは読み込まず、開ける拡張子をトーストで知らせること。複数のファイルを落としたときは、開けるファイルのうち 1 つ目だけを開く。
- ファイルやフォルダでないもの（選択した文字など）のドラッグでは、受け付けの表示を出さず、エディタの中での文字のドラッグを妨げないこと。
- ドロップしたファイルやフォルダを、ブラウザがそのまま開いて Lucivo の画面から移らないようにすること。
- **背景・根拠**: エクスプローラーなどで見つけたファイルやフォルダを開くのに、「開く」メニューからダイアログを開き、同じ場所を探し直す必要があった。
- **背景・根拠（受け付ける場所）**: ウィンドウ全体で受け付ける。専用の受け付けの場所を常に出すと、画面を使い、Visualモードの誌面の品質を損なう。起動時の案内の画面だけで受け付けると、ファイルを開いた後に別のファイルへ切り替えられない。受け付けの表示はドラッグ中だけ出し、普段の画面を変えない。
- **未対応**: 複数のファイルを同時に個別のタブとして開くことには対応しない。

### FR-043: 開く・保存のメニュー

- ヘッダーのロゴの右に「開く」と「保存」のボタンを並べ、どちらも押すとメニューを開くこと。
  - 「開く」: 「ファイルを開く…」（`FR-006`）、「フォルダを開く…」（`FR-044`）、前回のフォルダがあれば「前回のフォルダ「名前」を開く」、区切りの後に同梱サンプル 5 件（`FR-006`、`FR-067`）
  - 「保存」: 「Markdown を保存（ファイル名）」（`FR-013`）、「印刷 / PDF として保存…」（`FR-036`）
- 片方のメニューを開くと、もう片方は閉じること。メニューの外を押すか Esc キーで閉じること。
- 保存のキーボードショートカット（Ctrl+S）は設けない。印刷はブラウザの Ctrl+P でも従来どおり開ける。
- **背景・根拠**: フォルダを開く機能を足すにあたり、読み込みの操作（ファイル・フォルダ・サンプル）と、書き出しの操作（Markdown・印刷 / PDF）を分けた。以前は「ファイル」メニューに印刷が、独立した「保存」ボタンに Markdown の保存があり、書き出しの操作が 2 か所に分かれていた。
- **背景・根拠（文言）**: ボタンは「フォルダ / ファイルを開く」ではなく「開く」とした。ヘッダーの幅を取らず、隣の「保存」と対になって見えるため。何を開くかはメニューの項目で示す。
- **採らなかった案**: 「保存」の本体を押すとすぐ Markdown を保存し、右の ▾ で印刷を選ぶ分割ボタン。Markdown の保存は 1 クリックのままになるが、「開く」と形がそろわず、▾ の当たる範囲が小さい。メニューにすると Markdown の保存は 1 クリック増えるが、ショートカットは足さない（利用者の判断）。

### FR-044: フォルダを開く

- 「開く」→「フォルダを開く…」でフォルダを選ぶと、フォルダの中（サブフォルダを含む）の Markdown ファイル（`.md` / `.markdown` / `.txt`）を、エディタの左の一覧に並べること。
  - 一覧は、フォルダの直下のファイルを先に、その後はサブフォルダのパスの順に並べ、サブフォルダごとにパスの見出しを付ける。同じフォルダの中は名前の順（数字は数の大きさの順。`2_…` は `10_…` より前）とする。
  - 隠しフォルダ（`.` で始まる）と `node_modules` は、たどらない。大きなフォルダでも固まらないよう、一覧に載せるのは 2,000 件まで、たどる深さは 12 階層までとし、超えたときはその旨を知らせる。
- 一覧のファイルを押すと、そのファイルを開くこと。開いた後の動作（未保存の編集の確認、読み取り専用、タイトル）は、ファイル選択（`FR-006`、`FR-040`）と同じとする。開いているファイルを一覧で示す（`DTP-008`）。
- 一覧の見出しに、フォルダの名前、「フォルダを閉じる」、「一覧を隠す」のボタンを置くこと。隠すと細い帯だけを残し、帯を押すと一覧を戻す。隠したかどうかは、次に開いたときも保つ。フォルダを閉じると、一覧も帯も消す。
- 狭い画面（幅 1024px 未満）では、一覧をエディタとプレビューの上に重ねて出し、ファイルを選んだら隠すこと。
- Chrome / Edge（File System Access API があるブラウザ）では、選んだフォルダを覚え、次回は「開く」メニューの「前回のフォルダ「名前」を開く」から開けること（読む許可はブラウザが確かめる）。そのほかのブラウザでは、ブラウザ標準のフォルダの選択（`<input webkitdirectory>`）を使い、毎回フォルダを選ぶ。File System Access API が使えなかったとき（`file://` で拒まれたなど）も、標準のフォルダの選択に切り替える。
- ステージ発表と印刷には、一覧を出さないこと。
- **背景・根拠**: ファイル選択で開いた文書は、ブラウザが Markdown ファイルの場所をページに渡さないため、相対パスの画像を表示できなかった（#27）。フォルダを選んでもらえば、フォルダの中のファイルを読める。あわせて、講演の資料のように、同じフォルダの章ごとのファイルを行き来しながら見せる使い方に合う。
- **背景・根拠（一覧の形）**: フォルダを選んだ後に、続けてファイル選択のダイアログを出す案は、ブラウザがダイアログを利用者のクリックの直後にしか出せないため、2 つ目が出ない可能性が高い。画面の中の一覧なら、操作が 1 回で済み、別のファイルへの切り替えも一覧から選ぶだけになる。一覧は左側に置き、隠せるようにした（利用者の判断）。
- **実機での確認**: `file://` で開いた Lucivo からフォルダを開き、一覧・相対パスの画像・文書の中のリンクが動くことを、利用者が実機で確かめた（`TC-FILE-026`）。File System Access API が使えない環境でも、標準のフォルダの選択に切り替わる。
- **未対応**: 一覧の中の検索以外のフォルダ内ファイル監視、フォルダの中の変更の自動の反映（ファイルを足したら、フォルダを開き直す）。（注: フォルダのドラッグ&ドロップによる読み込みは `FR-041` で対応済み）

### FR-045: フォルダの文書の相対パスの画像

- フォルダの一覧から開いた文書では、相対パス（`images/a.png`、`./a.png`、`../images/a.png`）の画像を、その文書の場所を基準にフォルダの中から探して表示すること。高速モードと Visualモードで同じとする。
- パスの中の空白や日本語（Markdown では `%20` などに変わる）を、元の文字に戻して探すこと。
- フォルダの中に見つからない画像は「画像を読み込めません」と「フォルダの中に見つかりません」を、フォルダの外を指す画像（`../` が多すぎる）は「開いたフォルダの外の画像は表示できません」を示すこと（`FR-042`）。
- 文書を描き直すたびに画像を読み直さず、ちらつかせないこと。フォルダを閉じる・別のフォルダを開くときは、読み込んだ画像を捨てる。
- **背景・根拠**: #27（相対パスの画像が表示されない）の原因 A への対応。ファイル選択で開いた文書の相対パスは、引き続き表示できない（`FR-042`）。

### FR-046: 文書の中のリンク

- フォルダの一覧から開いた文書の中の、相対パスの Markdown へのリンク（`[概要](sub/overview.md)`、`../README.md` など。拡張子は `.md` / `.markdown` / `.txt`）を押すと、そのファイルを Lucivo の中で開くこと（`FR-044` と同じ動作。一覧に載らないファイルも、フォルダの中にあれば開く）。
- リンクに見出しへのアンカー（`overview.md#詳細`）があれば、開いた後にその見出しへ送ること。同じ文書の中の見出しへのリンク（`#詳細`）も、その見出しへ送る。アンカーは、GitHub と同じく見出しの文字から作る（小文字にし、記号を除き、空白を `-` にする）。Visualモードでは、見出しを含む章へ送る。
- 次のときは、画面を移さずにトーストで知らせること。
  - フォルダを開いていない（ファイル選択などで開いた文書）: 「フォルダを開く…」で開いた文書で使えること
  - フォルダの中に見つからない: 見つからないこと（パスを示す）
  - フォルダの外を指す: 開けないこと
  - アンカーの見出しが見つからない: 見つからないこと
- `https://` などのリンク、Markdown 以外の相対パスへのリンクは、従来どおりブラウザの動作に任せる。
- 同梱サンプルとして開いた文書（`FR-006` のメニューから開いたもの）は、相対パスの画像とリンクを、同梱の `samples` フォルダを基準に解決すること。画像は `samples/` からのパスで表示し、リンク先が同梱サンプルなら同梱サンプルとして開く（見出しへのアンカーも同じ）。同梱サンプルにないファイルは、画面を移さずに知らせる。
- **背景・根拠**: 相対パスの Markdown へのリンクを押すと、ブラウザが Lucivo の画面から Markdown ファイルそのもの（`index.html` のフォルダを基準にしたパス）へ移り、文書が開けなかった。見出しへのリンクも、見出しに id がないため効かなかった。同じフォルダの資料を行き来する使い方（`FR-044`）では、文書の中のリンクで移れることが欠かせない。
- **背景・根拠（同梱サンプル）**: 発展サンプル（`notation_sample_extra1.md`）に、画像と別の文書へのリンクの例を載せた（11 章）。同梱サンプルは「開く」メニューからワンクリックで開くのが主な使い方で、フォルダを開かなくても例がそのまま動くようにする。同梱サンプルは `index.html` から見た場所（`samples/`）が決まっているため、`file://` でも相対パスで読める。
- **背景・根拠（見出しに id を付けない理由）**: 見出しの id は、利用者の文書の中の HTML の id と重なるおそれがあり、図の id の一意化（`DD-DIAG-010`）とも関わる。押したときに見出しの文字から探せば、id を付けずに済む。

### FR-048: 文字コードと改行コード

- ファイルを開くとき（ファイル選択、ドラッグ&ドロップ、フォルダの一覧と文書の中のリンク）は、文字コードを判定してから読むこと。次の文字コードを読めること。
  - UTF-8（BOM あり・なし）、UTF-16（BOM のあるもの。LE・BE）
  - Shift_JIS（Windows の拡張文字を含む CP932）、EUC-JP、ISO-2022-JP
- 改行コード（CRLF・CR・LF・混在）は、読み込むときに LF にそろえること。
- UTF-8 以外で読んだときは、何の文字コードとして読んだかと、保存すると UTF-8 になることを、トーストで知らせること。
- 保存（`FR-013`）は、元の文字コードによらず UTF-8（BOM なし）・改行は LF とする。元が UTF-8 以外のときは、保存したときにも UTF-8 で保存したことを知らせる。
- 判定はブラウザの標準の機能（`TextDecoder`）で行い、ライブラリを足さないこと（`NFR-001`, `NFR-008`）。
- **背景・根拠**: 以前は UTF-8 と決め打ちで読んでいたため、Windows で作られた Shift_JIS の文書が文字化けした。あわせて、改行が CRLF の文書は、エディタ（`textarea`）が改行を LF に変えるため、最後に読み込んだ内容と食い違い、編集していないのに別のファイルを開くときに破棄の確認が出ていた。読み込みの最初で文字コードと改行コードをそろえると、どちらも直る。
- **背景・根拠（保存を UTF-8 にする理由）**: ブラウザの標準の機能は UTF-8 でしか書き出せない（`TextEncoder`）。Shift_JIS で書き出すには変換表を持つライブラリが要り、配布物が大きくなる。保存は書き出したファイルを別に作るだけで元のファイルを上書きしない（`FR-013`）ため、文字コードが変わることを知らせれば足りると判断した。
- **未対応**: BOM のない UTF-16、上記以外の文字コード（中国語・韓国語の文字コードなど）の判定。UTF-8 として正しくない文書は、Shift_JIS と EUC-JP のうち、読めない文字が少ないほうとして読む。

### FR-050: 公開 URL パラメータでの読み込み

- Lucivo 起動時の URL パラメータ（`?url=<URL>` または `#url=<URL>`）が指定されたとき、公開 URL（`http://` / `https://`）がウィンドウにドラッグ&ドロップされたとき、または起動画面（空状態ガイド）の公開 URL 入力欄へ URL を入力して開く操作が行われたとき、その公開 URL から Markdown を取得して自動で読み込み、読み取り専用で表示すること（タイトルは「ファイル名 - Lucivo」、文字コード判定 `FR-048` 適用、#373）。
- 許可するスキームは `http://` および `https://` のみとし、それ以外の不正な URL や取得失敗（HTTP エラー・CORS 制限・タイムアウト等）のときは読み込みを行わずトーストで通知すること。
- ドロップ時にファイルまたはフォルダと URL が同時に含まれる場合は、ローカルのファイル・フォルダ（`FR-041`）を優先すること。
- GitHub の画面 URL（`https://github.com/<ユーザー>/<リポジトリ>/blob/<ブランチ>/<パス>`、および `/raw/`・`?raw=true` 付き）が指定された場合は、Markdown の生ファイル URL（`https://raw.githubusercontent.com/<ユーザー>/<リポジトリ>/<ブランチ>/<パス>`）に読み替えて取得すること（スラッシュを含むブランチ名は機械判別できないため対象外とし、取得に失敗したときは `raw` URL の利用をトーストで案内する）。
- GitHub のフォルダ URL（`https://github.com/<ユーザー>/<リポジトリ>/tree/<ブランチ>/<パス>`）が指定された場合は、スラッシュを含むブランチ名（`feature/…` 等）についても GitHub REST API でブランチ名とパスの境目を解決したうえで、配下の Markdown ファイル一覧（隠しフォルダ・`node_modules` を除き、上限 2,000 件・深さ 12 階層）を取得して左のフォルダ一覧に表示し、直下の `README.md`（なければ先頭のファイル）を自動で開くこと（#370）。一致するブランチがない場合（タグ・コミット ID 等）は最初の 1 区切りを ref として扱う。一覧の選択、相対パスの画像（`FR-045` 相当）、文書内リンク（`FR-046` 相当）が動作し、レート制限や通信失敗時はトーストで知らせること。
- 単一の公開 URL で開いた文書内では、相対パスの画像および相対パスの Markdown リンク（見出しアンカーを含む）を、開いた文書の公開 URL を基準に解決して表示・遷移できること。
- 公開 URL の読み込みに成功したときは、アドレスバーを履歴を増やさずに `?url=<元のURL>` に更新すること（`blob` URL や `tree` URL の場合も元の URL を保持する。失敗時はアドレスバーを書き換えない）。ローカルのファイル・フォルダ・同梱サンプルを開いたときは `?url=` を外すこと。`file://` 環境等でブラウザがアドレスバー書き換えを拒否しても、エラーを出さず読み込みを継続すること。
- パラメータが指定されていない通常起動時は外部通信を行わないこと（`NFR-008`）。URL ドロップによる読み込みも利用者の明示的な操作によるため `NFR-008` に反しない。
- **背景・根拠**: Web 公開版 Lucivo やリンク共有で、ローカルにファイルを保存する手間なく指定の公開 Markdown をワンクリックやドラッグ&ドロップで閲覧・ブックマークできるようにする。一方で通常利用時の完全オフライン性・安全性を損なわないよう、パラメータ指定時・ドロップ時限定かつ `http:` / `https:` 限定の取得とする。

### FR-061: URL パラメータによる表示状態の指定と反映

- 起動時の URL パラメータ（`?` クエリまたは `#` ハッシュ。両方ある場合は `?` 優先）により、以下の表示状態を復元できること。値は画面表示名ではなく不変の識別名とする。
  - `mode`: `fast`（既定・高速モード）/ `visual`（Visualモード）
  - `theme`: `light`（既定）/ `dark`
  - `style`: `shapes`（既定）/ `cards` / `circles` / `editorial`（`style` が指定されて `mode` が省略された場合は `visual` として開く）
  - `tone`: `default`（既定）および製品メニュー登録の 20 トーン（`cotton-candy` / `spring-mist` / `lavender-apricot` / `dried-rose` / `peach-blossom` / `lime-aqua-dune` / `lemon-meringue` / `lilac-snow` / `cobalt-workshop` / `morning-window` / `blush-chambray` / `butterfly-sketch` / `matcha-wagashi` / `terracotta-courtyard` / `nordic-frost` / `sea-glass-shore` / `amber-sunset` / `midnight-library` / `black-blossom` / `cyber-prism`）
  - `view`: `split` / `canvas` / `code`（`editor` も同義として受け付ける。省略時は画面幅に応じた既定値）
  - `layout`: `page`（既定・16:10 ページ単位）/ `single`（ページ区切りなしのシングルページ表示。`layout=single` が指定されて `mode` が省略された場合は `visual` として開く、#308）
  - `present`: 発表モードの識別名（`FR-069`。現在は `museum-walk`）。表示状態ではなく、文書を開いた直後にモードを開始する合図であり、アドレスバーには反映しない
  - `ratio`: 版面の比率（`FR-070`）。`16:10` / `10:16`（省略は自動。画面の向きで決める）
- 不正な値や存在しない識別名が指定されたパラメータは無視し、既定値（または他の有効な状態）で起動を継続すること。
- 利用者が上記の表示状態を切り替えたときは、履歴を増やさずにアドレスバーのクエリ（`?`）を更新すること（`history.replaceState`）。既定値と一致するパラメータは省略して URL を簡潔に保ち（`view` は画面幅によらず `split` を既定値として比較し、`canvas`・`code` は常に URL に残す、#307）、発表モード中の一時的な状態切り替えでは更新しないこと。`file://` 環境等で書き換えが拒否された場合は無視して動作を継続すること。
- **背景・根拠**: ブックマークやリンク共有で「どの文書を、どの見た目で開くか」を 1 つの URL で再現できるようにする。図表の個別倍率（Fit / 1:1）や試験提供中の発表モード（`stage: "web"`）は対象外とする。

### FR-062: ローカルファイルの外部更新の自動反映

- File System Access API が利用できるブラウザ（Chrome / Edge 等）で、「ファイルを開く…」（`showOpenFilePicker`）・ファイルのドラッグ&ドロップ（`getAsFileSystemHandle()`）・「フォルダを開く…」（`showDirectoryPicker`）によりファイルハンドルを取得できたローカルファイルを開いている間、外部でのファイル更新（`lastModified`・サイズの変化）を検知すること（#282）。
- 検知はウィンドウへのフォーカス復帰時および一定間隔（2 秒）の定期確認を併用し、タブ非表示中および発表中（ステージ発表・発表モード）は一時停止すること。
- **未編集時**: スクロール位置を保ったまま自動で読み込み直し（文字コード判定 `FR-048`・自動整形 `FR-053` を適用）、トーストで反映を知らせること。
- **編集中（未保存の変更があるとき）**: エディタの内容を上書きせず、どうするかを尋ねる確認モーダル（`#external-conflict-modal`）および通知バー（「読み込み直す」ボタン付き）で外部更新を知らせること（#297）。確認モーダルでは「編集内容を保存してから外部の更新を読み込む」「編集内容を破棄して外部の更新を読み込む」「外部の更新を取り込まずに編集を続ける」を選べること。「編集を続ける」を選んだ場合は通知バーを保持したまま同じ外部更新では再表示せず、次の外部更新まで編集を維持すること。通知バーの「読み込み直す」または確認モーダルの読み込み操作で最新の内容を読み込み直すこと。
- 設定画面（`#settings-modal`）で自動反映のオン・オフを切り替えられること（既定はオン、`localStorage` に保存）。
- ハンドルを取得できない環境（非対応ブラウザ、`file://` で拒否された場合、`webkitdirectory` フォールバック）では従来どおり `<input type="file">` 相当の読み込みとし、エラーを出さないこと。
- 単一ファイルのハンドルはメモリ上のみ保持する。ローカルの読み取りのみのため、通常起動時に外部通信しない原則（`NFR-008`）に影響しない。

### FR-063: Web 版の利用状況計測

- Web 版（正式版およびプレビュー版）において、利用者がデザインスタイル・カラー トーン・発表モードを選んだときに、Google Tag Manager（`dataLayer`）経由で Google Analytics（GA4）へイベントを送信すること（#321）。
- 計測対象は次の 3 操作とし、起動時の既定値や URL パラメータによる初期適用では送信しないこと。
  - デザインスタイルの選択（`design_style_select`、パラメータ `design_style`）
  - カラー トーンの選択（`tone_select`、パラメータ `tone`、不変の集計用 ID `tone_id`、および外観 `appearance`: `'light'` / `'dark'`）
  - 発表モードの選択（`present_mode_select`、パラメータ `present_mode`、モードを読み込む `loadMode` 時点）
- カラートーンの集計用 ID（`tone_id`）は、`000-default`（スタイル準拠）および `doc/0.DTP/assets/color-tones/` の通し番号・ID に紐づく `NNN-<id>`（3 桁ゼロ埋め番号＋ケバブケース ID、例: `001-morning-window`）とし、今後の追加・廃止において一度割り当てた番号・ID・集計用 ID は永久欠番として再利用しないこと。重複および廃止済み ID の再利用は自動検査で検出すること。
- すべてのイベントに配布種別パラメータ `release_channel`（正式版: `production`、プレビュー版: `preview`）を付与すること。判定は URL パスではなく、ビルド時に埋め込まれるバージョン文字列（`-canary` の有無および `(build id:` の有無）で行うこと。
- ローカル開発ビルド（`(build id:` を含まない版文字列）、スタンドアロン版（`file://` およびビルド時に計測スニペットを除去した `dist/index.html`）、E2E 自動テスト実行時（`navigator.webdriver === true`）には送信しないこと。
- Web 版のルート（`/`、`/preview/`）の、言語別のページ（`/ja/`・`/en/`）へ転送するだけのページ（`FR-065`）には、計測のスニペットを含めないこと。計測は、言語別のページで行う。
- 送信する情報は選択された識別子と `release_channel` のみとし、ファイル名・文書内容・ローカルパス・閲覧 URL 等は送信しないこと。
- `README.md` の「安全性とプライバシー」節に、Web 版でデザインスタイル・カラー トーン・発表モードの利用傾向を把握するために Google Analytics を利用している旨を簡潔に記載すること（スタンドアロン版には含まないことも明記する。同意バナー等は設けない）。
- **背景・根拠**: Web 版で先行提供している発表モードや各種スタイル・トーンの利用傾向を把握し、展開・廃止・改善の判断材料にする（`ARC-MODE`）。一方でプライバシーとオフライン原則（`NFR-008`）を守るため、送信項目を最小限に絞り、スタンドアロン版からは計測コードを除外する。

### FR-064: フォルダ内文書の横断全文検索と該当箇所への移動

- フォルダを開いているとき（`FR-044`、`FR-050` の GitHub `tree` フォルダを含む）、左のフォルダペイン（`#folder-pane`）上部に検索入力欄（`#folder-search-input`）とクリアボタン（`#btn-folder-search-clear`）を表示すること（#331）。
- 検索語を入力すると、フォルダ内の Markdown 文書（`.md` / `.markdown` / `.txt`）を大文字・小文字を区別せずに横断検索し、一致した結果をファイルごとのグループと項目一覧（行番号・直近の見出し・一致箇所を `<mark>` で強調した前後の抜粋文）および一致件数ステータス（`<ファイル数> ファイル・<件数> 件一致`）として表示すること。
- 検索結果の項目をクリックすると、該当する文書を開き（未保存の編集がある場合は `FR-006` と同様に確認する）、エディタの対象行・語句を選択してスクロールするとともに、プレビュー（高速モード・Visualモードの両方）で該当見出し／章スラブへスクロールし、一致語句を `<mark class="lucivo-search-hit">` で視覚的に強調表示すること（印刷時は強調の背景色を消す）。
- クリアボタン押下または検索欄での `Escape` キー押下で検索語を空にすると、通常のファイル一覧表示（`#folder-list`）に戻り、プレビュー内の検索強調も解除されること。フォルダを切り替えたり閉じたときも検索状態とキャッシュをクリアすること。
- **背景・根拠**: 複数の仕様書・設計書からなるフォルダを閲覧する際、要求 ID や用語がどの文書のどの章に書かれているかをファイル名だけで探すのは困難だった。ブラウザの `Ctrl+F` は現在開いている 1 文書にしか効かないため、フォルダペイン内で横断検索から該当箇所への移動・強調までを完結させる。

### FR-053: 読み込み時の Markdown の整形

- 利用者が開いた文書（「ファイルを開く…」・ドラッグ&ドロップ・フォルダの一覧・URL パラメータ）を、表示の結果を変えずに整えてから表示すること（#77）。整えるのは次の乱れに限る。
  - 見出しの `#` の後の空白がない・多い（`#見出し` → `# 見出し`）
  - 見出し・コードブロック・リスト・表の前後の空行がない
  - 行末の不要な空白（段落の中で次の行が続くときの、改行の印の空白は 2 つにそろえて残す）
  - 箇条書きの記号（`-` `*` `+`）の不揃い（文書の最初の記号にそろえる）
  - 表の列の幅（パイプ `|` の位置をそろえる。右揃えの列は右に寄せる）
  - 文書の最後の改行
- 整えた文書を読み込んだ状態（編集していない状態）として扱い、保存すると整えた文書を書き出すこと。整えたときは、読み込みの知らせに直した箇所の数を添えること。
- 同梱サンプルを開くメニューの文書は整えないこと。
- 設定の画面で、読み込み時の整形をオン・オフできること（既定はオン。ブラウザに覚える）。設定の画面の「今の文書を整える」で、エディタの文書を整えられること（保存していない編集として扱う）。
- 整形はブラウザの中だけで行い、通信しないこと（`NFR-008`）。整形の部品は、文書を読み込むとき・整えるときだけ読み込み、起動を重くしないこと（`NFR-006`）。
- 整形のエンジンを差し替えられるよう、整形を 1 つの入口（`format(markdown)`）にまとめること。
- **背景・根拠**: 見出しの空白の抜けや前後の空行の抜けは、表示崩れの主な原因になる。読み込み時に裏で整えれば、作者が直さなくても意図どおりに表示される。表の列をそろえると、エディタで読んで直すときに読みやすくなる。
- **採らなかった案**:
  - 文書全体を構文木から組み直す整形（Prettier など）。字下げ・折り返し・作者が意図した空行まで変わり、不要な差分が大量に出る。
  - 文の中身や作者の意図を変えるおそれのある修正（連続した空行の削除、URL を `<>` で囲む、強調の書き方の統一、リストの字下げの修正など）。表示が変わる、または作者の書き方を不要に変える。
  - 行末の空白を markdownlint の規則（MD009）で消す。3 つ以上の空白をすべて消すため、改行（ハードブレーク）がなくなり表示が変わる。
  - 同梱サンプルも整える。サンプルは記法の見本として手で整えてあり（表をパイプなしで書く例など）、書き方そのものを見せる。

### FR-068: Web 版のサンプルの GitHub 参照

- Web 版は、`samples/` と `samples-data.js` を配信物に含めない。起動画面（`FR-007`）のサンプルと、「開く」メニューの同梱サンプル項目（`FR-006`）は、GitHub 上のサンプル（`https://raw.githubusercontent.com/prankster-freedom/Lucivo/<ref>/public/samples/<ファイル名>`）を公開 URL として読み込む。表示言語に合わせて日本語版（`<name>.md`）と英語版（`<name>.en.md`）を切り替える（`FR-067`）。
- 読み込んだ文書は、`FR-050` の公開 URL の文書と同じに扱う（読み取り専用、相対パスの画像・リンクは取得元を基準に解決する）。一方、アドレスバーには、`?url=` に GitHub のサンプルの URL を入れる。
- `<ref>`（参照するブランチ・タグ）は、ビルドのときに決める。テスト用 URL（`/preview/`）は `main`、公開用 URL は最新のリリースのタグ（`lucivo-vX.Y.Z`）とする。ビルドで決まらない手元の開発ビルドは `main` とする。
- 外部通信は、利用者がサンプルを選んだとき（リンクのクリック、`present` 付きの URL を開いたとき）に限る。サンプルを選ばない通常の起動では、通信しない（`NFR-008`）。取得に失敗したときは、`FR-050` と同じくトーストで知らせる。
- スタンドアロン版（ZIP）は、従来どおり `samples/` と `samples-data.js` を同梱し、オフラインで動く（`NFR-001`）。
- **背景・根拠**: Web 版は開くたびに配信物を読むため、日英すべてのサンプルとその画像を含めると、初期の読み込み量が増える。サンプルは選んだときだけ読めばよい。スタンドアロン版は、オフラインで使うことが前提なので、同梱を残す。
- **背景・根拠（`<ref>` をビルドで決める理由）**: 公開用 URL のサンプルを、リリースしたタグのものにそろえると、将来の `main` での変更（新しい機能を使ったサンプルなど）が、まだ公開していない版の画面で崩れて見えることを防げる。**採らなかった案**: 常に `main` を参照する案（単純だが、上のとおり公開版とずれる）。
- **採らなかった案（配信物の作り）**: `public/` を配信物にしたままにして、ビルドの手順で `samples/` を取り除く。`public/` を別のフォルダに分ける案は、Web 版の試験・公開・文書の参照が広く変わるため採らない（`doc/2.ARCHITECTURE.md` 4.14）。

### FR-069: 発表モードの URL 起動

- 起動時の URL パラメータ `present=<発表モードの識別名>` が指定されたとき、文書（`?url=`、または `FR-068` のサンプル）を開き、最初の描画が終わった直後に、そのモードを開始する。モードを開始する経路は、ヘッダーの「発表」メニューから選んだときと同じとする（`FR-056`）。
- 識別名は、登録されている発表モード（現在は `museum-walk` のみ）に限る。未登録の値は無視し、通常の表示で起動する。
- 外観は `theme` に従う。`present=museum-walk` と `theme=dark` を同時に指定したときは、ミュージアム・ウォークを Dark の外観で開始する。`theme` の指定がないときは、モードが前回の外観を覚えている場合はそれに従い、なければモードの既定の外観で開始する。URL で指定した外観は、モードが覚えている外観を上書きしない。
- 起動画面の「配色ミュージアム」カード（`FR-007`）は、`url`（配色ミュージアムのサンプル）・`mode=visual`・`theme=dark`・`present=museum-walk`・`lang` を組み合わせた URL とする。
- 開始できない場合は、通常の表示のまま、理由をトーストで知らせる。
  - モードのファイルの読み込みに失敗したとき: 既存の読み込み失敗の案内（`present.loadFailedToast`）を表示する。
  - 文書の取得に失敗したとき: `FR-050` と同じ案内を表示し、モードは開始しない。
- モードを開始した時点で、`present` をアドレスバーから取り除く。`Esc` で元の表示（`theme` で指定した外観の Visualモード）に戻ったあと、再読み込みや URL の共有をしても、モードを再び開始しない。
- スタンドアロン版には、ミュージアム・ウォークがない（`stage: "web"`）。スタンドアロン版で `present=museum-walk` が指定されたときは、値を無視する（`FR-061` の不正な値の扱い）。
- **背景・根拠**: 利用者が、説明文を読まずにリンク 1 つで、展示としての見た目（ミュージアム・ウォーク・Dark）を体験できるようにする。起動の合図を `present` として分けた理由は、`mode` が高速モード・Visualモードの切り替えを表しており、ここに発表モードの名前を混ぜると、`mode=visual` との意味が衝突し、値の検証が曖昧になるため。**採らなかった案**: `mode=museum-walk`（上記）、`theme=dark` だけで起動する案（Dark で開くだけでミュージアムが始まってしまう）。
- **背景・根拠（`present` をアドレスバーに残さない理由）**: 発表モードは `Esc` で元に戻る。URL に残すと、戻ったあとの再読み込みや URL の共有で、意図せずモードが再び始まる。
