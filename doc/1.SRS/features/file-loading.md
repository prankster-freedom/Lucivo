# Feature Requirement Specification: file-loading

本ドキュメントは、Lucivo におけるファイル操作およびエディタの保護・初期状態に関する機能要求仕様を定義する。

対応する全体 SRS: [doc/1.SRS.md](../../1.SRS.md)

## 対象機能要求一覧

| ID     | 機能名                         | 概要                                                                     |
| :----- | :----------------------------- | :----------------------------------------------------------------------- |
| FR-006 | Markdown ファイルの読み込み    | ヘッダーの「開く」メニューの「ファイルを開く…」からローカルファイルをエディタに読み込み、プレビューを更新する |
| FR-007 | 起動時の初期表示               | 起動直後のエディタは空とし、プレビューに案内を表示する                   |
| FR-013 | Markdown の保存                | 「保存」メニューの「Markdown を保存」でエディタの内容を Markdown ファイルとしてダウンロードする |
| FR-014 | 読み込み直後の読み取り専用     | ファイル読み込み直後はエディタを読み取り専用とし、「閲覧」「編集」の切り替えで切り替える |
| FR-040 | ウィンドウのタイトル           | ファイルを読み込んだら、ウィンドウのタイトルを「ファイル名 - Lucivo」にする |
| FR-041 | ドラッグ&ドロップでの読み込み  | ウィンドウのどこにファイルを落としても開く                               |
| FR-043 | 開く・保存のメニュー           | ヘッダーの操作を「開く」（ファイル・フォルダ・同梱サンプル）と「保存」（Markdown・印刷 / PDF）の 2 つのメニューに分ける |
| FR-044 | フォルダを開く                 | フォルダを選び、中の Markdown ファイルを左の一覧から開く。一覧は隠せる   |
| FR-045 | フォルダの文書の相対パスの画像 | フォルダから開いた文書の相対パスの画像を、その文書の場所を基準に表示する |

## 機能要求の詳細

### FR-006: Markdown ファイルの読み込み

- ヘッダーの「開く」メニューの「ファイルを開く…」から、ローカルの `.md` / `.markdown` / `.txt` ファイルをエディタに読み込み、プレビューを即座に更新する。
- 同メニューの下段に同梱サンプル項目として上段に「`Visualモードサンプル (visual-sample.md)`」、中段に「`記法サンプル (notation_sample.md)`」、下段に「`記法サンプル追補版 (notation_sample_extra1.md)`」を配置し、ファイル選択ダイアログを経由せずワンクリックで読み込めるようにする。
- エディタの内容を、最後に読み込んだ時点から編集していた場合（起動直後の空の状態から入力した場合を含む）は、置き換える前に確認ダイアログを表示し、ユーザーが誤って未保存の変更を破棄しないよう取り消せるようにする。
- ブラウザ標準のファイル選択（`<input type="file">`）および同梱サンプルの遅延スクリプトフォールバック（`samples/samples-data.js`）により、`index.html` をローカル環境で `file://` で直接開いた場合でも動作を保証する。

### FR-007: 起動時の初期表示

- 起動直後のエディタは空の状態とする。
- プレビュー領域には、上部に公式ブランド・フルバナーロゴ（`AST-012`、`DTP-005`。外観の Light / Dark に連動）を掲出し、本プロダクトの差別化ポイント（思考を妨げない「高速モード」、講演・展示素材品質の「Visualモード」、全画面の臨場感ある「ステージ発表」）と、画面上部のセグメントボタンや発表ボタンでいつでも切り替えられること、`?` キーでキーボードショートカット一覧を表示できることの簡潔な説明、および「ファイル」メニューから Markdown を開く案内を表示する。
- サンプル文書は `app.js` 内にハードコードして埋め込まず、同梱の `notation_sample.md` として配布し、ユーザーが必要に応じて FR-006 で開く形態とする。
- **背景・根拠**: ソースコード内にサンプル文書を埋め込むとコードの保守性が低下する。また起動時に `notation_sample.md` を fetch 等で自動読み込みする方式は、`file://` プロトコルで開いた場合にブラウザの CORS/ローカルファイルアクセス制約でエラーとなり、開き方によって挙動が変わるため採用しない。また、初期画面で Visualモードの存在を明示することで、ユーザーが展示品質の魅力に触れずに離脱することを防ぐ。

### FR-024: 公開リポジトリへの導線

- メインヘッダー左端のロゴと、起動時の案内（FR-007）のロゴを、公開リポジトリ（https://github.com/prankster-freedom/Lucivo）へのリンクにする。
- 起動時の案内の最後に「最新版はこちら」の一文と、同じ公開リポジトリへのリンクを表示する。
- リンクは新しいタブで開き、開いたページから Lucivo の画面を操作できないようにする（`rel="noopener noreferrer"`）。
- **背景・根拠**: Lucivo はダウンロードしてローカルで開く配布形態のため、利用者が手元の版が最新かを確かめる手段がない。配布元への導線を、常に見えるロゴと起動時の案内に置く。インターネットに接続していない環境では、リンク先を開けないだけで、Lucivo の動作には影響しない（NFR-008）。

### FR-013: Markdown の保存

- ヘッダーの「保存」メニューの「Markdown を保存（ファイル名）」を押すと、エディタの内容（YAML フロントマターを含む）を UTF-8 の Markdown ファイルとしてダウンロードする。
- ファイル名は、読み込んだファイルの名前を維持する（読み込んでいない場合は `untitled.md` とする）。
- ダウンロード完了後は、その保存時点の内容を「最後に読み込んだ内容」とみなし、別のファイルを読み込む際の破棄確認ダイアログ（FR-006）を表示しない。
- **背景・根拠**: 元ファイルへのローカル上書き API（File System Access API）は対応ブラウザが限定され、`file://` 環境での互換性に課題があるため、普遍的に動作するブラウザダウンロード方式を採用する。

### FR-014: 読み込み直後の読み取り専用

- ファイルを読み込んだ直後は、エディタを読み取り専用状態にする。エディタのヘッダーに「`閲覧` | `編集`」の 2 つ並びの切り替えを表示し、今の状態のほう（読み込み直後は `閲覧`）を選択中として示す（`DTP-006`）。
- `編集` を押すと編集可能状態に、`閲覧` を押すと再び読み取り専用状態に切り替わる。切り替えは、ファイルを読み込んだ後は表示したままにする。別のファイルを再度読み込んだ場合は、再び読み取り専用に戻る。
- 起動直後（ファイルを読み込んでいない状態）は、直ちに記述できるよう初期状態で編集可能とし、切り替えは表示しない。
- 読み取り専用の間も、保存（FR-013）、表示モード・スタイルの切替、図の操作・エクスポートは妨げない。
- **背景・根拠**: 本製品の位置づけは Markdown ビューアーであり、閲覧中のタイピングミスによる意図しない文書書き換えを防止するため。
- **背景・根拠（切り替えの形）**: 以前は「読み取り専用」のバッジとアクセント色の「編集」ボタンを並べていたが、ボタンの色が選択中の印に見え、読み取り専用なのに編集中に見えた。高速モード / Visualモードと同じ形の切り替えにして、今の状態を示す。読み取り専用に戻せないと、一度編集を始めた後の閲覧で誤入力を防げないため、`閲覧` で戻せるようにした。

### FR-040: ウィンドウのタイトル

- ファイルを読み込んだら（ファイル選択、同梱サンプル、ドラッグ&ドロップ（`FR-041`））、ウィンドウのタイトルを「`ファイル名 - Lucivo`」（例: `README.md - Lucivo`）にすること。
- ファイルを読み込んでいない起動直後は、製品名のタイトル（`Lucivo Markdown Presenter — Exhibition-Grade Markdown Viewer —`）のままとする。
- **背景・根拠**: ブラウザの印刷で「PDF として保存」を選ぶと、ウィンドウのタイトルが既定のファイル名になる。タイトルが製品名のままだと、印刷・PDF の配布資料（`FR-036`）を作るたびに、ファイル名を打ち直す必要があった。あわせて、複数のタブやウィンドウで開いたとき、どのファイルかを見分けられる。
- **背景・根拠（形）**: ファイル名を先に置くのは、タブの幅が狭いときに、見分けるのに要るファイル名が先に見えるため。拡張子を残すのは、保存（`FR-013`）のファイル名と同じ名前で見せるため（PDF の既定のファイル名からは、ブラウザが拡張子の扱いを決める）。

### FR-041: ドラッグ&ドロップでの読み込み

- Markdown ファイル（`.md` / `.markdown` / `.txt`。ファイル選択と同じ）を、ウィンドウのどこに落としても開くこと。読み込んだ後の動作（未保存の編集の確認、読み取り専用、タイトル（`FR-040`））は、ファイル選択（`FR-006`）と同じとする。
- ファイルをウィンドウの上へドラッグしている間だけ、画面全体に受け付けの表示（「ドロップして開く」と開ける拡張子）を重ねること。ウィンドウの外へ出たら、または落としたら消す（`DTP-007`）。
- 開けないファイルを落としたときは読み込まず、開ける拡張子をトーストで知らせること。複数のファイルを落としたときは、開けるファイルのうち 1 つ目だけを開く。
- ファイルでないもの（選択した文字など）のドラッグでは、受け付けの表示を出さず、エディタの中での文字のドラッグを妨げないこと。
- ドロップしたファイルを、ブラウザがそのまま開いて Lucivo の画面から移らないようにすること。
- **背景・根拠**: エクスプローラーなどで見つけたファイルを開くのに、「開く」メニューからファイル選択のダイアログを開き、同じファイルを探し直す必要があった。
- **背景・根拠（受け付ける場所）**: ウィンドウ全体で受け付ける。専用の受け付けの場所を常に出すと、画面を使い、Visualモードの誌面の品質を損なう。起動時の案内の画面だけで受け付けると、ファイルを開いた後に別のファイルへ切り替えられない。受け付けの表示はドラッグ中だけ出し、普段の画面を変えない。
- **未対応**: 複数のファイルを同時に開くこと、フォルダを落として開くことには対応しない。

### FR-043: 開く・保存のメニュー

- ヘッダーのロゴの右に「開く」と「保存」のボタンを並べ、どちらも押すとメニューを開くこと。
  - 「開く」: 「ファイルを開く…」（`FR-006`）、「フォルダを開く…」（`FR-044`）、前回のフォルダがあれば「前回のフォルダ「名前」を開く」、区切りの後に同梱サンプル 3 件（`FR-006`）
  - 「保存」: 「Markdown を保存（ファイル名）」（`FR-013`）、「印刷 / PDF として保存…」（`FR-036`）
- 片方のメニューを開くと、もう片方は閉じること。メニューの外を押すか Esc キーで閉じること。
- 保存のキーボードショートカット（Ctrl+S）は設けない。印刷はブラウザの Ctrl+P でも従来どおり開ける。
- **背景・根拠**: フォルダを開く機能を足すにあたり、読み込みの操作（ファイル・フォルダ・サンプル）と、書き出しの操作（Markdown・印刷 / PDF）を分けた。以前は「ファイル」メニューに印刷が、独立した「保存」ボタンに Markdown の保存があり、書き出しの操作が 2 か所に分かれていた。
- **背景・根拠（文言）**: ボタンは「フォルダ / ファイルを開く」ではなく「開く」とした。ヘッダーの幅を取らず、隣の「保存」と対になって見えるため。何を開くかはメニューの項目で示す。
- **採らなかった案**: 「保存」の本体を押すとすぐ Markdown を保存し、右の ▾ で印刷を選ぶ分割ボタン。Markdown の保存は 1 クリックのままになるが、「開く」と形がそろわず、▾ の当たる範囲が小さい。メニューにすると Markdown の保存は 1 クリック増えるが、ショートカットは足さない（利用者の判断）。

### FR-044: フォルダを開く

- 「開く」→「フォルダを開く…」でフォルダを選ぶと、フォルダの中（サブフォルダを含む）の Markdown ファイル（`.md` / `.markdown` / `.txt`）を、エディタの左の一覧に並べること。
  - 一覧は、フォルダの直下のファイルを先に、その後はサブフォルダのパスの順に並べ、サブフォルダごとにパスの見出しを付ける。同じフォルダの中は名前の順（数字は数の大きさの順。`2_…` は `10_…` より前）とする。
  - 隠しフォルダ（`.` で始まる）と `node_modules` は、たどらない。大きなフォルダでも固まらないよう、一覧に載せるのは 2,000 件まで、たどる深さは 12 階層までとし、超えたときはその旨を知らせる。
- 一覧のファイルを押すと、そのファイルを開くこと。開いた後の動作（未保存の編集の確認、読み取り専用、タイトル）は、ファイル選択（`FR-006`、`FR-040`）と同じとする。開いているファイルを一覧で示す（`DTP-008`）。
- 一覧の見出しに、フォルダの名前、「フォルダを閉じる」、「一覧を隠す」のボタンを置くこと。隠すと細い帯だけを残し、帯を押すと一覧を戻す。隠したかどうかは、次に開いたときも保つ。フォルダを閉じると、一覧も帯も消す。
- 狭い画面（幅 1024px 未満）では、一覧をエディタとプレビューの上に重ねて出し、ファイルを選んだら隠すこと。
- Chrome / Edge（File System Access API があるブラウザ）では、選んだフォルダを覚え、次回は「開く」メニューの「前回のフォルダ「名前」を開く」から開けること（読む許可はブラウザが確かめる）。そのほかのブラウザでは、ブラウザ標準のフォルダの選択（`<input webkitdirectory>`）を使い、毎回フォルダを選ぶ。File System Access API が使えなかったとき（`file://` で拒まれたなど）も、標準のフォルダの選択に切り替える。
- ステージ発表と印刷には、一覧を出さないこと。
- **背景・根拠**: ファイル選択で開いた文書は、ブラウザが Markdown ファイルの場所をページに渡さないため、相対パスの画像を表示できなかった（#27）。フォルダを選んでもらえば、フォルダの中のファイルを読める。あわせて、講演の資料のように、同じフォルダの章ごとのファイルを行き来しながら見せる使い方に合う。
- **背景・根拠（一覧の形）**: フォルダを選んだ後に、続けてファイル選択のダイアログを出す案は、ブラウザがダイアログを利用者のクリックの直後にしか出せないため、2 つ目が出ない可能性が高い。画面の中の一覧なら、操作が 1 回で済み、別のファイルへの切り替えも一覧から選ぶだけになる。一覧は左側に置き、隠せるようにした（利用者の判断）。
- **未確認**: `file://` で開いた Lucivo から File System Access API を使えることは、実機の Chrome / Edge で確かめていない（利用者の判断で、確認済みとして進めた）。使えない場合も、標準のフォルダの選択に切り替わる。
- **未対応**: フォルダをドラッグ&ドロップで開くこと、一覧の中の検索、フォルダの中の変更の自動の反映（ファイルを足したら、フォルダを開き直す）。

### FR-045: フォルダの文書の相対パスの画像

- フォルダの一覧から開いた文書では、相対パス（`images/a.png`、`./a.png`、`../images/a.png`）の画像を、その文書の場所を基準にフォルダの中から探して表示すること。高速モードと Visualモードで同じとする。
- パスの中の空白や日本語（Markdown では `%20` などに変わる）を、元の文字に戻して探すこと。
- フォルダの中に見つからない画像は「画像を読み込めません」と「フォルダの中に見つかりません」を、フォルダの外を指す画像（`../` が多すぎる）は「開いたフォルダの外の画像は表示できません」を示すこと（`FR-042`）。
- 文書を描き直すたびに画像を読み直さず、ちらつかせないこと。フォルダを閉じる・別のフォルダを開くときは、読み込んだ画像を捨てる。
- **背景・根拠**: #27（相対パスの画像が表示されない）の原因 A への対応。ファイル選択で開いた文書の相対パスは、引き続き表示できない（`FR-042`）。
