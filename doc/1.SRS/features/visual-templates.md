# Feature Requirement Specification: visual-templates

本ドキュメントは、Lucivo の Visualモードで、章（スラブ）ごとの Markdown の記述パターンに応じて誌面の雛形（レイアウトとベクター装飾素材）を自動で切り替えるとともに、講演・展示でのライブ操作に向けた動的ステージ演出（インタラクティブ・スポットライト）、文書の表紙、誌面の表を提供する機能要求仕様を定義する。

対応する全体 SRS: [doc/1.SRS.md](../../1.SRS.md)／デザイン仕様: [0.DTP/features/visual-templates.md](../../0.DTP/features/visual-templates.md)

## 対象機能要求一覧

| ID     | 機能名                                           | 概要                                                                                                  |
| :----- | :----------------------------------------------- | :---------------------------------------------------------------------------------------------------- |
| FR-016 | Visualモードの記述パターン別の雛形               | Visualモードのスラブの記述パターン（短い段落、箇条書き、番号付きリスト、引用など）を判定し、パターンに合った雛形（リード、要点カード、手順、ステートメントなど）で表示する |
| FR-017 | Visualモードのベクター装飾素材と動的ステージ演出 | Visualモードのヒーロー・各雛形に専用ベクター装飾素材（`AST-005`〜`009`）を適用し、カード・手順・スラブのインタラクティブ・スポットライトを提供する |
| FR-020 | Visualモードの表紙                               | フロントマターと章の構成から、アイブロウ・題名・リード文・目次を持つ表紙を組む                        |
| FR-021 | Visualモードの誌面の表                           | 表を罫線で組み、先頭の列・数値の列・短いラベルの列をそれぞれに合った組み方で表示する                  |
| FR-026 | Visualモードのスラブ画像エクスポート             | Visualモードの各スラブ（章）を高精細PNG画像としてクリップボードへコピーまたは保存できるようにする     |
| FR-027 | Visualモードの KPI メトリクス・ショーケース      | 要点カード型のうち、項目の題が数値・指標を表すカードを大判等幅タイポグラフィの KPI カードに昇格させる |
| FR-029 | Visualモードのタイムライン・ロードマップ修飾     | 要点カード型の全項目の題が日付・四半期・フェーズ表記で揃っているとき、等幅ピルバッジと接続ガイド付きのロードマップ表現にする |
| FR-030 | Visualモードの Before / After 比較ペアカード修飾 | 要点カード型が 2 項目で課題側と解決側の対になっているとき、視覚的コントラストを付けた比較カードにする |
| FR-031 | Visualモードのコード・ショーケース               | Visualモードのコードブロックに、言語ラベル・丸端キャレット装飾（`AST-109`）・ワンクリックコピー付きの暗色コンソール枠を適用する |
| FR-032 | Visualモードの表紙スペックバッジとドットマトリクス透かし | 表紙に著者・日付・章数・図数のスペックバッジ行と背面のドットマトリクス透かし（`AST-110`）を表示する |
| FR-035 | Visualモードの定義リスト型（用語集）             | 箇条書きの全項目が `**用語** — 説明` の形の章を、等幅の用語と説明を 2 段に組んだ用語集の誌面にする    |
| FR-036 | 印刷・PDF の配布資料                             | ブラウザの印刷（PDF として保存を含む）で、Visualモードは表紙と章を 1 ページずつ、高速モードは仕様書として、画面の操作部を除いて刷る |

## 機能要求の詳細

### FR-016: Visualモードの記述パターン別の雛形

- Visualモードで、スラブ（`h2` ごとの章、および最初の `h2` より前の部分）の中身の記述パターンを判定し、次の雛形のいずれか 1 つで表示すること。判定の条件と優先順位、各雛形のデザインは、デザイン仕様（`DTP-VTPL-001`〜`080`）に従う。

  | 雛形             | 記述パターンの概要                                          | デザイン仕様   |
  | :--------------- | :---------------------------------------------------------- | :------------- |
  | 解説＋図版型     | 本文と 1 つの図（`FR-015`）                                 | `DTP-VTPL-060` |
  | リード型         | 短い段落（1〜2 個、合計 160 字以内）だけ                    | `DTP-VTPL-020` |
  | 要点カード型     | （導入の段落＋）入れ子のない短い箇条書き（2〜6 項目）       | `DTP-VTPL-030` |
  | 手順型           | （導入の段落＋）入れ子のない短い番号付きリスト（2〜8 項目） | `DTP-VTPL-040` |
  | ステートメント型 | 短い引用（段落 1〜3 個、合計 240 字以内）だけ               | `DTP-VTPL-050` |
  | 標準型           | 上記のいずれにも当てはまらない                              | `DTP-VTPL-010` |

- 雛形の適用で、本文の内容（文字、リンク、インラインの装飾、数式）を失わないこと。
- 雛形のアクセント色は、選んでいるインフォグラフィックスタイル（`FR-003`）に合わせて切り替えること。Light / Dark のどちらでも、文字・装飾が背景と見分けられること（`NFR-004` に準じる）。
- 高速モードの表示は変えないこと（`NFR-006`）。
- **背景・根拠**: Visualモードは講演資料・展示素材としての品質を目指す（[プロダクトコンセプト](../../1.SRS.md#11-プロダクトコンセプト)）。すべての章を同じ箱に上から流し込むと、章ごとの主役（主張の一文、要点の並び、手順）が見分けにくく、簡易ビューアーで描画した印象になる。誌面の設計で章の内容に合った型を使い分けるように、記述パターンから雛形を選ぶ。
- **背景・根拠（判定の上限）**: 長い段落や項目の多いリストを大きな文字やカードにすると、1 枚のパネルとして読み切れない量になり、品質が下がる。そのため、雛形は短い内容に限り、それ以外は標準型にする。
- **採らなかった案**:
  - 独自の記法（HTML コメントなど）で雛形を指定する案。文書が Lucivo 専用になり、Markdown の可搬性を損なうため（`FR-015` と同じ方針。`RGH-901`）。
  - 表・コード・図だけの章の専用の雛形。崩れない汎用の規則を決めきれない、または既存の装飾と重なるため、ストックとして保留した（`RGH-101`〜`104`）。

### FR-017: Visualモードのベクター装飾素材と動的ステージ演出

- **ベクター装飾素材の適用（`DTP-001`, `DTP-VTPL-030`〜`070`）**:
  - 本番同梱のベクター装飾素材（`assets/motifs/` 配下の `AST-005` ヒーロー・プリズムエンブレム、`AST-006` ステートメント引用モニュメント、`AST-007` 要点カード・コーナーファセット、`AST-008` 手順フロー・方向シェブロン、`AST-009` ルミナス・フロースパーク）を Visualモードの該当要素に表示し、選択中のインフォグラフィックスタイルの配色（`--vs-c1`〜`--vs-c4`）に連動させること。
- **インタラクティブ・スポットライト（`DTP-VTPL-090`）**:
  - **要点カードのスポットライト**: 要点カード（`.vs-points > li`）をクリックすると、そのカードを浮き上がらせて強調（`.is-spotlight`）し、同じリスト内の他のカードを減光すること。もう一度クリックするか `Escape` キーで解除できること。
  - **手順ステップの進行ハイライト**: 手順の項目（`.vs-steps > li`）の $k$ 番目をクリックすると、1〜$k$ 番目を到達済み（`.is-reached`）、$k$ 番目を現在注目（`.is-spotlight`）として強調し、$k+1$ 番目以降を減光すること。もう一度クリックするか `Escape` キーで解除できること。
  - **スラブのステージフォーカス**: スラブ見出しの `STAGE nn` バッジ（`.exhibition-num-badge`）をクリックすると、そのスラブを注目強調（`.is-stage-focused`）し、他のスラブを減光すること。もう一度クリックするか `Escape` キーで解除できること。
- **光の演出**: 手順の接続線と図の結線の上を流れる光は、`FR-018`（[stage-show.md](stage-show.md)）に従う。
- **リアルタイム性の維持（`NFR-006`, `NFR-007`）**:
  - スポットライトの切り替えやホバー応答は即座に反応し、再描画（`renderApp()`）や `getComputedStyle` の呼び出しを発生させないこと。
- **背景・根拠**:
  - 簡易ビューアーの CSS 枠線やシステムフォントの記号だけでは「トップデザイナーが制作した細部の質感」に届かないため、専用設計のベクター素材（`AST-005`〜`009`）を同梱して質感を高める（`RGH-006`）。
  - また、Lucivo（「構文に、光と舞台を」）の Visualモードは紙の印刷物ではなく、イベント・講演・展示会場の画面でリアルタイムに操作・閲覧されるビューアーである。発表者がいま説明しているカード・工程・章をクリック 1 つで聴衆に示すスポットライト（`RGH-007`, `RGH-008`）を備えることで、静的な表示にとどまらない価値を訴求する。
- **採らなかった案**:
  - 方向性を持たず背景全体を常時浮遊・明滅する背景パーティクル（`RGH-903`）。情報の流れと無関係に背景が動き続けると文書の読解を妨げるため採らず、線の上だけを進行方向に沿って伝わる光（`FR-018`）を採用した。

### FR-020: Visualモードの表紙

- Visualモードの文書の先頭に、次の要素からなる表紙を表示すること。デザインはデザイン仕様（`DTP-VTPL-100`）に従う。

  | 要素       | 内容                                          | 表示する条件                                   |
  | :--------- | :-------------------------------------------- | :--------------------------------------------- |
  | アイブロウ | フロントマターの `tags`（先頭の 4 個）        | `tags` がある                                  |
  | 題名       | 文書の `h1`。なければフロントマターの `title`、なければ読み込んだファイル名 | いずれかがある（どれもなければ表紙を出さない） |
  | リード文   | フロントマターの `description`                | `description` がある                           |
  | 目次       | 章（`h2`）の番号（`STAGE nn` と同じ番号）と題 | 章が 3〜15 個                                  |

- 目次の項目を選ぶと、その章の先頭までスクロールすること。
- フロントマターの表示の ON / OFF（`FR-011`）によらず、表紙にはフロントマターの値を使うこと。
- フロントマターの値・章の題は文字として表示し、HTML として解釈しないこと（`NFR-003`）。
- ステージ発表（`FR-019`）の表紙では、目次を出さないこと。
- 高速モードの表示は変えないこと（`NFR-006`）。
- **背景・根拠**: 表紙は文書の最初の 1 枚で、展示・講演で最も長く映る画面である。題名 1 行だけの表紙は簡易ビューアーの印象が強く、何の文書か、どんな章があるかも伝わらない。書き手が文書のために書いたフロントマター（題名・説明・タグ）と章の構成は、表紙を組むのに十分な情報であり、記法を増やさずに使える（`RGH-013`）。
- **背景・根拠（フロントマターの表示の切替との関係）**: `FR-011` の切替は、YAML の原文を本文の前に見せるかどうかの切替である。表紙は YAML の値を誌面の要素として組むもので、原文を見せるものではないため、切替によらず使う。
- **背景・根拠（目次の範囲）**: 章が 2 個以下では地図にならず、16 個以上では目次が表紙の主役（題名）を埋もれさせる（`DTP-VTPL-100`）。
- **採らなかった案**:
  - 著者・日付・章数の行（`RGH-107`）。フロントマターの書き方が文書ごとに違い、確実に読み取れないため保留した。
  - 発表の表紙にも目次を出す案（`RGH-108`）。発表はシーンを順に送るため、目次が道案内にならない。

### FR-021: Visualモードの誌面の表

- Visualモードの表を、次のとおり表示すること。デザインはデザイン仕様（`DTP-VTPL-110`）に従う。
  - 縦の罫線を引かず、行の区切りの横の罫線と、見出しの行の下のアクセントの線（スタイルの `--vs-c1`）で組む。
  - 先頭の列を、行の見出しとして強調する。
  - 本文のセルがすべて数値の列（先頭の列と、Markdown で揃えを指定した列を除く）は、右揃え・等幅の数字で表示する。`—` などの欠損の印のセルは判定から除く。
  - 本文のセルがすべて 10 字以内で空白を含まない列は、セルを折り返さない。
  - それ以外の列は、文節の区切りを優先して折り返す。
- 表は版面の幅に収め、収まらない場合は表の枠の中で横スクロールにすること（`DD-MD-020` と同じ）。
- Markdown で指定した列の揃え（`TC-MD-006`）を保つこと。
- 高速モードの表示は変えないこと（`NFR-006`）。
- **背景・根拠**: 格子で囲み、見出しを等幅の大文字にした表は、仕様書（高速モード）には合うが、展示の誌面では表計算ソフトの画面に見え、簡易ビューアーの印象を残す。誌面の表は横の罫線と余白で読ませ、数字の桁をそろえるのが定石である（`RGH-101`, `RGH-014`）。
- **背景・根拠（列の判定）**: 列の種類はセルの文字（`textContent`）だけで判定する。要素の大きさを計測しないため、描画の軽さ（`TC-VTPL-010`）を保てる。
- **採らなかった案**:
  - セルを文節でだけ折り返す案（`RGH-907`）。長い複合語が列の最小幅になり、多列の表がはみ出した。

### FR-026: Visualモードのスラブ画像エクスポート

- **0.2.0 では提供しない**（`CR-001`）: 出力される画像が誌面にならない（題名とリードだけの白いカードになる）ため、要求を満たしていない。動かない機能を出さないよう、作り直すまで操作部（「コピー」「PNG」）を出さない（`DD-VTPL-124`）。以下は作り直すときの要求である。
- Visualモードの各スラブ（`.exhibition-slab`）のヘッダーまたは操作部に、スラブ全体を画像化して出力するボタン（「画像としてコピー」「PNG保存」）を設けること。
- スラブ全体の視覚的レンダリング結果（章見出し、リード、要点カード、手順、ダイアグラム、表、ベクター装飾素材、スタイル色）を高精細な PNG 画像（2倍スケール等）として生成すること。
- 「コピー」ボタン押下時は、クリップボードに PNG 画像データとして書き込み（`ClipboardItem`）、成功時にトースト通知を表示すること。クリップボード API 非対応環境や権限エラー時は自動的にダウンロードへフォールバックすること。
- 「PNG保存」ボタン押下時は、ファイル名 `slab-<章番号>-<タイトル>.png` としてダウンロードすること。
- 外部ネットワークへの通信を行わず、ローカル・オフライン完結で処理すること（`NFR-001`, `NFR-008`）。
- 高速モードの表示・動作には影響を与えないこと（`NFR-006`）。
- **背景・根拠**:
  - Visualモードで組版されたスラブは、見出し・解説文・カード・図版全体を含めて「1枚のプレゼンテーション素材」として高い完成度（Exhibition-Grade）を持つ。
  - これをワンクリックでプレゼンテーションスライド（PowerPoint / Keynote / Google Slides）やチャットツール、SNSに直接貼り付けられるようにすることで、ドキュメント閲覧だけでなく「スライド素材作成ツール」としての利便性を飛躍的に高める。
- **採らなかった案**:
  - 外部の巨大な HTML レンダリングライブラリ（html2canvas 等）を同梱する案。ファイルサイズが増加し、オフライン単体アプリとしての軽量性を損なうため、標準の SVG foreignObject ＋ Canvas による自前軽量レンダリングを採用する。

### FR-027: Visualモードの KPI メトリクス・ショーケース

- 要点カード型（`FR-016` / `DTP-VTPL-030`）の各カードにおいて、項目の題（`.vs-point-title`）が数値・指標表現（`120ms`, `99.9%`, `3.2x`, `+48%`, `< 15ms`, `$1.2M`, `2,400件`, `0依存` など、数字と単位・記号からなる 20 字以内の表現）に一致する場合、そのカードを KPI メトリクス・カード（`.vs-metric-item` / `.vs-metric-value`）として大判等幅タイポグラフィに昇格させること（`DTP-VTPL-035`, `RGH-104`）。
- 同一リスト内で数値項目と通常のテキスト項目が混在していても、条件を満たすカード単位で個別に適用すること。
- 高速モードの表示は変えないこと（`NFR-006`）。
- **背景・根拠**: 企画書・成果報告・ベンチマーク発表では、KPI や性能数値を一目で聴衆に印象づけることが重要である。独自の Markdown 記法を追加することなく、通常の `**99.9%**: 稼働率` という記述だけで展示品質の KPI カードに自動昇格させることで、執筆体験と視覚的訴求力を両立する。

### FR-029: Visualモードのタイムライン・ロードマップ修飾

- 要点カード型（`ul.vs-points`）のすべての項目（2 個以上）が題を持ち、かつ全項目の題が日付・四半期・フェーズ・マイルストーン・バージョン（`2026 Q1`, `2026-04`, `Phase 1`, `Milestone 2`, `v1.0`, `第1期` など）に一致する場合、リスト全体に `.vs-points-timeline`、各項目に `.vs-timeline-item`、題に `.vs-timeline-badge` を付与し、等幅ピルバッジと接続ガイドで結んだロードマップ表現にすること（`DTP-VTPL-036`, `RGH-112`）。
- **背景・根拠**: プロジェクト計画やリリースロードマップは箇条書きで書かれることが多いが、単なる並列カードよりも時系列のつながりが見えるピルバッジ＋接続ガイドにすることで、工程やマイルストーンの流れを直感的に伝える。

### FR-030: Visualモードの Before / After 比較ペアカード修飾

- 要点カード型（`ul.vs-points`）の項目がちょうど 2 個で、1 項目目の題が課題側（`Before`, `従来`, `旧`, `課題`, `現状`, `As-Is` で始まる）、2 項目目の題が解決側（`After`, `導入後`, `新`, `解決`, `改善`, `To-Be` で始まる）の対になっている場合、リストに `.vs-points-compare`、1 項目目に `.vs-compare-before`、2 項目目に `.vs-compare-after` を付与し、課題側を抑えたトーン、解決側をアクセント太枠と光彩で強調した対比表現にすること（`DTP-VTPL-037`, `RGH-111`）。
- **背景・根拠**: 提案書やアーキテクチャ刷新の発表で最も頻出する「従来の課題 vs 導入後の解決」の 2 枚カードを、色と枠の強弱だけで明確に対比させ、解決策の訴求力を高める。

### FR-031: Visualモードのコード・ショーケース

- Visualモードのスラブ内のコードブロック（図版内部を除く `<pre><code>`）に `.vs-code-block` を適用し、丸端キャレット装飾（`AST-109`, `.vs-code-caret`）、言語ラベル（`data-code-lang`）、およびワンクリックでコードをクリップボードへコピーするボタン（`.vs-code-copy-btn`）を備えた暗色コンソール枠として表示すること（`DTP-VTPL-038`, `RGH-102`）。
- 言語ラベルおよびコピーボタンのラベルは CSS 擬似要素（`attr()`）で描画し、コードブロック本来の `textContent` を汚染しないこと。
- **背景・根拠**: エンジニアリング仕様書や技術登壇ではコードスニペットが重要な主役となる。単なる `<pre>` 枠ではなく、ブランドモチーフの丸端キャレット（`AST-109`）と言語バッジ・コピー機能を備えたコンソールパネルに仕立てることで、技術プレゼンにおける実用性とデザイン品質を高める。

### FR-032: Visualモードの表紙スペックバッジとドットマトリクス透かし

- Visualモードの表紙（`FR-020`）に、背面のドットマトリクス透かし（`AST-110`, `.vs-cover-texture`）と、文書のメタ情報・規模を示すスペックバッジ行（`.vs-cover-specs` / `.vs-cover-spec-pill`）を表示すること（`DTP-VTPL-105`, `RGH-107`）。
- スペックバッジには、フロントマターの単一行スカラー `author`・`date`（入れ子構造は無視する）、章数（`NN STAGES`）、および図数（`NN DIAGRAMS`、図が 1 つ以上ある場合）を表示すること。
- **背景・根拠**: 表紙を開いた瞬間に「誰がいつ書いた、何章・何図からなるドキュメントか」が一目で伝わることで、展示パネルや仕様書扉としての信頼感と情報密度が向上する。

### FR-035: Visualモードの定義リスト型（用語集）

- 章の本文要素が「箇条書き（`ul`）1 つ」または「段落 1 つ＋箇条書き 1 つ」で、項目が 2〜12 個、かつすべての項目が `**用語** — 説明`（太字の用語の直後がダッシュ `—`・`–`・`―`）の形の場合、その章を定義リスト型（`glossary`）の誌面にすること（`DTP-VTPL-045`、`RGH-115`）。
- 用語は 40 字以内、項目は 200 字以内で、項目に入れ子のリスト・コード・表・引用・チェックボックスを含まないこと。条件を満たさない章は、これまでどおり要点カード型・標準型などで表示する。
- 定義リスト型では、箇条書きを定義リスト（`dl`）に組み替え、用語（`dt`）を等幅・太字、説明（`dd`）を本文の書体で、2 段（用語の列と説明の列）に揃えること。区切りのダッシュは表示しないこと。
- 項目が 7 個以上で版面が十分に広いときは行を 2 段に並べ、版面が狭いとき（`Split` 表示など）は用語の下に説明を置く 1 列にすること。
- コロン区切り（`**題**: 説明`）の箇条書きは、要点カード型（`DTP-VTPL-030`）の書き方のため、定義リスト型にしないこと。
- 判定はセルの文字と要素の種類だけで行い、要素の大きさを計測しないこと（`TC-VTPL-010` の描画の軽さを保つ）。高速モードの表示は変えないこと（`NFR-006`）。
- **背景・根拠**: 技術発表・仕様書の用語の説明は、要点カードにすると項目ごとに大きな枠が並び、10 語前後の用語集では縦に長く間延びする。標準のリストのままでは用語と説明の境目が文中に埋もれる。辞書のように用語の列を揃えると、聴衆は用語の列だけを縦に追って探せる。用語を等幅で組むことで、ブランドの「丸みのある等幅」の論理性（ブランドコンセプト 1.2.5）を誌面に出せる。
- **背景・根拠（区切りの記号）**: 要点カード型はコロン区切りを題と説明の区切りとして使っている。区切りの記号で用語集と要点カードを分けると、書き手は書き方だけで結果を選べ、独自の記法も要らない（`RGH-901` と同じ方針）。
- **採らなかった案**:
  - コロン区切りの 7 項目以上を用語集にする案（`RGH-909`）。同じ書き方が項目の数でカード・用語集・リストの 3 通りに変わり、書き手が結果を予測できない。

### FR-036: 印刷・PDF の配布資料

- ブラウザの印刷（`Ctrl+P` / `⌘P`、および「PDF として保存」）で、プレビューの文書だけを刷ること。ヘッダー、エディタ、状態の表示、トースト、スラブの操作ボタン、コードのコピーボタン、ステージ発表の操作部、光の演出の層は刷らないこと（`DTP-VTPL-120`、`RGH-119`）。
- Visualモードでは、A4 横の用紙に、表紙と各章（スラブ）を 1 ページずつ刷ること。1 ページに収まらない章は、カード・手順の項目・図・表の行の途中で切らずに次のページへ送ること。
- 高速モードでは、A4 縦の用紙に仕様書として上から流して刷り、見出しの直後で改ページしないこと。
- 画面と同じ配色（背景色・グラデーションを含む）で刷ること。アニメーション・遷移・スポットライトの減光は止めた状態で刷ること。
- ヘッダーの「ファイル」メニューに「印刷 / PDF として保存…」を置き、ブラウザの印刷を開くこと。
- 追加のライブラリやネットワークを使わないこと（`NFR-001`, `NFR-008`）。画面の表示・操作の速さに影響しないこと（印刷の指定は印刷のときだけ効く CSS で行う。`NFR-006`）。
- **背景・根拠**: 展示会・講演では、投影した誌面と同じ内容の配布資料を求められることが多い。スラブの画像化（`FR-026`）は 1 章ずつの操作のため、文書全体を 1 回で書き出す手段が要る。ブラウザの印刷は「PDF として保存」も含めて追加の部品なしに使え、オフラインで動く。
- **採らなかった案**:
  - PDF を生成するライブラリを同梱する案。ファイルが大きくなり、ブラウザの印刷と同じ誌面を再現する手間も大きい。
  - 印刷では Light の配色に切り替える案（`RGH-911`、ストック）。画面で確かめた誌面と配布資料の見た目が変わる。
