# Feature Requirement Specification: zoom-map

発表モードの 1 つ「ズーミング・マップ」の要求を定める。

対応する全体 SRS: [doc/1.SRS.md](../../../1.SRS.md)／目次: [README.md](README.md)

## 機能要求の詳細

### FR-054: ズーミング・マップ（Web 版）

- 文書の全体を 1 枚の大きな地図に並べ、発表では、カメラが章から章へ飛ぶこと（#61、`RGH-129`）。全体と部分の関係を、位置と大きさで伝える。
- **入口と提供する版**: ヘッダーの「発表」のドロップダウンから選ぶ。提供する版は登録表（`src/ts/modes/modes.json`）の `stage` で決める。今は Web 版だけで出し（`stage: "web"`）、スタンドアロン版（ZIP）には入れない。使う人の制限（隠し設定や確認）は設けない。
- **地図**: Visualモードの表紙と章を、左から右へ進み行ごとに折り返す道の形に並べ、章の順番を細い道でつなぐこと。配置は見出しの並びから自動で決め、Markdown に独自の記法を足さない。章が多い文書（15 以上）も、行を増やして並べる。
- **動き**:
  1. 始めると、全体の地図が見える（俯瞰）。すべての章が画面に収まる。
  2. `→`（`Space`・`Enter`・`↓`・`PageDown`）で、カメラが 1.0〜1.4 秒かけて次の場所へ飛ぶ。遠い場所へは、いったん引いてから寄る（地図の上を飛ぶ感じを出し、全体のどこへ移ったかを動きで伝える）。章が画面いっぱいになる。
  3. 章に小見出し（h3）があれば、さらに小見出しへ寄る。小見出しの区間や章が画面に収まらない（文字が読めないほど縮む）ときは、上から 16:9 の区切りで順に寄る。
  4. 最後に、カメラが引いて全体の地図に戻る。
  5. `←`（`↑`・`PageUp`・`Backspace`）で前へ、`Home` で全体の地図、`End` で最後、`Esc` で終える。地図の上の章を押すと、その章へ飛ぶ。
- 今いる章の輪郭を灯し、ほかの章を少し沈めること。下の帯に、今いる場所の名前と番号、操作の案内を出すこと。
- 動きを減らす設定（`prefers-reduced-motion`）のときは、カメラを動かさず、すぐに次の場所を映すこと。
- 終えたら、地図に入る前の表示（描画モード・表示の切り替え・スクロールの位置）に戻すこと。
- 部品は、選んだときだけ読み込み、起動を重くしないこと（`NFR-006`、#58）。
- **背景・根拠**: ページを 1 枚ずつめくる発表では、全体のどこを話しているかが伝わりにくい。空間を移動する見せ方にすると、全体と部分の関係を、聴衆が動きで理解できる。
- **採らなかった案**:
  - 題名を中心に章を放射状に並べる配置。章が多いと外周が広がり、隣の章へ移る距離がばらつく。道の形なら、章が増えても行を増やすだけで済む。
  - 章を複製して地図を作る。図の SVG の id が重複し、矢じりやグラデーションの参照が崩れる。Visualモードの章をそのまま並べ直す。
