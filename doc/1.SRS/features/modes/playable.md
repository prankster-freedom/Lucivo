# Feature Requirement Specification: playable

発表モードの 1 つ「プレイアブル・ダイアグラム」の要求を定める。

対応する全体 SRS: [doc/1.SRS.md](../../../1.SRS.md)／目次: [README.md](README.md)

## 機能要求の詳細

### FR-055: プレイアブル・ダイアグラム（Web 版）

- 文書の中の図を、見るだけでなく触って動かせるようにすること（#62、`RGH-135`）。状態遷移図は「画面の試作品」になり、フローチャートは「質問に答えて進む診断」になる。
- **入口と提供する版**: ヘッダーの「発表」のドロップダウンから選ぶ。提供する版は登録表（`src/ts/modes/modes.json`）の `stage` で決める。今は Web 版だけで出し（`stage: "web"`）、スタンドアロン版（ZIP）には入れない。使う人の制限は設けない。
- **対象の図**: 文書の中の状態遷移図（`stateDiagram` / `stateDiagram-v2`）とフローチャート（`flowchart` / `graph`）。独自の記法は足さず、標準の図から動かす。動かせる図がないときは、始めずに知らせる。複数あるときは、図を切り替えられる（`[` / `]`、または上の ‹ ›）。
- **状態遷移図（試作品）**: 左に小さな画面の枠（スマートフォンの形）を出し、今の状態の名前を画面の題名、状態の注釈（`状態 : 説明`）を画面の項目、矢印のラベルをボタンにする。ボタンを押すと次の状態に移る。終わり（`[*]`）へ進むと「おわり」の画面になる。
- **フローチャート（診断）**: 判定のノード（ひし形）は質問になり、分岐のラベルが選択肢のボタンになる。答えていくと 1 歩ずつ進み、矢印の先がないノード（結果）にたどり着く。次のカードは下からスライドして現れる。
- **図の上の表示**: 右に図を出し、今いるノード（入れ子の状態は枠）を光らせ、通ったノードを残し、まだのノードを少し沈める。フローチャートでは、最後に通った矢印に光を走らせる。図の上で、今の場所から矢印でつながるノードを押しても進める。
- ボタン（`1`〜`9`）で選び、`R` で最初から、`Esc` で終える。ボタンを押すと小さなクリック音を鳴らす（鳴らせない環境では鳴らさない）。終えたら、図を元の場所・元の順に戻し、付けた印を残さないこと。
- 部品は、選んだときだけ読み込み、起動を重くしないこと（`NFR-006`、#58）。
- **背景・根拠**: 状態遷移図やフローチャートは、読むだけでは動きを想像しにくい。触って動かせると、仕様の確認や、利用者・関係者への説明がそのまま試作品の体験になる。
- **採らなかった案**:
  - 状態から凝った画面を推測して作る。推測には限界があり、外れると誤解を生む。ワイヤーフレームの記号（題名・項目・ボタン）にとどめる。
  - 変数や条件を持つ複雑な動き。単なる状態の遷移に絞る。
  - 図の構造を SVG から取り出す（Issue の「技術の当たり」）。Mermaid の版で SVG の構造が変わると壊れやすい。構造は原文から読み、SVG は光らせるためだけに使う。
