# Feature Requirement Specification: museum-walk

発表モードの 1 つ「ミュージアム・ウォーク」の要求を定める。

対応する全体 SRS: [doc/1.SRS.md](../../../1.SRS.md)／目次: [README.md](README.md)／デザイン仕様: [museum-walk.md](../../../0.DTP/features/modes/museum-walk.md)

## 機能要求の詳細

### FR-056: ミュージアム・ウォーク（Web 版）

- 文書を 1 枚ずつのスライドで切り替えるのではなく、1 本の連続した建築空間（回廊・広間・小部屋）として構成し、歩いて読み進む展示・閲覧体験を提供すること（#63、`RGH-142`、`DTP-MWLK-010`〜`070`）。
- **主たる利用場面**: 大画面での展示閲覧と、スマートフォン（縦長画面）での回遊閲覧を主とし、発表（プレゼンリモコンでのコマ送り）用途は前提としない。
- **入口と提供する版**: ヘッダーの「発表」のドロップダウンから選ぶ。提供する版は登録表（`src/ts/modes/modes.json`）の `stage` で決める。今は Web 版だけで出し（`stage: "web"`）、スタンドアロン版（ZIP）には入れない。文書が空のときは開始せず、案内（トースト）を出す。なお、タッチ主体端末のスマホ（`pointer: coarse` かつ短辺 768px 以下）では描画欠けの修正（#123）が完了するまで暫定的にメニュー項目を無効化し、利用を制限する（#125）。
- **Markdown からの自動構成（独自の記法は足さない）**:
  1. 文書の題名（`h1` とフロントマターの概要）を入口の「表紙の門」にする。
  2. 各章の見出し（`h2`）を、通路の中央に立つ「門」にする。近づくと開いて通り抜けられ、通過後に次の章の空間が開ける。
  3. 図表（Mermaid 図など）を含む箇所には天井の高い「広間」を開き、図を中央に立てる（`DTP-MWLK-050`）。
  4. 引用ブロック（`blockquote`）には狭く低い「小部屋」を設け、壁に近づけて銘板として配置する。
  5. 小見出し（`h3`）・段落・箇条書きは種類ごとに壁からの奥行きと出現距離をずらして配置する（`DTP-MWLK-030`）。
- **歩き方と視線制御**:
  - マウスホイール、タッチの上下スワイプ、キーボードの矢印キー（`↑` `↓` `→` `←`）・`W` `S` `Space` で前後に歩けること。ドラッグで見回せること。
  - 歩いている間は進行方向寄りを見、立ち止まると壁の文字へ視線を向ける自動視線制御（`G` で切替）を持つこと。門の前と広間では中央・正面へ、小部屋では引用の近くへ自然に導くこと。
  - スマートフォン等の縦長画面では、立ち止まった際に壁の文字が左右とも画面内に収まるよう、視野と向き・立ち位置を自動補正すること（`DTP-MWLK-060`）。
  - `T` で Dark / Light の外観を切り替え（初期値は本体の外観設定に合わせる）、`R` / `Home` で入口に戻り、`Esc` で終えること。
- **動きを減らす設定と終了時の復元**:
  - `prefers-reduced-motion` が有効な環境では、カメラの揺れ・過度な滑走を抑えること。
  - 終えたら、開始前の表示（描画モード・表示の切り替え・スクロールの位置）に戻すこと。
- **起動と描画の軽快さ**:
  - 部品は選んだときだけ読み込み、起動を重くしないこと（`NFR-006`）。
  - 歩行中はレイアウト再計算や背景の再ペイントを起こさず、滑らかに歩けること（`DTP-MWLK-070`）。
- **背景・根拠**: 「1 章 = 1 シーン」や「次へ」の送り操作では、聴き手や展示の閲覧者が全体の現在地を見失いやすい。文書を連続した空間に置き直すことで、歩くこと自体が読み進む体験になり、スマホのスワイプ閲覧や展示ブースでの回遊にも自然になじむ。
- **採らなかった案**:
  - 1 章 1 額縁の前に止まり、2D で全画面に重ねる案（`RGH-136`）。止まった画面が従来のスライドと同じになり、空間を歩く意味が薄れる。
  - 門や立体図の脇を回り込む動線（`RGH-912`）。中央を通り抜けるほうが視界が開け、操作も単純になる。
  - 文書の中身から建物を自由生成する案（`RGH-144`）。初期提供では破綻を防ぐため、通路・広間・小部屋の 3 断面に絞る。
