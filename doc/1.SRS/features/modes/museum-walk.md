# Feature Requirement Specification: museum-walk

発表モードの 1 つ「ミュージアム・ウォーク」の要求を定める。

対応する全体 SRS: [doc/1.SRS.md](../../../1.SRS.md)／目次: [README.md](README.md)／デザイン仕様: [museum-walk.md](../../../0.DTP/features/modes/museum-walk.md)

## 機能要求の詳細

### FR-056: ミュージアム・ウォーク（Web 版）

- 文書を 1 枚ずつのスライドで切り替えるのではなく、1 本の連続した建築空間（回廊・広間・小部屋）として構成し、歩いて読み進む展示・閲覧体験を提供すること（#63、`RGH-142`、`DTP-MWLK-010`〜`070`）。
- **主たる利用場面**: 大画面での展示閲覧と、スマートフォン（縦長画面）での回遊閲覧を主とし、発表（プレゼンリモコンでのコマ送り）用途は前提としない。
- **入口と提供する版**: ヘッダーの「発表」のドロップダウンから選ぶ。提供する版は登録表（`src/ts/modes/modes.json`）の `stage` で決める。今は Web 版だけで出し（`stage: "web"`）、スタンドアロン版（ZIP）には入れない。この方針は version 1.0.0 でも変えない（1.0.0 でも Web 版限定）。スタンドアロン版へ展開するか、廃止するかは、1.0.0 の後に、利用者の反応を見て決める。文書が空のときは開始せず、案内（トースト）を出す。スマホ（タッチ主体の端末）でも、PC と同じく選べる（#397。以前の利用制限 #125 は解いた）。描画のメモリが足りない端末向けには、描画の軽さを選べる（下記）。
- **Markdown からの自動構成（独自の記法は足さない）**:
  1. 文書の題名（`h1` とフロントマターの概要）を入口の「表紙の門」にする。
  2. 各章の見出し（`h2`）を、通路の中央に立つ「門」にする。近づくと開いて通り抜けられ、通過後に次の章の空間が開ける。
  3. 図表（Mermaid 図など）を含む箇所には天井の高い「広間」を開き、図を中央に立てる（`DTP-MWLK-050`）。
  4. 引用ブロック（`blockquote`）には狭く低い「小部屋」を設け、壁に近づけて銘板として配置する。
  5. 小見出し（`h3`）・段落・箇条書きは種類ごとに壁からの奥行きと出現距離をずらして配置する（`DTP-MWLK-030`）。
- **歩き方と視線制御**:
  - マウスホイール（上回しで前進・下回しで後退、#305）、タッチの上下スワイプ、キーボードの矢印キー（`↑` `↓` `→` `←`）・`W` `S` `Space` で前後に歩けること。ドラッグ（マウス）・左右スワイプ（指）で見回せること。見回せる範囲は、進む向きから左右とも同じ約 100 度（真横より少し後ろ）までとすること。指のスワイプは、マウスのドラッグより少ない動きで大きく見回せること（#434）。
  - `Ctrl`＋ホイールの上下回し、または `+`（`=`）・`-`・`0`（`Ctrl` 併用を含み、ミュージアム・ウォーク中はブラウザ標準ズームを上書きする）で展示に一歩近寄る・離れる・既定の距離へ戻れること（#275）。タッチでは、2 本指を広げる（ピンチアウト）と近寄り、狭める（ピンチイン）と離れること。ピンチの間は見回し・歩行を止め、指を離しても近寄った量を保つこと（#437）。近寄り・戻りは一歩踏み出す上下の動きを含めたカメラワークとし、壁・門・立体図を通り抜けない上限で止め、歩き出したら自動で既定の距離へ戻すこと。
  - 歩いている間は進行方向寄りを見、立ち止まると壁の文字へ視線を向ける自動視線制御（`G` で切替）を持つこと。門の前と広間では中央・正面へ、小部屋では引用の近くへ自然に導くこと。
  - 広間・小部屋の境目などに段差（スロープ・蹴上げ）と空間全体の起伏（中盤にかけて緩やかに下り、後半にかけて少し上へ戻る高低差）を設け、通過に合わせてカメラの高さも滑らかに追従させること（#306、`DTP-MWLK-020`・`060`）。
  - スマートフォン等の縦長画面では、立ち止まった際に壁の文字が左右とも画面内に収まるよう、視野と向き・立ち位置を自動補正すること（`DTP-MWLK-060`）。
  - `T` で Dark / Light の外観を切り替え（未設定時の初期値は Dark とし、前回 `T` で選んだ外観を覚える）、`R` / `Home` で入口に戻り、`Esc` で終えること。
- **動きを減らす設定と終了時の復元**:
  - `prefers-reduced-motion` が有効な環境では、カメラの揺れ・過度な滑走を抑えること。
  - 終えたら、開始前の表示（描画モード・表示の切り替え・外観・スクロールの位置）に戻すこと。
- **起動と描画の軽快さ**:
  - 部品は選んだときだけ読み込み、起動を重くしないこと（`NFR-006`）。
  - 歩行中はレイアウト再計算や背景の再ペイントを起こさず、滑らかに歩けること（`DTP-MWLK-070`）。
  - 描画のメモリが足りない端末でも、門や壁の文字が欠けたり描かれなくなったりしないよう、描画の軽さを 4 段階（1 が最も細かく、4 が最も軽い）から選べること。段階は、URL の指定（`museum-light=1`〜`4`）、保存した段階、端末の既定（PC は 1、スマホは 3）の順に決める（#426、`DTP-MWLK-070`）。「その他（アプリ設定）」の画面に、「ミュージアム・ウォークの描画の軽さ」の選択（おまかせ（端末に合わせる）・1 くっきり・2 ふつう・3 軽い・4 とても軽い）を置き、選んだ段階を保存すること。「おまかせ」は、保存した段階を消して、端末の既定に戻す。変更は、次にミュージアム・ウォークを始めるときから効く。ミュージアム・ウォークのない版（スタンドアロン版）では、この選択を出さない。
- **背景・根拠**: 「1 章 = 1 シーン」や「次へ」の送り操作では、聴き手や展示の閲覧者が全体の現在地を見失いやすい。文書を連続した空間に置き直すことで、歩くこと自体が読み進む体験になり、スマホのスワイプ閲覧や展示ブースでの回遊にも自然になじむ。
- **採らなかった案**:
  - 1 章 1 額縁の前に止まり、2D で全画面に重ねる案（`RGH-136`）。止まった画面が従来のスライドと同じになり、空間を歩く意味が薄れる。
  - 門や立体図の脇を回り込む動線（`RGH-912`）。中央を通り抜けるほうが視界が開け、操作も単純になる。
  - 文書の中身から建物を自由生成する案（`RGH-144`）。初期提供では破綻を防ぐため、通路・広間・小部屋の 3 断面に絞る。
