# design-craft（伝わるデザインの考え方と道具）

デザインを「飾りつけ」ではなく「伝えたいことを、伝わる形に整理すること」として進めるための考え方と道具をまとめる。
`dtp` スキルが工程と成果物（仕様書・ラフ台帳・校正記録）を定めるのに対し、本スキルは、その中で**何をどう判断するか**を定める。

対象: $ARGUMENTS

## 0. 本スキルの読み方

- 1〜11 章は、ユーザーが共有した書籍の内容（第 1 章「編集×デザイン」、第 2 章「デザイナーの 7 つ道具」、第 3 章「デザインの素」の一部）を、見本の写真も含めて文章にしたもの。例はすべて書籍の見本による。
- 12 章は、書籍の内容を Lucivo などの画面デザインに当てはめた**応用（推論）**。書籍には書かれていない。
- 図はテキストのポンチ絵（コードブロック）で示す。□ は四角い要素、■ は色ベタの要素、○ は丸い要素を表す。

## 1. デザインの前に「編集」をする（誰に・何を・なぜ・いつどこで）

同じ題材でも、伝える相手と目的が変われば、正しいデザインは変わる。デザインを始める前に、次の 4 つを決める。

| 問い                   | 考える軸（書籍の例）                          |
| :--------------------- | :-------------------------------------------- |
| どんな人に伝えたい？   | 年齢と性別（こども↔大人）、知識レベル（とても詳しい↔全く知らない）、関心の高さ（関心が高い↔無関心）、状況（受験生、新社会人、忙しい）、ライフスタイル（食にこだわる など） |
| 何を伝えたい？         | 作り方、バリエーション、おいしさ、美しさ など |
| なぜ伝えたい？         | 理解してほしい、迷わせない、正確に伝えたい、覚えてもらいたい、楽しんでもらいたい、好きになってほしい、商品を売りたい など |
| いつ・どこで伝えたい？ | 接点（本屋やコンビニで手に取る本、勝手に届く DM、学校で使う教科書、通勤途中で見る広告）、順番（巻頭に出てくる、後半に出てくる） |

題材「朝食」を、3 通りに編集した例:

|     | どんな人に                 | 何を                   | なぜ               | いつ・どこで（媒体）      |
| :-- | :------------------------- | :--------------------- | :----------------- | :------------------------ |
| A   | 男女問わず料理初心者が     | 朝食の作り方を         | 迷わないために     | 長く使ってもらいたい書籍  |
| B   | 料理好きで関心の高い女性が | 朝食のバリエーションを | 楽しんでもらう     | 月に複数回発行される雑誌  |
| C   | 生活にこだわりのある人が   | 上質な朝の風景に       | 憧れを持ってもらう | 季節ごとに 1 冊出るムック |

- 4 つの答えが、後のすべての判断（方向性、主役、足し算と引き算のさじ加減）の基準になる。
- 2 章のトーストのレシピは、B（楽しんでもらう雑誌）の例。だから表現の方向性が「にぎやか」になり、足し算が多めになる。

## 2. 6 つのステップ（大きな構成から、細部は最後に）

デザインに「絶対正しい手順」はない。それでも、先に大きな構成から決め、細部のディテールは最後の最後に着手するのが、スムーズで効率的。
見本は、雑誌の 1 ページ「毎日楽しい 彩りトーストレシピ」（トースト 3 品のレシピと、つくりおきバターのコラム）。ページが各 STEP でどう変わるかは、[assets/toast-steps.svg](assets/toast-steps.svg) に縮図で示す。

```text
STEP 0 図解とラフ  →  1 方向性を決める  →  2 骨格をつくる
   →  3 キャラを立たせる  →  4 足し算と引き算  →  5 ブラッシュアップ
（構成・構造）─────────────────────────→（細部・ディテール）
```

### STEP 0 図解とラフ

目的: デザインしたいことが整理できているかを確かめる。図解やラフが上手く描けないなら、どこかにあいまいな部分が残っている。始める前に、完成したデザインが目に浮かぶくらい考える。

**図解**: 大げさなものは要らない。確かめるのは**情報の階層構造**。

- 親子関係か、並列関係か。
- 等しく扱うべき内容か、特定の 1 つを目立たせたほうが良いのか。
- 「デザインが進んでから、そもそも構成から違っていた」という失敗を防ぐため、不明点をなくしてから進める。

```text
◎ 正しい図解（彩りトーストレシピ）
   [A] [B] [C]  ＋ バターのコラム
   ・レシピ A・B・C は並列関係で、全部同じ大きさで扱う
   ・コラムは独立した内容で、特定のレシピにはつかない

× 親子関係と誤解        × 大きさを誤解
      [A]                  [ A ]  [B] [C]
     ／  ＼               （A だけが B・C より大きい）
   [B]    [C]
```

**ラフ**: いきなりアプリケーションで作業を始めると、できることが多すぎて、肝心の構成を見落としがち。手描きのラフなら迷子にならない。色も書体も変えられないラフだからこそ、内容の理解と整理に役立つ。ラフは複数描き、写真とレシピの配置で印象がどう変わるかを比べる。

### STEP 1 方向性を決める

内容が理解できたら、おおまかな方向性を**「表現」と「構造」の両面**から考える。表現の方向性の材料は、テーマからの連想で集める（7 章「連想力」）。デザインが進んでから構造を考え直すと、大幅な修正になる。ざっくり配置した状態で、どの方向性で進めるかを先に決める。

**表現の方向性**（見本では「きっちり」より「にぎやか」を選んだ）:

```text
 きっちり          にぎやか
 □□□     より    ○  ○
 □□□              ○   ○
```

- 配置はランダムにして、動きを出す。
- 色は多めに使って、カラフルな楽しさを出す。
- 角版の写真より、キリヌキの写真でにぎやかにする。

**構造の方向性**（ラフで案を比べ、問題点を言葉にする）:

- 写真を左にまとめる案: 右下にコラムが入る分、左の写真と右のレシピをきれいに横に並べにくい。どの写真がどのレシピか、混乱しやすい。
- 写真を中央に固める案: 写真が奇数（3 点）なので、中央に固めたように見せにくい。コラムが左上に来てしまうのもいまいち。

### STEP 2 骨格をつくる

色や書体を変えるのは、まだ我慢する。ディテールに惑わされて、肝心の構造ができているかが見えなくなるため。色や書体に頼らなくても成立する配置なら、言葉がなくても伝わる、直感的な分かりやすさが生まれる。

- **タイトルとリードは頭にまとめる**: メインタイトルとリードは真っ先に目がいく文字サイズにして、左上にまとめる。欧文やリードもセットにして「かたまり感」を出し、他に埋もれない存在感にする。
- **バランス良く写真を配置する**: 写真をキリヌキにして、動きのある配置にする。3 点なら三角形を作る意識で置くと、バランスを取りやすい。写真の色や料理のカタチに合わせて、順番も入れ替える。
- **コラムはページの最後に**: おまけ感が出るよう、目線が最後に来る下のエリアに置く。それだけではレシピとなじむので、カコミの色地を入れて差をつける。
- **写真とレシピのかたまり感を出す**: どのレシピがどの写真を説明しているかを、誤解なく伝える。トースト名・材料・作り方の 3 点をまとめて写真に添え、かたまりにする。

### STEP 3 キャラを立たせる

「デザイン＝あれこれ飾りつけること」ではない。飾りを足さなくても、**書体・組み・カタチ・配置**に気を配り、要素ひとつひとつに個性を持たせるだけで、印象は十分に変わる。どんな個性にするかは、デザインを人に例えて決める（6 章「擬人化力」）。

- **タイトルまわりを中央揃えにする**: ここだけ中央揃えに組みかえ、特別感を出す。「毎日楽しい」をサブタイトル扱いにして、メリハリをつける。
- **和文の書体を変える**: メインはベーシックながらやさしさのある書体（見本では TB ゴシック）にする。レシピ名は、大きく使ったときにほどよい抑揚が出る書体（見本では游ゴシック）にする。
- **レシピ名の字間をあける**: パラパラした印象にして、他の文字と差をつける。文字が多い中で存在感を変えたいとき、字間の調整は有効。
- **材料とレシピを調整する**: 文字サイズに差をつける。材料は罫線を入れて、リストだと一目で分かるようにする。手順の数字を ❶〜❸ にして、切れ目を分かりやすくする。

### STEP 4 足し算と引き算

ここまで進めても狙った印象に届いていなければ、**足し算**をする。なくても困らない要素が見つかれば、**引き算**をする。見本は方向性が「楽しく」「にぎやか」なので足し算が多めだが、さじ加減が重要（方向性が違えば、引き算が中心になる）。

| 種類 | 何をしたか                           | なぜ（効果）                                                                                           |
| :--- | :----------------------------------- | :----------------------------------------------------------------------------------------------------- |
| 足す | タイトルにリボンのようなあしらい（「毎日」をリボンに） | タイトルまわりの文字が多くケンカしていたので、まとめた。サブタイトルとタイトルの主従関係がはっきりした |
| 足す | レシピ名と番号に色                   | トースト名が目を引くようになった。材料の色をもとにしたので、レシピと写真のつながりも強まった           |
| 足す | 背景に紙の質感（テクスチャ画像）     | 白い皿のカタチが浮き上がり、メリハリと奥行きが出た                                                     |
| 引く | タイトルまわりの欧文のキャッチを削除 | 全体が盛り上がった分、タイトルまわりがごちゃついた。欧文は飾りとしての言葉なので、削ってすっきりさせた |

### STEP 5 ブラッシュアップ

ゴールは間近。**全体を眺める引いた目線**と、**細部を観察する寄りの目線**の両方で点検する。意図が伝わっているか、それをさらに強められないかを探す。寄りの目線で使う道具と細部のチェック項目は、9 章「虫めがね（詳細デザイン）」にまとめる。

- **紙色をさらに濃く、白フチを足す**: 紙色が濃いほうが、白抜き文字も白い皿も引き立つ。ただし重さも出るので、ページ全体に白フチをつけて少し引き算する（足し算と引き算を組み合わせる）。
- **文字を加工して丸みをつける**: トースト名を太らせて大きくし、角にわずかに丸みをつける。「書体そのまま」と「加工した文字」の差は、わずかでも目に引っかかりを作る。
- **タイトルに「止め」を作る**: サブタイトルがリボンになったので、下にも何か入れてバランスを取る。丸い皿が特徴のページなので、● を 3 つ添えて「止め」にする（ページのモチーフを繰り返す）。
- **コラムは罫線がなくてもよい**: レシピとの混同が心配だったが、色と文字サイズの差だけで区別できる。罫線を取ってすっきりさせ、代わりに写真に白フチをつけてアイコンらしくする。

## 4. ダイジ度天秤（意味の優先づけ）

デザインは、ときに「伝えたい量」と「伝わる量」との戦いになる。言いたいこと同士がケンカしたり、多すぎたりすると、表現がぼやける。全部入れたいと欲張ると、要素が多くごちゃごちゃになり、見る気を失わせる。**全てを伝えようとするデザインは、何も伝わらない。**「何がダイジなんだっけ？」を考え、取捨選択と強調をする。

**ダイジ度と表現の対応**:

| 項目   | ダイジ度が高い     | ダイジ度が低い               |
| :----- | :----------------- | :--------------------------- |
| サイズ | 大きい             | 小さい                       |
| 分量   | 多い               | 少ない                       |
| 位置   | 目が行きやすい場所 | ふつう、または目立たない場所 |
| 強さ   | 強い               | 弱い                         |
| 色     | 目立つ             | 目立たない                   |
| 要素   | 絶対入れる         | 入らなければ削る             |

**使い方**:

1. **伝えたいことを整理する**: 伝えたいことを書き出す。天秤にのりきらないほど多ければ、数を絞り込む。
2. **どっちがよりダイジ？**: 両方を同時に実現できないことは、天秤の左右にのせて優先順位をつける。似たものをグループにまとめ、グループ同士を比べる。
3. **ダイジな方を強調する**: サイズ、分量、強さ、色を調整する。選ばなかった方は小さくするか、削る。

**例 1: 傘の広告**

- 伝えたいこと: 撥水性が高い／超軽量で持ち運びしやすい／特殊構造の骨で風に強い／値段は 1,980 円／ABC というメーカーが作っている／シンプルで飽きのこないデザイン／カラーバリエーションが豊富
- 2 つのグループ: 「高機能さ」（撥水性、軽さ、骨）と「カラフルさ」（シンプルなデザイン、色の豊富さ）。値段とメーカーは、どちらにも入れない。
- 高機能さを選んだ場合: 写真 1 点を大きく使い、それぞれの機能を線で引き出して詳しく説明する。色の見本は小さく添える。
- カラフルさを選んだ場合: 全色を並べ、カラフルで楽しくする。色の選択肢の豊富さを一目で伝える。機能は小さなチェックリストにする。

```text
 高機能なカサ                  カラフルなカサ
 ┌────────────────┐            ┌────────────────┐
 │    ／傘＼ ── 撥水 │            │ ○ ○ ○  ・機能  │
 │   （大きく）── 軽量 │            │ ○ ○ ○  （小さく）│
 │        ── 骨    │            │ ○ ○ ○  （全色）  │
 │ ・・・（色は小さく） │            └────────────────┘
 └────────────────┘
```

**例 2: 料理教室の案内**

- 伝えたいこと: スタジオのアクセスが良い／キッチンスタジオがキレイ／素敵な先生が教えてくれる／少人数で教わりやすい／たくさんの料理を習える／たくさんのジャンルを習える／レッスンの値段が手頃
- 「教わる場所と人」（先生、スタジオ、少人数）を選んだ場合: スタジオと先生の写真が真っ先に目に入るバランスにし、素敵な空間を印象づける。
- 「教わるメニュー」（料理の数、ジャンル）を選んだ場合: 料理の写真と名前を、できる限りたくさん入れる。プログラムでワクワクさせる。
- アクセスと値段は、どちらの案でも主役にしない。

**例 3: 街歩きの案内**

- 伝えたいこと: アクセスする方法／お店や観光名所の場所／歩いてどのくらいかかるか／どんなエリアか／どんな料理が食べられるか／どんな観光名所があるか／どんなモノが買えるか
- 「位置関係」を選んだ場合: 地図を大きくメインに置き、そこから引き出し線で写真を紹介する。
- 「アクティビティ」を選んだ場合: 見られるモノ・買えるモノで興味をひくため、写真をメインにする。

**例から分かること**: 同じ材料から、正しいデザインが 2 通りできる。決め手は「どちらがダイジか」の判断で、それは 1 章の「誰に・なぜ」から決まる。選ばなかった要素は、小さくするか、削る。

## 5. スポットライト（見た目の優先づけ）

主役が脇役に埋もれないよう、スポットライトを当てる。読み手の目線が迷わず重要な場所へ向かうよう、デザインで舞台を整理整頓する。ダイジ度天秤が**意味の優先づけ**なら、スポットライトは**見た目の優先づけ**。

デザインした本人は、主役がすぐ分かる。それは内容をすでに理解しているから。予備知識のない人が初めて見たとき、同じように分かるとは限らない。

**使い方（離れて見るチェック）**:

1. **離れて見てみる**: いつもの数倍離れた、文章が読めない距離から見て、どう感じるかを確かめる。
2. **ライトを当てる**: 主役にすぐ目が向かなければ、下の 5 つのライトのどれかで光を当てる。
3. **もう一度離れて見る**: 主役らしくなったかを確かめる。「机では良さそうだったが、離れると分からない」なら、まだライトが弱い。

各ライトの効く例と効かない例は [assets/spotlight.svg](assets/spotlight.svg)、余白のライトは [assets/whitespace-light.svg](assets/whitespace-light.svg) を参照。

### 5.1 色のライト — 色がないなら足し算で、色がありすぎるなら引き算で目立つ

無彩色（白・黒・グレー）より、色味のあるほうが目立つ。ただし使いすぎると、色があることが「ふつう」になり、特別感が出ない。**スポットライトは、周囲が暗くなければ効かない。**色は必要最低限の数と量だけ使う。色がなければ主役に 1 色を足し、色がありすぎれば主役以外の色を引く。

### 5.2 地のライト — 地を作って図を弱める。図を作って地を弱める

「図と地」という考え方がある。図はカタチのあるもので、手前に出てきやすい。地はその背景で、奥まって感じられやすい。2 つはシーソーの関係で、図に意識がいくと地への認識は弱くなる（ルビンの壺: 杯を見ると横顔が、横顔を見ると杯が見えにくくなる）。
この性質を使い、線で描いた要素が並ぶ中で、主役だけを**色ベタの面（地）**にする。たったひとつ地があるだけで、ほかへの意識が弱まり、主役がふっと浮かび上がる。枠線を太くするだけでは、分かりづらい。

見本のトーストのページで、コラムに「カコミの色地」を入れてレシピと区別したのも、地を使った例。

### 5.3 サイズのライト — 画面に占める面積 ≒ 重要度。主役の大きさは脇役が決める

目立たせたい要素を一番大きくするのは、素直で有効な方法。面積の割合が多いほど目立ち、重要に見える。どのくらい大きくすれば主役に見えるかは、**脇役が握っている**。

- 脇役がごく小さく並んでいるなら、ほんの少し大きくするだけで十分。
- 脇役の存在感が強いなら、やり過ぎなくらいにガツンと大きくする（画面からはみ出すくらい）。

**見本（スパイスのレシピ）**: 15 種類のスパイスの写真が同じ大きさで並び、そのうち 2 つに「FEATURE」の文字を足して特別扱いしようとしたが、文字を足すだけでは弱く、目立たなかった。2 つを思い切った大きさにし（左上と右下の対角に置く）、その分ほかの写真をやや小さくしてバランスを取ると、文字がなくても特別扱いが伝わった。

### 5.4 余白のライト — おおまかに眺めても分かる余白の差をつくる

脳の神経細胞には、おおまかな空間に反応する細胞と、細かい情報に反応する細胞がある（書籍の説明による）。そのため、おおまかな空間の認識でも分かる「差」のほうが、認識されやすい。**罫線で区切るより、余白で区切るほうが分かりやすい。**罫線のグループはぼかすと区別が消えるが、余白のグループはぼかしても分かれて見える。離れて眺めると差がよく分かるので、埋もれた主役の救出に役立つ。

### 5.5 揃えないライト — まっすぐにはナナメを、整列にはズレを。秩序を作ってから、あえて乱す

脳には、まっすぐに反応する細胞とナナメに反応する細胞があり、別々に処理される（書籍の説明による）。そのため、向きの違う要素は別のものとして目立つ。ただし、**秩序があって初めてイレギュラーが効く。**最初からランダムに置くより、基本のルールを作ってから崩すほうがバランスを取りやすい。

整列の中で 1 つを傾ける、1 つを列からずらすと目立つ。動きのない足し算（枠線を足すだけ）は、意外と目立たない。

## 6. 擬人化力（デザインを人に例えて、キャラを決める）

鳥獣戯画から萌えキャラまで、日本人の手にかかれば擬人化できないモノはない。この想像力は、デザインでも役立つ。
「あの人らしいね」という言葉は、人だけでなくデザインにも言える。良いデザインには人格のようなものがあり、だからこそ心に残る。

**人に例えると、次の一手が見つかる**（書籍の例）:

- 要素をキッチリ並べただけで、まとまってはいるが「なんかさみしい」→「もっとにぎわった感じ」にしたいので、要素をずらしたり増やしたりして、ガヤガヤさせる。
- 「ドレスアップした女性」らしくしたいのに、淡白で「すっぴん」みたい → メイクを濃くするように、あしらいを「盛る」。

**使い方**: いいなと思うデザインに出会ったら、じっくり観察し、「人物に例えるなら誰？ どんな人？」と勝手にキャラ化する。自分の中に、キャラクターのアーカイブを作る（勝手に擬人化遊び）。
デザインするときは、1 章の「誰に・なぜ」から「このデザインは、どんな人として振る舞うべきか」を決め、その人らしい書体・組み・配置・あしらい・色を選ぶ。

### 6.1 要素ごとの例え

STEP 3「キャラを立たせる」で使う、書体・組み・配置・あしらい・色の 5 つの要素を、それぞれ人の特徴に例える。

## 7. 連想力（テーマから、デザインの要素を導く）

カタチ・書体・色・質感などの要素は、デザイナーが自分で決めるより、伝えたい内容やテーマから**「自然に導かれていく」「勝手に決まっていく」のが理想**。そのほうが直感的で、内容に寄り添った、伝わりやすいデザインになる。

- テーマについてじっくり考え、連想される言葉やモノをたくさん出す。それはどんなカタチ？ 色？ におい？ 手触り？ イメージの世界に浸って並べているうちに、デザインの方向性がおぼろげに見えてくる（STEP 1「方向性を決める」の材料になる）。
- 「海だから、青！」のような直接の連想も悪くはないが、それだけだと面白みに欠けたり、分かりやす過ぎて底が浅い印象になったりする。
- 正反対のモチーフ 2 つをぶつける、一見関係なさそうなところまで連想を広げる。寄り道してよい連想ゲームを続け、思いもよらないジャンプにたどり着くことも楽しむ。

**使い方**:

```text
 テーマ ─→ 言葉 ─→ イメージ ─→ デザインの要素
 (START)   word      Image       書体・色・質感・レイアウト
           word      （写真・場所・記憶）
           word
```

1. **言葉の連想**: コンセプトから連想される言葉やモチーフの名前を、たくさん書き出す。
2. **イメージの連想**: 写真を眺める、場所に行く、記憶を思い出すなどして、イメージに浸る。
3. **ヒントを引き出す**: 実際にデザインに取り入れられる色・質感・カタチなどを引き出す。

### 7.1 見本（書籍の完成例）

各例の「書籍の説明」は、書籍のキャプションによる。「連想の筋道」は、完成例とキャプションからの読み取りで、書籍に連想マップが示されているわけではない。

## 8. 翻訳機（言葉と絵を、相互に置き換える）

コミュニケーションには、大きく 2 種類ある。会話や文章など**言葉を使った「言語」**と、顔の表情・視線・身振り・声のトーンなど**言葉以外を使った「非言語」**。
同じ伝えたいことでも、どちらを選ぶかで意味が大きく変わる。たとえば街の風景の美しさを伝えるとき、言葉を尽くして文章で語るのか、美しさが分かる写真を 1 枚だけ置くのか。著名な作家の旅のエッセイなら文章が似合い、見どころを紹介する旅のガイドブックなら写真で見せるほうが適している（1 章の「誰に・なぜ・いつどこで」で決まる）。
どちらか一方が優れているわけではない。言語と非言語を行き来できるようになる。

```text
 言語（Verbal）        非言語（Non-verbal）
 ┌───────────┐         ┌───────────┐
 │ A P P L E │  ⇄     │  （りんごの  │
 │ （文字）   │         │    写真）    │
 └───────────┘         └───────────┘
```

**それぞれの得意と不得意**:

|            | 言語（言葉・文章など、文字による表現） | 非言語（写真・図版など、ビジュアル表現） |
| :--------- | :------------------------------------- | :--------------------------------------- |
| 良いところ | 媒体を問わず、表現を揃えやすい／受け取り方の個人差が比較的少ない／物事を深く細かく説明しやすい | 伝わるのが速い場合が多い／同じ言語を持たない人の間でも通じる／非言語でしか伝えられない情報がある |
| 悪いところ | 同じ言語を理解できないと使えない／伝わるまでに時間がかかる／言語だけだと見た目が退屈になりやすい | 色や媒体の制約を受けやすい／伝わる情報があいまいになりやすい／受け取り方の個人差が大きい |

**使い方**:

1. **要素を並べてみる**: 要素をすべて並べて俯瞰し、翻訳できそうなところを見つける。
2. **非言語に翻訳する**: 同じ内容でも表現を変えたほうがよいところを、非言語に翻訳する。
3. **バランスを調整する**: 言語と非言語のちょうどよいバランスは、デザインの目的に合わせて調整する。

### 8.1 見本（STUDY CAFE の案内）

カフェとシェアオフィスの良いとこどりをした店「STUDY CAFE」の案内を、ほぼ同じ内容で「言語多め」（A）と「非言語多め」（B）の 2 通りに作った例。翻訳したポイントごとに、得意と不得意がある。
写真では指で隠れて読めない箇所があったため、説明は読めた範囲の要約とする。

| 翻訳ポイント | A（言語）      | B（非言語）            | 得意と不得意（書籍の説明の要約） |
| :----------- | :------------- | :--------------------- | :------------------------------- |
| 店舗の名前   | タイトルの文字の一部として書く | ロゴを大胆に使う | B は目を引き、店に行ったときにも印象に残る。ただし、いきなりロゴが来ると宣伝っぽさが強くなりすぎる |
| 話の要点（来店した人の不満） | 口コミを文章で載せる（「席が空いてなくて…」「電源がないカウンター席しか空いていなかった」など、年齢と職業つき） | 混雑状況・座席・電源と Wi-Fi を行にした表に、× と短い説明を書く | 表は要点を簡潔に伝えられる。文章は「生の声を拾っている」感じが出るので、口コミらしさを優先するなら文章が似合う |
| 3 つの業態（カフェ、シェアオフィス、STUDY CAFE） | 文章で説明する | カップとノート PC のアイコンを添え、STUDY CAFE のロゴに両方を入れる | アイコンは見た目のアクセントになるだけでなく、「カフェ＝お茶、シェアオフィス＝仕事、STUDY CAFE＝両方をあわせ持つ」という意味も加わる |
| メリットとデメリット | 文章で説明する | ◎・○・× の記号で比べる | 記号は比べやすいが、人によって評価が分かれる内容でも、○なら○と言い切ることになる。それを「分かりやすい」とするか「受け手に判断を残す余地がない」とするかは、内容次第 |

**見本から分かること**: 非言語に翻訳すると速く分かりやすくなる一方で、ニュアンス（生の声らしさ、評価の幅）や控えめさが失われることがある。翻訳するかどうかは、ポイントごとに目的で決める。

## 9. 虫めがね（詳細デザイン：細部を詰める）

デザインの最終的なクオリティは、ブラッシュアップで決まる。そこで使う虫めがねは、デザイナーの最終兵器。STEP 5「ブラッシュアップ」で使う。

ブラッシュアップは、基本的に**「ちょっとしたこと」の積み重ね**。1 つだけでは大きな印象の変化にならないが、細かい調整を数多く行うと、最終的に明らかにクオリティが上がって見える。調整すべき場所に気づけるよう、普段から良いものをたくさん見ておく。

**使うタイミングが重要**:

- 最初は粗く見る: 大枠が固まるまでは使わずに我慢し、大きな構造と方向性を優先する。最初から細部ばかり気にすると、大きな構造を見落とす。
- 最後は細かく見る: 「もう大きな路線変更はなさそうだ」と思えたら、見方を細かくしてブラッシュアップする。

虫めがねの見方は、次の 3 つ。色と矢印の解像度、カタチの細部、見た目で揃える例は [assets/magnifier.svg](assets/magnifier.svg) に見た目で示す。

| 見方           | 内容                                                     | 書籍の例（ブラッシュアップでしたこと） |
| :------------- | :------------------------------------------------------- | :------------------------------------- |
| 視覚の解像度を上げる | 色・書体・カタチの見方は、細かいほどクオリティが上がる | 青みの緑を黄みの緑に変えた／同じ明朝体のまま書体を変えた／フキダシのカタチを変えた |
| 神は細部に宿る | 細部をおろそかにすると、全体の美しさは得られない         | 写真のトリミングを調整した／キャプションが読みやすいよう色を足した／見出しの句読点の前後をつめた |
| 見た目で考える | 人の目の錯覚や、作ったデータと実際の見え方のズレをなくす | ハイフンのベースラインを上げた         |

### 9.1 視覚の解像度を上げる

「赤」「明朝体」「矢印」とひとくくりにせず、違いを見分けて選ぶ。

| 対象   | 解像度が低い見方 | 解像度が高い見方（書籍の例） |
| :----- | :--------------- | :--------------------------- |
| 色     | 赤・黄・青・グレー | 赤＝ナチュラル・ケミカル・和風・にぶい／黄＝さわやか・シャープ・柔らかい・浅い／青＝風格がある・さわやか・若い・神秘的／グレー＝フラット・冷たい・暖かい・色味がある。わずかな差でも、並べると印象はかなり違う |
| 書体   | なじみのある汎用の書体 1 つ | 同じ明朝体でも、伝統的だが現代的、墨だまりがあり暖かい、ふところが狭く払いが伸びやか、エレメントがすっきり現代的、筆の力強さ、和の味わい、など表情は様々。先端のカタチ、骨格、ふところの大きさで変わる |
| カタチ | ふつうの矢印     | 先端のパーツだけの矢印、曲がって何かが起こりそうな矢印、円や四角と組んだボタンらしい矢印、手描きの線の矢印、指さす手の矢印。先端のカタチ、軸の太さと長さ、角の丸み、質感など、ディテールは無限にある |

### 9.2 神は細部に宿る

書籍の細部のチェック項目（紙面の組版の例を含む）:

**文字**

1. 見出しの句読点はつめる（大きく見せる文章では、句読点の前後をあけすぎない）
2. 全角と半角に注意する（英数字の中に全角のコロンや記号が入ると、前後にアキができて間が抜ける。「1,980」の「,」や「A:」の「:」は半角に）
3. 字間を変えたら、ダーシ（——）に注意する（字間を広げると間が抜ける記号がある）
4. ルビは、元の文章の組みに影響が出ないように付ける
5. 間違った引用符を使わない（ダブルミニュート〃とダブルクォーテーション“”は似ているが意味が違う）
6. 1 文字だけの最終行（校正用語で「首つり」）は避ける
7. 字間がパラパラにあいた行を作らない（途中で切れない英単語が多いと起きる。1 文字単位で調整する）
8. 分離禁止の文字（「……」「——」、ひとまとまりの数字）を、行の途中で分けない
9. 縦組みの 2 桁の数字は、回転と文字幅を変える（縦中横にする）

**色**

1. グラデーションは、両端だけでなく途中の色もきれいにする（途中で濁らないよう、両端の色を調整する）
2. 濃度を変えるだけでなく、色を個別に作る（濃淡だけで展開すると、薄い色が間の抜けた色になる。彩度を少し足す）
3. 重ね刷りや半透明の表現は、意図に合わせて精度を上げる（透明感の表現に使う）

**写真**

1. 写真の上の文字は、コントラストを調整する（読みにくいときは、文字の周りに同じ系統の色の影を落とす）
2. トリミングを丁寧にする（不要な要素が入っていないか、傾いて見えないか、人の指などが中途半端に切れていないか）

**カタチ**

1. 罫線の太さを、狙う印象に揃える（太さは面積の割に印象を大きく左右する。強くポップなら太く、軽やかなら細く）
2. 図形と文字の距離を丁寧に整える（端が近すぎると窮屈に見える）
3. 点線の切れ目を整える（中心軸を揃える、端に中途半端な切れ端を残さない、角を揃える）
4. 不格好なリサイズをしない（無理に縦横比を変えると形が崩れる）
5. 意味が同じ図形は、形を揃える（同じ意味の矢印は、先端のデザインを揃える）
6. 荒れたエッジの表現は、拡大率に注意する（大げさすぎるとわざとらしい）
7. 角の丸みを揃える（角丸を内外に重ねるとき、同じ半径だと揃って見えない。内側の半径を小さくする）
8. 現実の光を意識する（影やグラデーションは、光の方向と強さを現実に合わせる。影が濃くぼかしが大きいと嘘っぽい）

### 9.3 見た目で考える（データに委ねず、目で決める）

数値で揃えても、見た目では揃って見えないことがある。最後は目で確かめて調整する。

| 揃えたいもの       | データのままだと                                      | 見た目で揃える                     |
| :----------------- | :---------------------------------------------------- | :--------------------------------- |
| 中央（記号の高さ） | 「12:45」「03-123」のコロンとハイフンが下がって見える | 記号のベースラインを少し上げる     |
| 左揃え（行頭）     | 文字のカタチが違うため、漢字で始まる行とカタカナで始まる行がずれて見える | 行ごとに少し動かす |
| 大きさ（図形）     | □ △ ○ ◇ を同じ高さにしても、△ ○ ◇ が小さく見える      | □ を基準に、△ ○ ◇ を少し大きくする |

## 10. 愛（そのデザインを決めるもの）

7 つ道具の最後。デザイナーが持っていたい愛には、2 種類ある。

| 愛         | 内容                                                                                     | 気持ち |
| :--------- | :--------------------------------------------------------------------------------------- | :----- |
| 内容への愛 | お決まりのパターンに内容を後からはめ込むのではなく、内容そのものからデザインを見つけ出す | デザインする対象を深く理解し、良いところを確かめて見つけ出し、いちばんふさわしい姿にしたい |
| 届ける相手への愛 | デザインを受け取る人の身になって考える。同じ内容でも、相手に知識や興味があるかないかで、適切なアウトプットの形はまるで違う | 届けたい相手になりきったつもりで、興味・知識・気分を想像し、それに寄り添うアウトプットを考えたい |

- デザイナーが作りたい・やりたい表現から始めると、内容の良さを犠牲にしたデザインに陥りがち。
- 内容を深く理解するほど、何を優先すればよいかが分かり、要素を取捨選択できる（4 章「ダイジ度天秤」の判断の土台）。
- 「内容のことを考え抜いて作っていたら、勝手にデザインがこうなっていた」というのが理想（7 章「連想力」の、テーマから自然に導かれる理想と同じ）。
- どんな人に、何を、どんな気分で伝えるのかを考える（1 章の「誰に・何を・なぜ・いつどこで」）。言葉にすると当たり前だが、たぶんそれがデザインをするうえでいちばん大事なこと。

**ほかの章とのつながり**: 1 章の編集は「届ける相手への愛」、STEP 0 の図解と 4 章の取捨選択は「内容への愛」から始まる。ほかの道具は、この 2 つの愛を形にする手段として使う。

## 11. デザインの素（要素ごとの扱い方）

7 つ道具とは別に、書籍の第 3 章「デザインの素」から、文章・色・写真・グラフの扱い方をまとめる。

### 11.1 文章の要素の「らしさ」

紙面の文章は、役割ごとに「らしさ」がある。らしさが出ていると、読み手は迷わずに読み進められる。

| 要素     | らしさ     | 役割                                                                                                                       | ポイント（書籍の POINT） |
| :------- | :--------- | :------------------------------------------------------------------------------------------------------------------------- | :----------------------- |
| タイトル | 主役感     | ページ全体の内容を端的に伝える。真っ先に目がいく存在感で、短時間でパッと伝わるようにする。言葉の切れ目を気持ちよく、強弱をつける | 真っ先に目が行く場所にある／一番大きい場合が多い／文字量は少なめで簡潔／書体を他と変えて目立たせる |
| リード   | イントロ感 | タイトルで宣言した後、本文に入る前の「つなぎ」。タイトルで伝え切れない具体的な内容を入れつつ、情報量は少なくして本文へ誘う | タイトルの後、本文の前に置く／本文よりやや大きいか同じ大きさ／文字量はタイトルより多く、本文より少ない／行の終わりごとに改行するとよい |
| 本文     | 下地感     | ページの骨格。「個性が強くないのが個性」。ただし面積が広く、ページの印象を大きく左右するので、設計は慎重に                 | まとまった文字量がある／改行を入れない箱組が基本／極端な個性をつけないほうが読みやすい／文字サイズは 12〜16 級（約 8.5〜11 ポイント）が多い |
| データ・キャプション | 黒子感 | プロフィール、クレジット、写真の説明など、主役ではないが必要な情報。主役を邪魔しないよう、どこまで存在を消せるかを、書体・大きさ・場所・面積で考える | ページの下、商品の下、写真の隅など目立たない場所に／ページの中で一番小さく／小さくても読みやすいゴシック体が合う／字間と行間を狭めて面積をコンパクトに |
| 見出し・キーワード | 言い切り感 | 本文の要約や、伝えたいことの箇条書き。簡潔に言い切る。自由度が高いので、ページ全体を見てほどよく「浮いた」存在にする | 本文以上、タイトル以下の大きさ／文字はできるだけ短く、不要な文言を減らす／カッコなどの記号でらしさが上がる／大きく使って映える書体に変えるのも有効 |
| あしらい | 読む＜見る感 | アクセントや装飾。「文字」ではなく「絵」に見えるようにする。可読性を度外視して、本文や見出しとは異質なものとして感じさせる | 書体に差をつける／筆記体やディスプレイ書体はあしらいと認識されやすい／傾ける、字間をあけるなど、文章では普通しない表現を／可読性よりデザイン性を優先 |

**タイトルの置き方**: タイトルは「一番大きい」か「始まりの位置（左上）にある」のどちらかで、タイトルと分かる。大きければ、本文の途中や写真の流れの中にあっても、離して置いても成り立つ。傾けると存在感が上がる。

**キャプションの入れ方**: 主役の邪魔をしない場所に、一番小さく置く。写真との対応は、近くに添える・引き出し線・番号・小さな配置図のどれかで示す。

置き方 7 種と入れ方 6 種の縮図は、[assets/title-caption-placement.svg](assets/title-caption-placement.svg) を参照。

**見出し・キーワードの表し方**（書籍の例）:

- 数字をつけて数える（01 02 03）
- アイコンや記号で動きを加える（◆）
- カッコは万能な見出し化の手段（【 】）
- 書体を変えると存在感が変わる
- ルビ（読みや英語訳）を添える（カルシウム／Calcium）
- 共通する語をくくり出して、言い切り感を上げる（「体幹ほぐしプログラム」「肩こり解消プログラム」→【プログラム】体幹ほぐし／肩こり解消）
- 言葉のタイプを揃える（「便利なアクセス」「おいしいコーヒー」のように形容詞＋名詞、「アクセス良くする」「コーヒーを飲む」のように名詞＋動詞、「アクセス」「コーヒー」のように名詞だけ、のどれかに統一する）

**書体の選び方**: 文字や文章の読みやすさは、次の 3 つの要素から成る。書体やフォント次第で、これら 3 つの性質を変えることができる。

| 要素   | 意味                   | 確かめる問い                 |
| :----- | :--------------------- | :--------------------------- |
| 可読性 | 文章の読みやすさ       | 文や単語をスムーズに読めるか |
| 視認性 | 文字の目立ちやすさ     | 文や単語が目立ちやすいか     |
| 判読性 | 文字の誤読のされにくさ | 文や単語を読み間違えないか   |

書体は、次の 4 点で選ぶ。

1. **目的に合った書体を使う**: 長文には、明朝体やセリフ体（あるいは細い書体）を使う。プレゼン用のスライドには、ゴシック体やサンセリフ体を使う。ポップ体や筆書体（行書体）は使わない。
2. **美しいフォント・太字に対応したフォントを使う**: 長文には、MS 明朝や Century ではなく、游明朝やヒラギノ明朝を使う。スライドには、MS ゴシックや Arial ではなく、メイリオやヒラギノ角ゴ、游ゴシックなどを使う。太字に対応したフォント、あるいは複数のウェイトをもつフォント（メイリオ、ヒラギノ角ゴ、游ゴシック、游明朝など）を使う。
3. **英数字には欧文フォントを使う**: 和欧混植の場合も、英数字には欧文フォントを使う。和文フォントと相性の良い欧文フォントを選ぶ。
4. **文字の過剰な装飾を避ける**: 文字を縦や横に伸ばさない。文字に影や枠線、立体感などの過度の装飾をしない。

あしらい（上の表）は、可読性よりデザイン性を優先する例外である。あしらい以外の文章には、4 点を当てはめる。

### 11.2 色（配色の考え方）

**トーン（明度と彩度の組み合わせ）**: 色の印象は、色相よりもトーンで大きく変わる。「どんな印象にしたいか」から、トーンを選ぶ。実際の色の見本（トーン 12 区分と、目的別の配色）は [assets/color-tones-schemes.svg](assets/color-tones-schemes.svg) を参照。

```text
 明度 高 │ うすい（pale）        あさい（light）     あかるい（bright）
        │ あかるいはいみの      やわらかい（soft）  つよい（strong）   さえた（vivid）
        │ はいみの（grayish）   にぶい（dull）      こい（deep）
 明度 低 │ くらいはいみの        くらい（dark）
        └──────────────────────────────────────────→ 彩度 高
```

**目的別の配色**:

| したいこと                   | 答え（書籍）                                 | 配色の名前と内容 |
| :--------------------------- | :------------------------------------------- | :--------------- |
| なじみの良い配色にする       | 色相・明度・トーンなど、何かひとつでも揃える | ドミナント・カラー: 色相を揃えるか少しだけ変える。色の持つイメージがそのまま伝わる／トーン・オン・トーン: 色相を絞り、明度に差をつける。リズムが生まれる／ドミナント・トーン: トーンを揃える。色相が違ってもまとまり、トーンの印象を強く押し出せる |
| パキッと引きしめる           | 正反対の色を少しだけ使う                     | アクセントカラー: ベースカラー 7 割、同系のアソートカラー 2 割、ベースと正反対の色 1 割／セパレーション: 色と色の間に、別の色（黒・白・灰色などの無彩色が中心）を細く差し込んで、元の配色を引き立てる（ステンドグラスの黒、タイルの白い目地） |
| 繊細なニュアンスを出す       | ほんのわずかな差で繊細さを出す               | カマイユ: 遠くから見ると 1 色に見えるほど、さりげなく色を変える／フォカマイユ: カマイユの変化に少し幅をもたせる |
| 色数が多くてもまとめる       | 赤みと青みを揃える                           | 同じ黄色でも、赤みのある黄は暖かく、青みのある黄は冷たい。暖かい色で揃える（ウォームシェード）か、冷たい色で揃える（クールシェード） |
| 統一感を出しつつ単調にしない | 似ている色と、差がある色を両方合わせ持つ     | グラデーション: 色相・明度・彩度を規則的に少しずつ変える。隣の色は似ていて、両端には差がある。紅葉や夕焼けなど自然にも多く、なじみやすい |
| 自然で落ち着く配色にする     | 黄色に近い色は明るく、青紫に近い色は暗くする | ナチュラルハーモニー: 光が当たると黄色がかり、陰は青みがかる。自然の見え方に合わせる |
| 人工的で斬新な配色にする     | 黄色に近い色は暗く、青紫に近い色は明るくする | コンプレックスハーモニー: ナチュラルハーモニーの逆。なじみにくいが、目的に合わせれば新鮮さを出せる |

**色の目的を決める（左脳の色と右脳の色）**: いま使おうとしている色の目的がどちらかを考える。

|        | 左脳の色（機能的な色） | 右脳の色（情緒的な色）                     |
| :----- | :--------------------- | :----------------------------------------- |
| 役割   | 説明や強調のために使う | ひと目見たときの印象を左右する             |
| 使い方 | 差をつける／見やすくする／注目させる／記号として認識させる／グループに分ける／階層を分ける | 視覚・味覚・嗅覚・聴覚・触覚・記憶に訴える |

右脳の色（印象の色）を、伝えたい感情や雰囲気から選ぶ方法は、`color-image` スキルにまとめている。

### 11.3 写真の構図

写真が持つラインと動きを活かす。構図の線の重ね方は [assets/photo-composition.svg](assets/photo-composition.svg) を参照。

| 種類                                                         | 構図       | 内容 |
| :----------------------------------------------------------- | :--------- | :--- |
| シンプルライン（スッキリした印象。単調にならないよう注意）   | シンメトリー | 上下や左右が対称。整理された印象で、日常では見つかりにくいため、非日常の美しさを感じさせる |
|                                                              | 二分割構図 | 画面を上下か左右で二分割する。水平線や地平線を活かす典型的な構図。見やすい |
|                                                              | 三分割構図 | 縦横を三等分した線に合わせて置く。二分割よりリズムがあり、表現の幅が広い |
| 動きが生まれる（放射線はダイナミック、曲線はやさしく広がる） | 曲線構図   | 川・地形・植物や、人工物の中の曲線を取り入れる。動きと柔らかさが出る |
|                                                              | 放射線構図 | 放射線が上向きなら開放的、下向きなら神秘的でドラマチックな印象 |
|                                                              | 三角形構図 | 三角形の線に合わせて置く。末広がりは安定感があり、ダイナミックな仕上がりになる |

### 11.4 グラフ

**1 つのグラフに 1 つのメッセージ**: すべてのデータを 1 つのグラフに入れると、情報が多すぎて読み取りにくい。伝えたいメッセージを分解して、メッセージごとにグラフを分け、メッセージを見出しにする。

書籍の例（レストランの売上状況）: 時間帯別の売上の棒グラフと、来客数の折れ線を 1 枚に重ねたグラフ（惜しい例）を、次の 4 つに分ける（正解の例）。分ける前と後は [assets/chart-one-message.svg](assets/chart-one-message.svg) を参照。

| メッセージ（見出し）                                | グラフ                             |
| :-------------------------------------------------- | :--------------------------------- |
| ディナータイムの売上は、ランチタイムの 4.6 倍である | 2 本の棒（間に「4.6 倍」）         |
| カフェの売上はランチの 1/3 だが、客単価はほぼ同じ   | 売上と客単価を並べた棒             |
| 来客のピークは 13 時台と 19 時台                    | 折れ線（ピークの数値を書き添える） |
| ランチの時間帯は、9 割近くがランチセットを頼む      | 円グラフ                           |

**グラフを選ぶ**: 何を比較したいかで選ぶ。メッセージの中のキーワードがヒントになる。

| 比較したいこと | キーワード | グラフ       | メッセージの例（書籍）                                 |
| :------------- | :--------- | :----------- | :----------------------------------------------------- |
| 割合           | 割合、%    | 円グラフ     | 1 日の売上の約 8 割はディナータイムが占めている        |
| 項目の大小     | 多い、低い | 横棒グラフ   | 定番のマルゲリータが一番注文の多い人気メニュー         |
| 時系列の増減   | 減少、増加 | 縦棒グラフ   | 新商品は順調に売上を増やし、8 か月で年間目標を達成した |
| 分布           | 集中、範囲 | 折れ線グラフ | 売上の大半は 1,000〜4,000 円の範囲に収まっている       |

**テクスチャは言葉を発している**: ポップなストライプ、やさしい水彩、手描きらしさ、黒板の板書への見立て。正確さには劣るが、テクスチャは雄弁。グラフのテーマに合うテクスチャで作れれば、立派なグラフィックになる（7 章「連想力」）。

## 画面デザインへの応用

| デザイン一般の考え方 | 画面デザインでの当てはめ方                                                      |
| :------------------- | :------------------------------------------------------------------------------ |
| 誰に・何を・なぜ・いつどこで | 展示・講演・レビューなど、表示する場面と見る人を先に決める。遠くから見る展示と、手元で読む資料では、正しい密度が違う |
| 図解で階層を確かめる | Markdown の見出しの階層と、強調したい項目を確かめてから、スライドの構成を決める |
| 離れて見るチェック   | スクリーンショットを縮小するか、ぼかして見て、主役が分かるかを確かめる。目視の代わりに、縮小画像で比べる |
| 色のライト           | 1 枚のスライドで強調に使う色の数を絞る。全部の要素に色をつけない                |
| 地のライト           | 強調したいカードや数値だけ、色ベタの面にする。ほかは線や淡い面にとどめる        |
| サイズのライト       | KPI などの主役の数値は、脇役の大きさに応じて、思い切って大きくする              |
| 余白のライト         | グループの区切りは、罫線より余白の差で示す                                      |
| 揃えないライト       | グリッドを守ったうえで、1 つだけを崩す。最初から崩さない                        |
| 足し算と引き算       | 演出（光、アニメーション、装飾）は、狙った印象に届かないときだけ足す。飾りとしての言葉や装飾は、削れないかを先に考える |
| 擬人化力             | Visualモードのスタイルごとに「どんな人か」を言葉で決め、書体（声色）・組み（話し方）・配置（立ち方）・あしらい（服装）・色（年代）をその人物像にそろえる。人物像に合わない要素が混ざっていないかを点検する |
| 連想力               | 新しいスタイルや演出を考えるときは、テーマから言葉とイメージを書き出し、そこから色・質感・カタチを引き出す。根拠のない装飾を足さない。直接の連想だけで終わらせず、1 つは意外な連想を検討する |
| 翻訳機               | Visualモードは、Markdown の文字（言語）を、カード・アイコン・図・数値（非言語）に翻訳する機能と言える。箇条書きをカードやアイコンに、比較を表や記号にするのは翻訳の例。一方で、引用や口コミのように文章のニュアンスが大事な部分は、文章のまま残す。評価が分かれる内容を ◎・× のような記号で言い切らない |
| 細部の調整           | 細部の調整は、構成と方向性が固まってから行う（`dtp` の校正）。画面では、見出しの約物のアキ（CSS の `font-feature-settings` の約物詰めなど）、半角と全角の混在、1 文字だけの最終行（`text-wrap: pretty` など）、アイコンの見た目の大きさと位置、角丸の内外の半径、影の方向と強さを確かめる。数値で揃えたうえで、スクリーンショットを拡大して目で確かめる |
| 愛                   | 演出や装飾は、作りたい表現からではなく、利用者の文書の内容と、それを見る人（講演の聴衆、展示の来場者、レビューの参加者）から決める。利用者の文書の良さを、演出が邪魔していないかを確かめる |
| 文章の要素のらしさ   | Markdown の `#` をタイトル、見出し直後の段落をリード、`##` 以下を見出し、図や表の説明をキャプションに当てはめ、それぞれのらしさ（大きさ・位置・書体・面積）を出す。装飾の欧文などのあしらいは、本文と異質に見せる |
| 書体                 | Visualモードや発表モードはスライドに当たるため、ゴシック体（サンセリフ体）を基本にし、複数のウェイトをもつフォントで見出しと本文の差をつける。CSS の `font-family` では欧文フォントを和文フォントより前に書き、英数字に欧文フォントが当たるようにする。文字の影や縁取りは、背景とのコントラストを補う目的に限り、装飾として足さない |
| 色                   | 色を足すときは、機能的な色（強調・区分）か情緒的な色（印象）かを先に決める。スタイルごとの配色は、トーンを揃える（ドミナント・トーン）か、色相を揃える（ドミナント・カラー）で、まとまりを出す。トーンは単体のアクセント色ではなく、**背景色（Light / Dark それぞれ）・文字色・図形色（丸・矢印・バッジ）・演出色（光・影）の組み合わせ**として設計し、Light 用パレットを Dark 背景に流用しない |
| グラフ               | Mermaid のグラフや数値のカードは、1 つに 1 つのメッセージにし、メッセージを見出しにする。比較したいこと（割合・大小・増減・分布）でグラフの種類を選ぶ |

## 13. 点検の観点

デザインの検討や `dtp` スキルの校正で使う。

- [ ] 誰に・何を・なぜ・いつどこでが、要件として言葉にできているか
- [ ] 情報の階層（親子か並列か、同じ大きさか）を図解で確かめたか（STEP 0）
- [ ] 色や書体を決める前に、配置だけで構造が伝わるか（STEP 2）
- [ ] 足し算は、方向性に合ったさじ加減か。飾りとしての要素を削れないか（STEP 4）
- [ ] 引いた目線と寄った目線の両方で点検したか（STEP 5）
- [ ] 伝えたいことを絞り、どっちがダイジかを決めたか。選ばなかった要素は小さくするか削ったか（4 章）
- [ ] 離れて見ても（縮小・ぼかしても）主役が分かるか
- [ ] ライトは主役だけに当てているか。色を使いすぎて、周囲が明るくなっていないか
- [ ] デザインを人に例えると、どんな人か言えるか。書体・組み・配置・あしらい・色が、同じ人物像にそろっているか
- [ ] 色・質感・カタチを、テーマからの連想で説明できるか。直接の連想だけで、底が浅くなっていないか
- [ ] 言葉で書いた部分と、絵（写真・図・アイコン・記号）にした部分は、それぞれ目的に合っているか。翻訳で失われたニュアンスはないか
- [ ] 細部の調整は、大きな路線変更がなくなってから始めたか。文字・色・写真・カタチの細部と、見た目の揃い（中央・左揃え・大きさ）を確かめたか
- [ ] 作りたい表現が先に立って、内容の良さを犠牲にしていないか。受け取る人の知識・興味・気分に寄り添っているか
- [ ] タイトル・リード・本文・キャプション・見出し・あしらいが、それぞれのらしさを持っているか
- [ ] 書体は目的（長文かスライドか）に合い、太字・複数のウェイトに対応しているか。英数字に欧文フォントが当たっているか。文字を伸ばしたり、過度の影や縁取りをしたりしていないか
- [ ] 色の目的（機能か印象か）が決まっているか。配色は、何かひとつ（色相・明度・トーン）を揃えてまとめているか
- [ ] 背景色（Light / Dark）・文字色・図形色・演出色の組み合わせで十分なコントラストが取れているか。光の演出が矢印や文字と重なって潰れていないか
- [ ] グラフは 1 つに 1 つのメッセージか。比較したいことに合う種類を選んだか
