# cr のひな形

## CR 票

`<プロジェクト>/doc/6.change_request/<サービス>/CR-<SVC>-<nnn>_<件名>.md` に置く。

```markdown
# CR-<SVC>-<nnn> <件名>

| 項目       | 内容                                                     |
| :--------- | :------------------------------------------------------- |
| 分類       | 不具合 / 仕様の変更 / 追加                               |
| 状態       | 登録 / 承認 / 対応済み / 保留 / 却下                     |
| 優先度     | 高 / 中 / 低                                             |
| 起票の元   | 利用者の指摘、`TC-<FEAT>-<nnn>` の所見、校正の所見など   |
| 戻る工程   | dtp / swe1 / swe2 / swe3 / test                          |
| 対応       | ブランチ名、PR の番号                                    |

## 1. 要求の内容

利用者から見た事象と、期待する状態を書く。不具合の場合は再現手順を書く。

## 2. 分析

### 2.1 現在の仕様との関係

分類の根拠を、関係する FR / DD の ID とともに書く。

### 2.2 原因

確認した結果から特定した原因を書く。特定できない場合は、その旨と、確かめるために必要なことを書く。

## 3. 影響範囲

| 種別   | ID                | 影響                 |
| :----- | :---------------- | :------------------- |
| 要求   | `FR-<SVC>-<nnn>`  | 変更・追加する内容   |
| 設計   | `DD-<FEAT>-<nnn>` | 変更・追加する内容   |
| テスト | `TC-<FEAT>-<nnn>` | 変更・追加する内容   |

## 4. 対応方針

- 採る案:
- 採らなかった案とその理由:
- 副作用（他の機能・表示・操作への影響）:
- 規模の見積もり:

## 5. 対応結果

- 変更した成果物（ID）:
- 合格した TC:
- 残った課題（新しい CR、保留にしたもの）:
```
